0. 一句话定位

LDA = 光电接缝上的可证伪设计入口。 不做整条链，只做「封装测试占 79.9% 成本的那一格」——把设计决策（耦合容差 / 间距 / 端口布局）对那 79.9% 成本池的影响，用物理定律锚 + 实证锚做成死标量判决。钱与价值都在接缝，不在一成多的芯片成本池。

1. 战略边界（研发必须守住的红线与不做清单）

1.1 三不做及根因（对外护城河话术 + 对内研发边界）

不做根因推论
电域求解器（SerDes/DSP/BER/眼图）电域判决锚来自工艺统计与量产实测，方程给不了 ⇒ 硬做 = 造漂亮的自证桩（必假绿）；客户已有 Cadence 不会换电域只做接口层（网表→带参数紧凑模型 + 接 Cadence）
foundry TCAD（工艺仿真/计算光刻 OPC·RET/配方）商业核心资产 + NDA 不给 + MPW 排期不支持交互式迭代黑箱，外部只给 PDK/实测回流
封测实体产线C 期能力，资本开支重先委托测试、后自建；B 档跑完 MPW 后封测才是花钱大头

1.2 全生命周期只承担 3–5 段（责任边界）

8 阶段核对：0 商机 / 1 需求冻结 / 2 架构权衡 / 3 设计实现 / 4 版图签核 / 5 出带包 / 6 封测验证 / 7-8 量产收尾。

  • 强项 3-4-5（设计实现 / 版图签核 / 出带包）—— 这是 LDA 的承担区。
  • 断点 1（需求冻结）与 6（封测验证） —— 1 由 T0 覆盖（提供模板 + 要签字）；6 委托伙伴。
  • 0 / 7 / 8 不做（商机/量产） — 不承接也不负责。
  • 🔴 基线缺失 = 最隐蔽缺陷：可证伪的前提是「证伪对象固定」；需求不冻结则 52 道锚无的放矢。⇒ 阶段 1 需求冻结是必补环节（成本极低、不需写求解器、「开工前签字画押」天然有说服力）。

1.3 AI 分工铁律：AI 出题、物理定律判卷

  • ❌ 审核 = 判 PASS/FAIL → LLM 进判决路径，破最核心红线，绝不可给。
  • ✅ 审核 = 找可能错的地方（出题/攻击） → 属生成侧，可以给，越多越好。
  • 正确架构 = 蓝队生成 / 红队出题攻击 / 锚裁判（死标量）/ 人终审 四层。判决权在锚，签字权在人。
  • 代码已有红线：llm_proposer.py:66「只出参数不判对错」；run_proposal_compiler_smoke.py:13/171「LLMProposer 零 PASS/FAIL 判决逻辑（源码级断言进 CI）」。

1.4 生态开放四层光谱（定位 = 获客引擎，不是研发外包）

① 实测语料/对抗题（已在做·风险最低·应加大）② PDK 适配/器件库/文档（判据我们写）③ 边缘求解模块+新增锚（先判据后代码）④ 核心求解器/判决路径/锚库（不开放代码，只开放对抗）。

  • 🔴 最大风险 = 假绿（自证桩批量生产）：外部贡献「自己写代码 + 自己写 smoke 证明自己对」。
  • 规避（核心机制）：判据先于代码，且判据由 maintainer 写 —— 贡献者写实现，我们写判据。与「AI 出题、物理定律判卷」完全同构：生态出题（写代码），锚判卷。
  • 🔴 许可不可逆：现在就加最轻量 DCO（Signed-off-by），成本近乎零，保住未来双许可/商业授权权（Redis/MongoDB 前车之鉴）。待杜先生拍板是否启用。

1.5 跨期工程铁律（落到行为复核，非标签）

  • 🔴🔴 标签≠行为、值≠行为（已累计 8 次血案）：只读 docstring/注释/常量名会漏判。读代码判断「有没有某能力」必须 grep 实际调用点；加字段必须打到数据出口（端点）并真跑生产代码验证，不在 smoke 里另写同式复算（=重言式）。
  • 🔴🔴 新护栏必须反向测试会响；须测生产代码非内嵌副本；CORE 覆盖不到=没门禁；SKIP 宁红不假绿。
  • 🔴🔴 「写了 smoke」≠「进了 CI」：新 smoke 必须登记 CORE_SMOKES，<5s 且无重依赖者无权豁免（run_ci_coverage_gate_smoke.py 强制）。
  • 扩库类改动同步五处：①条目库 ②CI 断言计数 ③定价/白名单派生表 ④回归集登记 ⑤对外账本计数。
  • CI 解释器固定：C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe（3.13.14）。绝不用 `lda_cuda_venv`（3.11 不支持 PEP 701 ⇒ 假 FAIL）。
  • 改后端（routes.py/store.py 等 import 期加载文件）后实测前必须先重启被测实例（「标签≠行为」第 8 次）。

3. 逐期实施计划（WBS + 验收 + 风险）

T0 需求架构层（0–9 月 · 60 万 · 升级非新建）

已有资产（勿答「我们没有」）：lda/lda_harness/proposal_compiler.py（687 行，15 判据 smoke 已在 CI，2026-09-09 实测 15 PASS/0 FAIL）。五段管线：编译 → 锚约束剪枝（S1/S2/S5/S7）→ 域内生成 → 逐案锚验 → 确定性排序 → 人终审。6 条流水线：link / wdm_demux / quantum_fidelity / sensor_frontend / qkd_link / cpo_optical_io。

5 项研发内容（WBS）：

  1. 多目标 Pareto 排序：成本/功耗/面积/良率/可封装性加权前沿，替换当前单目标余量降序。
  2. NLP 需求→结构化入口：自然语言需求 → 结构化提案 JSON（复用 /api/store/guide 匹配逻辑，不杜撰数字）。
  3. S8 锚纳入：当前已接 S1/S2/S5/S7（S7 实际已生效，docstring 旧注释已订正）。
  4. 生成器启用 LLM 接口：generator="llm" 已就位，替换只动 generate_candidates 一处，判决层零改动（红蓝队纪律：LLM 只生成不判）。
  5. 可封装性维度占位：预留接口，T3 接入。

验收（判据 D 思路）：

  • ① 同一需求改变成本权重，Pareto 前沿必须位移（防常数假绿）
  • ② 任一候选必须带逐案锚证据，无证据者不得进 ranked 列表
  • ③ 域外候选（违反功率预算）必须被剪枝

风险：Pareto 前沿若对所有权重都不变 → 权重未真生效 → 反向测试必 FAIL。

T1 光电接口层（0–12 月 · 110 万研发 / A 档对外报价 150–300 万是订单）

范围：网表从拓扑骨架升级为带参数紧凑模型：VπL / 3dB 带宽 / 结电容 / 响应度 / 暗电流 / 电极 RC。接进 Cadence（行为级模型 + 带参数网表）。

已有基础：parasitic_rc.py + B29 热光锚。

明确不做：SerDes / DSP / 眼图 / BER（电域求解器，见 §1.1）。

WBS：

  1. 紧凑模型参数 schema 定义（VπL/带宽/结电容/响应度/暗电流/电极RC）。
  2. 参数化网表生成器（SPICE 兼容）+ Cadence 导入适配。
  3. 参数↔物理映射校准（接 B29 热光锚 + B30 读出保真度锚做死标量比对）。
  4. 反向护栏：参数扰动 ±20% 时域响应必须变。

验收：参数扰动 ±20% → 时域响应必须变（同判据 D，防常数假绿）；与 Cadence 导入往返一致。

商业衔接：A 档是客户已划好范围的首单（订单非融资），能自造血，最可能先落地。我方研发投入 110 万 vs 对外报价 150–300 万，差额非毛利（含交付/支持）。

T2 真值链（6–24 月 · 240 万）

范围：3–4 轮 MPW + 委托封测 + 实测回流规范。先委托测试、后自建（封测占近八成成本）。

WBS：

  1. MPW 排期与 foundry 对接（IMEC/CEA-Leti/TSMC/GF，按器件定）。
  2. 委托封测协议（ficonTEC 类耦合设备年产能仅 30–40 台，交期 5–7 月，须早锁）。
  3. 实测回流规范：把外部实测写入 lda_pdk/empirical.py 的 review_measurement（具名人工评审 + 确定性自测门禁）。
  4. ≥5 个自证桩换真锚：优先选 25 个自证桩中物理上可有公开实测/自有 MPW 的（参照 E8/E9 升格路径，但 E9 的 c1 仍待真实 PDK 标定）。
  5. 工艺角由假设分布 → 实测分布（S7 蒙特卡洛最坏情况 margin p5 改为实测支撑）。

验收：≥5 自证桩换真锚；工艺角由假设变实测分布；实测与仿真偏差公开标注（诚实边界，不美化）。

风险：MPW 排期长、封测设备交期长 ⇒ 必须 6 月启动询价与锁单，否则堵住后续所有真值回流。

T3 设计侧虚拟制造 2.0（12–30 月 · 研发人力承担，不单列预算）

🔴 战略修正（关键）：不能只做工艺波动（光刻/刻蚀→CD 偏差→工艺角）。既然八成成本在封装与耦合，真正值钱的设计优化是「可封装性」——设计阶段就算清耦合容差、对准失配、封装良率。

WBS：

  1. 工艺波动链路（既有，巩固）：CD 偏差→工艺角→良率。
  2. 可封装性链路（新建）：耦合容差预测 / 对准失配预算 / 封装良率模型，接 S13 设计良率锚 + P-CPO 间距几何下界护栏。
  3. 设计决策→封装良率反向追溯（给设计师「这版布局会让封测良率掉 X%」的实时反馈）。

验收：设计改动 → 封装良率预测同向变化且可复现；耦合容差/对准失配预测与实测对标误差公开。

T4 标准位与生态（24–36 月 · 40 万）

范围：L0 IR / DesignPackage JSON 推标准位。

🔑 领袖逻辑：「别人引用你的数」才是领袖，不是功能全。唯一有领袖相资产 = L0 IR / DesignPackage JSON（光子界无统一语义交换标准，电子有 OpenAccess/IBIS-AMI）。🔴 前提：标准是被采用出来的，当前 users=1。

WBS：

  1. L0 IR schema 冻结 + 文档化（中英）。
  2. 对外采用计划：≥2 家外部机构采用 + ≥1 家 foundry 签 PDK。
  3. 生态开放治理三件套：判据先于代码 / 自动主权扫描（import+license 双扫，复用 run_optional_import_guard_smoke.py 的 ast 全包经验）/ 贡献分级。

验收：≥2 家外部采用 + ≥1 家 foundry 签 PDK。

5. 跨期治理与 CI 纪律

  • 回归门禁：发版前必跑 --tag core 全量回归（21–35min）看 rc；回归中不改被读文件；后台 python -u。
  • 反向测试文化：每个新护栏必须有反向测试证明会响；静态守卫 + 动态实跑两层都要（grep 会被 lda_cuda_venv/ 淹没且误计 try 内合法写法）。
  • 判据先于代码：无论是新锚、新求解器、还是生态 PR，先写死标量判据，再写实现。
  • 主权扫描：PR 门禁做 import + license 双扫（防 Meep=GPL v2+ 不可逆污染、防 B 级依赖「借今踢后」变「踢不掉」）。
  • 三分类一致性：README 账本 ≡ 本机 harness 推导 ≡ /api/verification_ledger 端点，任一漂移即红。
