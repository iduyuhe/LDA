## 0. 裁决

| 路线 | 原命题 | 裁决 | 一句话原因 |
|---|---|---|---|
| **① ADC 衰落** | `SNDR_hf` 相对 `SNDR_lf` 的衰落落在抖动模型同一族 | 🔴 **判死** | 语料**没有 σ_t**，抖动律不可检；退化成「高频不比低频好」，而那是**测量一致性约束**，不是任何候选模型的预测 |

## 1. 路线① ADC 衰落 —— 判死

语料：Murmann ADC Survey（`github.com/bmurmann/ADC-survey`，BSD-3），778 条实测记录。

### 1.1 原命题为什么不可检

抖动限制的 SNR 是 `SNR_j = −20·log10(2π·f_in·σ_t)`。要用它做判据，**σ_t 必须在语料里**。
778 条记录 36 列里**没有任何一列是 σ_t 或等效的相位噪声/抖动指标**。
没有 σ_t ⇒ 这条「衰落落在抖动族上」的命题**无法证伪**，所以它连判据都算不上。

### 1.2 退而求其次的界成立，但它不是锚

同一记录内，高频输入下的 SNDR 不应高于低频 SNDR。四列齐备（`SNDR_lf` + `SNDR_hf` + `fin_hf` + `fsnyq`）的 **156 条**：

| 项 | 结果 |
|---|---|
| 违反 `SNDR_hf > SNDR_lf + 0.1 dB` | **2 / 156**（+0.40 dB @2014-5.4 · +0.28 dB @2021-C15-4，两条 `fin/fsnyq` 恰为 0.5000） |
| 违反幅度 | 全部 ≤ 0.4 dB，在测量重复性内 |

**为什么它仍然不能作锚**：锚的定义是「**候选模型做出预测、与实测死标量比对**」。
这条界**没有任何候选模型在做预测**——它是「数据不该自相矛盾」的卫生约束。
把它注册成锚，等于把 `assert x <= x_max` 当物理验证，正是 E1/E3–E7 那 6 道自证桩的同型病。

### 1.3 顺带否掉的想法：`Δ` 对 `fin/fsnyq` 的斜率

算出来 **−0.05 dB/decade**（n=156），即**几乎没有趋势**。原因很直白：每个设计的 σ_t 不同，
把 156 个不同 σ_t 的设计混在一起回归，斜率会被抹平。**这条也做不成判据**（同样缺 σ_t）。

## 2. 路线② MOSIS 参数 —— 判死（三个独立理由）

语料：`github.com/DDD-FIT-CTU/CMOS-SPICE-Model-Collections`（MOSIS 电测参数报告再发布）。
本轮实际下载解析 **10 份**（IBM 90/130/180/250 nm + TSMC 180 nm 各 2 份）。

### 2.1 弃权率：只有一半报告带 SPICE deck

10 份里 **5 份根本没有 `.MODEL CMOSN` 段**（IBM 130 nm ×2 / 250 nm ×1 / 90 nm ×2），只有前段的「实测参数表」。
⇒ 就算这条路能走通，可用样本也先从 249 份报告缩到「恰好带 deck 的那些」，**不是一个稳定的语料基数**。

### 2.2 🔴 `NCH` 是模板常量，不是该批次的掺杂

5 份带 deck 的报告，跨**两家代工厂**（IBM / TSMC）、**两个技术节点**（180 / 250 nm）、**不同批次**：

| 文件 | TOX | **NCH** | VTH0 | K1 | U0 |
|---|---|---|---|---|---|
| IBM180 t42s | 4.5E-9 | **2.3549E17** | 0.3026 | 0.4866 | 267.98 |
| IBM180 t67k | 4.5E-9 | **2.3549E17** | 0.3089 | 0.4740 | 284.93 |
| IBM250 t51m | 6.3E-9 | **2.3549E17** | 0.5681 | 0.7807 | 351.88 |
| TSMC180 t42p | 4.1E-9 | **2.3549E17** | 0.3672 | 0.5893 | 262.34 |
| TSMC180 t58f | 4.1E-9 | **2.3549E17** | 0.3756 | 0.5834 | 270.39 |

`TOX` / `VTH0` / `K1` / `U0` 都随批次变，**只有 `NCH` 五位有效数字逐位相同**（PMOS 侧同理，恒为 `4.1589E17`）。
氧化物厚度 4.1 nm 与 6.3 nm 的两种工艺怎么可能"恰好"有同一个沟道掺杂？

⇒ 两种解释都通向同一结论：**要么这是 MOSIS 统一提取流程写死的模板初值，要么这批 deck 共用一套模板参数**。
不论哪种，`NCH` **都不能当"该器件的衬底掺杂"用**。而它正是闭式 Vth 唯一能拿到的掺杂输入。

### 2.3 三个已公布参数彼此不自洽（BSIM3 恒等式检验，无需任何外部输入）

BSIM3 的体效应系数有定义式 `K1 ≡ √(2·q·ε_si·N_a)/C_ox`。三个参数都在报告里，可以直接对拍：

| 文件 | K1（报告） | K1（由 NCH+TOX 算） | 比值 |
|---|---|---|---|
| IBM180 t42s | 0.4866 | 0.3644 | **1.34** |
| IBM180 t67k | 0.4740 | 0.3644 | **1.30** |
| IBM250 t51m | 0.7807 | 0.5101 | **1.53** |
| TSMC180 t42p | 0.5893 | 0.3320 | **1.78** |
| TSMC180 t58f | 0.5834 | 0.3320 | **1.76** |

**5/5 份偏离 1 超过 10%**（范围 1.30–1.78）。这就是 §2.2 的直接后果：
`NCH` 不是真掺杂 ⇒ 拿它算出来的 K1 当然对不上拟合出来的 K1。
⇒ **凡是用 `NCH` 当输入的候选模型，在这份语料上做的是"对拟合残差"，不是"对物理"。**

### 2.4 闭式 Vth 的绝对偏差：缺的那个参数比答案本身还大

用 LDA 自己的闭式（`ecore.device_pde.physics_vth_closed`，`V_FB` 取 ecore 工程默认 **−0.60 V**），
`N_a = NCH`、`t_ox = TOX`，对实测 `LARGE`（50/50 µm，长沟道，教科书的适用域）：

| 文件 | 实测 Vth(LARGE) | 闭式 Vth | 偏差 | 要让闭式命中需挪 V_FB |
|---|---|---|---|---|
| IBM180 t42s | 0.360 | 0.6190 | **+0.259** | −0.259 |
| IBM180 t67k | 0.360 | 0.6190 | **+0.259** | −0.259 |
| IBM250 t51m | 0.620 | 0.7555 | **+0.136** | −0.136 |
| TSMC180 t42p | 0.430 | 0.5887 | **+0.159** | −0.159 |
| TSMC180 t58f | 0.430 | 0.5887 | **+0.159** | −0.159 |

**5/5 同号（系统性高估）**，|偏差| 0.136–0.259 V，相对偏差 **22%–72%**（远超「10% 内」的闸门）。

🔴 **关键在于偏差的来源只有一个**：`V_FB`（功函数差 − 固定氧化层电荷/C_ox）。
`V_th = V_FB + 2φ_F + Q_dep/C_ox`，后面两项由 `N_a`、`t_ox` 决定，`V_FB` 是**语料里没有的那一项**。
而它的量级：**0.60 V** —— 是实测答案（0.30–0.36 V）的 **1.7–2.0 倍**。
**缺的那个参数比答案本身还大**，所以"闭式算不准"根本不是模型的问题，是**输入缺失**的问题。

⚠️ 若把 `V_FB` 逐工艺拟合到命中实测（上表最后一列），那就是**用 golden 反推参数再回代** —— 循环自证，
正是 MEMORY 里「`==` 只用于精确已知量 / 反解回代必然相等」同族。**不许这么做。**

### 2.5 附带否掉：「Low-field Mobility」不是独立测量

报告里 `Low-field Mobility = 398.78 cm²/V·s`。核对：`2K'/C_ox = 2×153 µA/V² / (3.9ε₀/4.5nm) = 398.8`.
⇒ 它就是 **`2K'/C_ox` 的定义式改写**，不是另一次测量。
拿它当 golden、又用 `μ = 2K'/C_ox` 当候选 = 同一个式子对自身。**pass 了也什么都不能说明。**

## 3. 这次判死把 P1 的假设升级成了事实

v0.9.302 的 P1 写的是**假设**：「参数齐的必是仿真，实测的必缺参数」。
P2b 实测后，这句话要改成更强的一条：

> **参数齐的那份实测语料，参数本身是模板常量；参数真的那份，缺的项比答案还大。**

具体到电子域：

| 语料 | 缺什么 | 缺的东西占答案多大 |
|---|---|---|
| MOSIS（实测） | `V_FB`（功函数 + Q_ox） | **1.7–2.0×** 答案本身 |
| MOSIS（实测） | 真 `N_a`（`NCH` 是模板常量） | 使 K1 恒等式崩 30–78% |
| Hacker Fab（实测） | `t_ox` / `N_a` / `μ₀` | 未知 |
| NBSDC PMOSFET（实测） | Ge 沟道参数（`ecore` 无） | 未知 |
| MESD（仿真） | —— 参数全，但**仿真不许作 golden** | — |

⇒ **电子域实证锚的死结不是"找不到语料"，是"公开实测语料永远不公开配方，而配方才是模型需要的输入"。**
这不是本仓能靠努力解决的问题，是产业事实（工艺 split 属代工厂机密）。

## 4. 下一步：转 A2（超导语料升格）

理由（也是当初把 A2 排在 N1 前面的理由，现在得到验证）：

1. **不需要工艺配方**：超导器件的 `T1`/`T2`/`readout_fidelity`/`qubit_freq`/`g`/`resonator_Q`
   是**器件级可直接测量、且论文正文给数字**的量，不像 MOSFET 那样必须知道 `N_a`、`t_ox`、`V_FB` 三件套。
2. **语料已在库**：122 条语料里已有 **10 条超导实测指标**（v0.9.302 P1 §3② 实测），一条都没升格。
3. **流程已验证**：光子侧 E1–E10 的升格机制（A 级溯源 + 候选独立 + 窗口法容差）已跑通。

⚠️ 但 A2 也必须过同一道闸门：**每条都要先验「候选物理成立」**。
超导侧的风险形态不同——不是缺参数，而是**候选模型可能是"拟合出来的经验式"**（如 `T1` 对几何/材料的多参数拟合）。
A2 的第一件事应当是：**逐条列出这 10 条各自能被 `lda_l2` 哪个模块现算，算不出来的当场标边界声明。**

## 5. 复现命令（本文每个数字都能自己跑）

两个探针都是**一次性分析**，不进仓库（避免污染判据面）。取数 + 计算全在下面，照抄即可复现。

### 5.1 取数

```bash
# ① ADC survey（778 条实测）
curl -sL -o /tmp/adc.xlsx \
  "https://raw.githubusercontent.com/bmurmann/ADC-survey/main/xls/ADCsurvey_latest.xlsx"

# ② MOSIS 参数报告（避开 api.github.com 的 raw 域名抖动，走 contents API + base64）
python - <<'EOF'
import json, base64, urllib.request
T, N = "IBM_180nm", "t42s-params.txt"          # 其余 9 份同理，换 技术名/文件名
u = (f"https://api.github.com/repos/DDD-FIT-CTU/CMOS-SPICE-Model-Collections/"
     f"contents/MOSIS_waferTestData_{T}/data/{N}")
d = json.load(urllib.request.urlopen(u, timeout=30))
open(f"/tmp/{T}__{N}", "w", encoding="utf-8", newline="").write(
    base64.b64decode(d["content"]).decode("utf-8", "replace"))
EOF
```

### 5.2 计算（§1 / §2 的数字全在此）

```python
# ── §1 ADC 衰落 ──（xlsx 解包后按 36 列表头取值）
pairs = []
for r in records:                      # records = sheet2(467) + sheet3(313) 的行字典
    lf, hf, fin, fs = (f(r["SNDR_lf [dB]"]), f(r["SNDR_hf [dB]"]),
                       f(r["fin_hf [Hz]"]), f(r["fsnyq [Hz]"]))
    if None in (lf, hf, fin, fs) or fs <= 0:
        continue
    pairs.append((lf, hf, fin / fs))
assert len(pairs) == 156 and len(records) == 778
viol = [p for p in pairs if p[1] > p[0] + 0.1]        # ⇒ 2 条（+0.40 / +0.28 dB）

# ── §2 MOSIS：三个已公布参数的自洽性 ──
EPS_OX, Q, KSI_SI = 3.9 * 8.8541878128e-12, 1.602176634e-19, 11.7 * 8.8541878128e-12
Cox   = EPS_OX / TOX                                   # TOX 见 deck 的 TOX 字段
k1_pred = (2 * Q * KSI_SI * NCH * 1e6) ** 0.5 / Cox     # BSIM3 体效应系数定义式
ratio = K1 / k1_pred                                    # ⇒ 1.30 / 1.30 / 1.53 / 1.78 / 1.76

# ── §2.4 闭式 Vth（LDA 自己的实现）──
import sys; sys.path.insert(0, "D:/agent_LDA/lda")
from lda_l2.ecore.device_pde import physics_vth_closed
vth = physics_vth_closed(n_a_cm3=NCH, t_ox_nm=TOX * 1e9, vfb_v=-0.60)["V_th"]
# ⇒ 0.6190 / 0.6190 / 0.7555 / 0.5887 / 0.5887；减实测 LARGE Vth 即 §2.4 的偏差列
```

**唯一的自由参数是 `vfb_v = −0.60`**，取自 `ecore` 的工程默认 `VFB_V_DEFAULT`，不是为凑失败而设——
§2.4 已说明：语料**根本没给** `V_FB`，这正是判死理由。

## 6. 诚实边界（本文自身）

- **只有 10 份报告**（5 份带 deck），不是 249 份全扫。`NCH` 是模板常量这一条在 5/5 上成立，
  **但我没有验证另外 244 份**；若其中有不相同的，结论要收窄为「多数批次是模板值」。
- **`V_FB = −0.60 V` 是 `ecore` 的工程默认值**，不是我"设成能失败的数"。若某工艺真实 `V_FB` 恰好是 −0.34 V，
  那条会命中 —— 但**语料没给 `V_FB`，我无从判断哪个工艺是哪种**，这正是判死的理由本身。
- **本文没有测试「Vth 对 L 的单调性」**（实测：L=0.18 µm 时 0.46–0.51 V，L=50 µm 时 0.36 V，roll-off 存在）。
  那是一条**趋势**判据，而 P2b 定的闸门本来就是「不看趋势看绝对量级」——因为上一次失败正是"趋势符号相反、幅度却几乎相等"。
  若要重开趋势路，必须先解决 §2.4 的 `V_FB` 缺口，否则还是同一条死路。
- 路线①的「2/156 违反」我**没有**去追那两条记录原文核实，只说"在测量重复性内"，不主张它们有错。
- **本文不主张电子域"永远不可能"有实证锚**，只主张**本轮这两条路走不通**，且原因是**输入缺失**而非努力不够。
