# LDA 百万级器件规模 · 技术可行性评估

> 评估日期：2026-09-04 · 版本基准 v0.9.31
> 方法：**全部结论来自本机实测或代码取证，无一项来自推测**。凡属外推均显式标注。
> 环境：20 核 / 68 GB RAM / Python 3.13.14 / numpy 2.4.6
> 评估脚本：`assess_1m_layout.py`、`assess_1m_circuit.py`、`assess_1m_route_e2e.py`（留存可复现）

---

## 0. 结论先行

**百万级器件不是"能不能"的问题，而是"哪种百万级"的问题。分层判定差异达 6 个数量级。**

| 层 | 场景 | 百万级判定 | 实测证据 |
|---|---|---|---|
| 版图签核链 | 规则阵列 / 模板布线（无需避障） | ✅ **已达成** | 1M = **142.7s** / 0.97GB / LVS ACCEPT |
| 内存 | 1M 器件 IR 常驻 | ✅ 富余 | **2.35 GB** |
| 电路仿真 | 链式 / 总线（CPO 形态） | ✅ 已达成 | 16k=0.042s ⇒ 1M ≈ **3s** |
| **自动布线** | **A\* 避障（工业 EDA 核心能力）** | 🔴 **不可行** | 40 网=12.4s，**O(N^3.57)** |
| GDS 层次化 | cell / AREF | 🔴 **架构缺失** | SREF 原语存在但**全仓零调用** |
| 物理级验证 | 3D FDTD 全波 | 🔴 不可行 | 1000³ ≈ **96 GB** |

**战略判断：不建议将"百万级"设为升级目标。** 理由与替代方案见第 4 节。

## 1. 版图签核链：百万级已达成（有前提）

### 1.1 实测数据

用 S11 规模锚全链路（构建 → 2D 放置 → 多层布线 → LVS 签核）：

| N 器件 | build_s | lvs_s | **total_s** | 翻倍斜率 | RSS 增量 | LVS 判决 |
|---|---|---|---|---|---|---|
| 256,000 | 3.28 | 12.04 | **15.32** | — | 0.24 GB | ACCEPT |
| 512,000 | 7.13 | 36.95 | **44.08** | 2.88× | 0.48 GB | ACCEPT |
| **1,000,000** | 13.49 | **129.23** | **142.72** | 3.24× | 0.97 GB | **ACCEPT** |

**百万器件版图签核全链 2.4 分钟，内存 <1GB，LVS 判决 ACCEPT。**

### 1.2 增长阶分析（关键）

- **构建（build）近线性**：3.28 → 7.13 → 13.49（斜率 2.18 / 1.89，甚至次线性改善）
- **LVS 是超线性瓶颈**：12.04 → 36.95 → 129.23（斜率 3.07 / 3.50）
  - 拟合阶数：`log(129.23/12.04) / log(1M/256k)` = **O(n^1.74)**
  - 1M 时 LVS 占总耗时 **90.6%**

**外推**（标注：外推非实测）：
| N | LVS 预估 |
|---|---|
| 1M | 129 s（实测） |
| 10M | ≈ 2.0 小时 |
| 100M | ≈ 4 天 |

⇒ **版图签核层的真实天花板约在千万级**，百万级有充足余量。

### 1.3 🔴 成立的前提（必须显式交代）

上表成立的前提是：**布线走几何直连，不调用 A\* 避障**。

S11 链路与 CPO 250k 报告的布线（3.46s / 250k 器件）都是**模板化/规则化直连**——
源漏之间无障碍或障碍可忽略。一旦设计要求真正的**避障布线**，见第 2 节，结论完全反转。

## 2. 🔴 自动布线：百万级不可行（最硬的卡点）

### 2.1 单次路由成本 vs 障碍数（实测）

固定源漏距离（300×300 µm），只增加障碍数：

| 障碍数 | 单次 `route_net` | 翻倍斜率 |
|---|---|---|
| 0 | 0.02 ms | — |
| 250 | **1,220.92 ms** | — |
| 500 | 2,369.08 ms | 1.94× |
| 1,000 | 4,983.95 ms | 2.10× |
| 2,000 | 10,411.41 ms | 2.09× |
| 4,000 | 22,450.90 ms | 2.16× |
| 8,000 | **39,318.65 ms** | 1.75× |

⇒ 单次路由成本 ≈ **4.9 ms / 障碍**（线性于障碍数）。
代码根因：`lda/lda_layout/router.py:220-229` 每布一条网都要遍历**全部**障碍膨胀栅格；
`router.py:104-119` 的 `_path_hits` 是 O(采样点 × 障碍数)。

### 2.2 端到端增量布线（真实顺序流程，实测）

模拟真实流程：逐条布线，每布一条加入障碍集供后续避让。

| 网数 | 总耗时 | **翻倍斜率** | ms/网 |
|---|---|---|---|
| 5 | 0.010 s | — | 2.08 |
| 10 | 0.099 s | 9.56× | 9.94 |
| 20 | 1.044 s | 10.50× | 52.19 |
| **40** | **12.355 s** | **11.84×** | 308.88 |

⇒ 增长阶 `log(11.84)/log(2)` = **O(N^3.57)**。

**比 O(N²) 还差一阶半**：障碍累积不仅增加数量，还迫使 A\* 绕行，搜索空间随障碍密度超线性膨胀。

### 2.3 外推（标注：由实测斜率外推，非实测）

| 网数 | 端到端布线总耗时 |
|---|---|
| 40 | 12.4 s（实测） |
| 160 | ≈ 29 分钟 |
| 1,000 | ≈ **15 天** |
| 10,000 | ≈ **数万年** |
| 1,000,000 | 不可用 |

**结论：LDA 的自动避障布线在约 50 条网以上即失去工程可用性。**

这是一个必须正视的反差：
> 同一个系统，1M 器件签核只要 2.4 分钟，**但 40 条需要避障的网要 12 秒**。
> 前者成立是因为绕开了后者。

另有硬上限（`router.py:214`）：单次路由网格 > **4,000,000 格直接放弃返回 None**；
`router.py:161` `max_span = 2000 µm`。

## 3. 其余分层判定

### 3.1 ✅ 内存（非约束）

| 组成 | 1M 器件 RSS |
|---|---|
| Component 对象 | 1.28 GB |
| + placement（dict + tuple） | 0.54 GB |
| + routes（3 点折线） | 0.53 GB |
| **合计 IR 常驻** | **2.35 GB** |

68 GB 机器余量充足。⚠️ 但云端 8 GB 实例会紧张。

### 3.2 ✅ 电路仿真（链式/总线，非约束）

| N 器件 | 仿真耗时 | 翻倍斜率 | µs/器件 |
|---|---|---|---|
| 500 | 0.002 s | — | 3.76 |
| 16,000 | 0.042 s | 2.04× | 2.66 |

**O(n) 近线性，1M 器件外推 ≈ 3 秒。**

⚠️ 成立前提：**无环前馈拓扑**。引擎（`lda_chain/engine.py:55-85`）是 DFS 枚举所有简单路径——
在 MZI mesh / crossbar / 环形回环等拓扑下路径数**指数爆炸**（`seen = seen|{node}` 每步 O(n) 集合复制，
每边 O(n_wl) list 构造）。链式/总线形态下路径数为 O(1)，故未暴露。
**这是"未验证的风险"，不是"已排除的风险"。**

### 3.3 🔴 GDS 层次化：架构缺失（最本质的差距）

- `lda/lda_l2/gds_export.py:99-100` **存在 SREF（0x0A）写入原语**
- 但全仓 grep：**除 gds_export.py 自身外零调用**
- **无 AREF（阵列引用）**

实证代价：CPO 250,240 器件 → **897,600 个 GDS 元素 / 97.45 MB**，且是**完全 flat 展开**。
其中 40 光引擎 × 68 通道是**结构完全相同的重复单元**——
若使用 AREF，同样设计可压缩到数千元素、数 MB 量级。

**这是"百万级"最本质的架构差距**：
真实 EDA 处理十亿级器件靠的是 **层次化 + 阵列引用 + 层次化 DRC/LVS**，不是 flat 暴力展开。
flat 展开的 1M 器件：内存 2.35GB、GDS ~400MB、LVS O(n^1.74)——**能跑，但不专业**。

### 3.4 🔴 物理级验证（3D FDTD）

- `fdtd3d.py:155-160` 6 个 (Nx,Ny,Nz) float64 场；`run_large_grid.py:26-28` 估算 12 数组 × 8B = **96 B/点**
- **1000³ = 1e9 点 ≈ 96 GB** ⇒ 不可行
- 实跑上限仅 **N=120**（基准日志：numba-cpu 20.08s / torch-cpu 102.86s / numpy 865.52s）
- ⚠️ 默认值是伪 3D（`fdtd3d.py:198,240-241` 默认 `ny=nz=2`），名义 3D 实为准 1D 细柱

⇒ **百万器件逐个物理级验证不可能**，必须靠 PDK 降阶模型 / 参数化单元库。这条路 LDA 尚未建。

## 4. 需求侧校准：百万级是 2033+ 的需求

升级战略之前，必须先问：**谁需要百万级？**

### 4.1 光子（PDA）

| 标的 | 规模（2026 实证） |
|---|---|
| Broadcom Bailly / TH5 51.2T CPO | 8 个 6.4T 光引擎 |
| Broadcom TH6-Davisson 102.4T | 16 个光引擎（64 个 Condor SerDes 核） |
| NVIDIA Quantum-X Photonics | 4 ASIC × 9 组 3.2T 光引擎 = **36 个光引擎** |
| 单颗 CPO 光器件数（微环/波导/耦合器） | **数万量级** |

### 4.2 量子（QEDA）

| 标的 | 时间 | 规模 |
|---|---|---|
| IBM Condor | 2023 | 1,121 物理比特 |
| IBM Kookaburra | 2026 | ~4,158 物理比特（3 模块） |
| IBM Starling | 2029 | ~1 万物理比特 / 200 逻辑比特 |
| IBM Blue Jay | 2033 | 2,000 逻辑比特 |
| **破解 RSA-2048** | — | **≈ 100 万物理量子比特**（Google 2026 估算；Gidney 2021 估 2000 万） |

### 4.3 校准结论

**工业界当前真实规模：光子数万器件、量子数千比特。
百万级 = 领先实际需求 10–20 年（对应 2033+ 容错量子计算时代）。**

LDA 现有 CPO 250k 样例（25 万器件）**已经超过当前工业界单芯片需求约一个数量级**。

## 5. 战略判断与建议

### 5.1 为什么不建议把"百万级"设为升级目标

1. **它已部分达成** —— 版图签核层 1M = 2.4 分钟。设为"升级目标"名不副实。
2. **需求侧不存在** —— 客户今天需要的是数万器件 + 可信 PDK，不是百万器件。
3. **继续 flat 缩放不产生竞争力** —— 真实 EDA 的规模能力来自**层次化**，不是 flat 暴力。
   没有层次化的百万级 = 400MB GDS + 2 小时 LVS + O(N^3.57) 布线，是**负担不是资产**。
4. **真正的卡点在别处**：
   - 自动避障布线 O(N^3.57)（工业 EDA 的核心能力，LDA 最弱环节）
   - GDS 层次化缺失
   - PDK/工艺可信度（未流片、公开文献近似）
   - **外部验货：0 真实用户**（`dist/store.json` users=1）

### 5.2 替代路径：把"百万级"降级为**派生指标**

> **补齐层次化架构与布线器后，百万级会自然达成，且成本下降 1–2 个数量级。**

| 优先级 | 项 | 预期收益 | 工作量 |
|---|---|---|---|
| **P0** | **GDS 层次化（cell + AREF）** | CPO 250k：897,600 元素 → 数千；97MB → 数 MB；层次化后 LVS 只需在唯一 cell 上跑 ⇒ **复杂度骤降** | 中（SREF 原语已有） |
| **P1** | **布线器重写**（持久化空间索引 R-tree/网格 + 层次化分治） | O(N^3.57) → O(N log N)；解锁任意网表自动布线 | 大 |
| **P2** | 电路引擎 mesh 拓扑防护 | 消除指数爆炸风险（路径数上限 + 拓扑预检） | 小 |
| **P3** | 参数化单元库 / 降阶模型 | 替代"每器件 FDTD"，使物理级验证可规模化 | 大 |

P0 的杠杆最高：**它是唯一同时改善内存、GDS 体积、DRC、LVS、布线五项指标的单点改造。**

### 5.3 与现有主线的关系

当前 v0.9.32+ 主线是「可验货性」（T-7 一键复现 / T-8 去 GPU / T-9 锚题覆盖矩阵）。
P0 层次化与这条主线**不冲突但会抢资源**。建议二选一或明确排期。

## 6. 诚实边界

1. **A 层 1M 用的是链式拓扑 + 几何直连**，不代表任意设计。真实任意网表的百万级**未验证**。
2. **B2 端到端布线是小样本外推**（n=40 为最大实测点），且障碍为密集布局。
   稀疏、分散的真实布局会好于本表，但**量级结论（不可用）不变**。
3. **电路仿真指数爆炸未实测**——仅从代码结构（`engine.py:55-85` DFS）判定为风险，
   链式/总线形态下未暴露。mesh/crossbar 拓扑需另行构造测试才能定量。
4. **GDS 层次化的收益是估算**，未实测（LDA 当前无能力产出层次化 GDS，无法对比）。
5. 本机 68GB / 20 核属于较强配置，云端小实例的绝对数值会更差。
6. 需求侧规模数据来自公开检索（Broadcom / NVIDIA / IBM 公开路线图），为二手信息。
