## 1. 为什么"串起来"会产生新结论

单点各自正确，不等于串起来正确。分工变细的代价是：**没有人对"数字之间的关系"负责。**

本段抓到的三个缺陷，全部属于这一类：

### 1.1 面积口径混用：把"规模收益"记成了"换层代价"

`best_layer()` 报「面积 **×74.28**」。实际构成：

```
74.28 = 52.56（N 12→87 的 N² 规模因子，这是收益）× 1.41（换层因子，这才是代价）
```

而换层代价的真实值是 **1.33×**（同 N=87 下 `pitch_y` 2.40→3.20）。

⇒ 读者会以为「换层要付 74 倍面积」。正确读法是「换层只付 1.33 倍面积，而阵列变大了 7.25 倍是赚的」。

### 1.2 能效有两个口径，相差 3.27×，而只有一个能对外

| 来源 | N=87 | E25 的裁决 |
|---|---|---|
| `energy.system_energy_report`（自算 CDAC 开关能量） | **7.555 fJ/op** | 🔴 **下界**：CDAC 只占 ADC 总能耗 0.6~3.6% ⇒ 漏掉 96%+ 主体 ⇒ **不可对外** |
| `adc_calibration`（三条实测 FOM 锚反推） | **24.717 fJ/op** | ✅ **可信** |

流程若不知道这个，就会把 7.555 当结果报出去 —— **那正是 E25 花一整段纠正的错误。**

### 1.3 E31 把"链长 12"当成"via 数"

`ROW_STACK_CHAIN` 的 12 项里**只有 6 项是 via**（VIA1–VIA5 + VIA_AP），另 6 项是**金属落垫**（M1–M6）。

⇒ `n_vias = n² × 12` 把金属算成 via，**良率风险高估 2 倍**（9.1% vs 实际 4.5%）。
⇒ N=87 的正确数字是 **45,414 个串联节点**，不是 90,828。

🔴 这条**修正了 v0.9.328 已发布的数字**，`run_ecore_e31_smoke` 的 B12 判据一并修正。

## 2. 流程设计

### 2.1 8 个 Stage

```
device ─→ scale ─→ stack ─→ layout ─→ drc ─→ lvs ─→ gds ─→ report
器件族    基线能力   换层选型   版图生成   DRC    LVS   导出    带口径汇总
```

| Stage | 输入 | 输出 | fail 条件 |
|---|---|---|---|
| `device` | bits | 器件族（8 bpc + 1e5 耐久） | 无族满足精度/耐久 |
| `scale` | budget_pct | 基线 N 上界（M1 单端） | 基线 N < MIN_N |
| `stack` | budget_pct | 可签核层 + N 上界 + 换层参数 | 无层通过 DRC+LVS |
| `layout` | N, 层, W, pitch_y | 几何 + 元素数 + via 数 | 几何为空 |
| `drc` | 几何 | ACCEPT/REJECT | REJECT |
| `lvs` | 几何 + params | ACCEPT/REJECT | REJECT |
| `gds` | N, 层, W, pitch_y | 字节数 + roundtrip | flat ≠ 几何 或 roundtrip 失败 |
| `report` | 全部 | 能效/面积/via（带 basis） | — |

### 2.2 三条核心纪律

**① fail-fast + 反向完备**

任一步 FAIL ⇒ 立即停（`halted_at` 记录停点），后续全标 `SKIPPED`。
`stages_completed == 8` 才 `flow_ok=True` —— **少一步不算跑通**。

🔴 **停下 ≠ 报告可以缺步**：第一版 `run_flow` 直接 return，后面 7 步根本没进报告。
读者只看到 1 步 FAIL，不知道流程截断了多少。修法：`_pack` 补齐未执行步骤并排序。

**② 每数字带 basis + claimable**

```python
{"name": "energy_per_op_fj", "value": 24.717,
 "basis": "measured_adc_anchor(a28_8b)", "claimable": True,
 "note": "E25 口径：用实测 ADC FOM 反推 ⇒ 唯一可对外的能效值"}
```

**"哪个能对外"是机器可查的，不是注释里的约定。** 探针 C3/C4 专守此点。

**③ fail 与「未达标」是两件事**

| | 含义 | 处置 |
|---|---|---|
| **fail** | 物理/工具不可行 | 停流程 |
| **未达标** | `vs_target > 1`（差距） | **不 fail**，如实报 gap |

🔴 **本段第一版就在这里错了**：把 `recommend_family(target_fj)` 放在第 ① 步，
默认目标 8.3 fJ/op（低于任何族地板）让流程**第 1 步就 fail** ——
那等于说「达不到理想水平 = 器件不存在」。

## 3. 实测结果

### 3.1 N=87 全链：9.3 秒

| Stage | 结果 | 耗时 |

## 5. 我在本段踩的四个坑

| 坑 | 症状 | 判据 |
|---|---|---|
| 🔴 **耗时用了时钟读数** | 报告写「**16621.5 s**」，实跑 9.3 s（差 **1787×**） | B10 + C7 |
| 🔴 **`bits` 门槛被 `min()` 抹平** | `min(bits, MIN_BITS_PER_CELL)` ⇒ 要 10 bit 也按 8 bit 放行 | B13 场景① |
| 🔴 **`same_n_ratio` 用跨 N 除法** | footprint 的**常数边距**不随 N² 缩放 ⇒ 得 1.40 而非 1.3333 | B7 |
| **`_pack` 不补 SKIPPED** | 停下后报告只剩 1 步 | C6 |

🔴 第一条最值得记：**参数名叫 `t_all` 就容易忘记它是"时刻"不是"时长"**。
判据只要问一句「这个数像不像耗时」就能抓住（`0 < elapsed_s < 120`）。

🔴 第三条与 E20「跨口径比较必须同口径」同型，只是这次发生在**面积**上：
`area/(base_area×(n/base_n)²)` 看起来像归一化，实际因**常数边距不按 N² 缩放**而不干净。
正解是**真同 N 比**：直接算两次 `array_footprint(n, n)`。

## 7. 边界（必须与结果同屏）

### 🔴 流程里没有数字控制壳

E21 三条红线的第二条「数字链借不借」**至今未决**。

⇒ **产物是 CIM 阵列的签核报告，不是 SoC 的签核报告。**
`SOC_FLOW_DISCLOSURE["no_digital_shell"]` 明写此点，B12 守着不许删。

### 其他未建模项

- **无流片、无 PDK**；DRC/LVS 过 **≠ 可制造**（无 CMP / OPC / 天线 / 密度规则）
- **via 良率完全未建模**：45,414 个串联节点，1 ppm/节点 ⇒ ~4.5% 失效
- ADC 能耗的实测锚**只覆盖 ADC 子模块**，不是 CIM 芯片能效锚（E25 边界）
- 器件族与工艺参数为**公开 A 级来源照录**

### 净增 0 锚

流程产物是**设计期验证**，不是实测语料，不进 541。抬锚唯一路径仍是流片回来做实测。
