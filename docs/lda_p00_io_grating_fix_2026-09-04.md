## 2. 缺陷实况：三处，不是两处

| # | 位置 | 症状 | 状态 |
|---|---|---|---|
| 1 | `_io_grating_elements:120` | boundary 分支漏加 `(ox, oy)` 端口偏移 → 齿堆原点 | 🔴 **已触发** |
| 2 | `_device_elements:103` | 同模式无偏移 | 🟠 潜伏 |
| 3 | `_device_elements:99` | `d["points_um"]` 硬索引；boundary 描述只有 `rings_um`（两键互斥）→ **KeyError 崩溃** | 🟠 潜伏 |

根因是**同一段逻辑被抄了两遍、错得一样**：`path` 分支施加了偏移，`boundary` 分支没有。而 `primitive_descs('grating_coupler', n_tooth=16)` 返回的是 **1 个 path + 16 个 boundary（光栅齿）**——齿全走 boundary 分支，于是全军覆没。

---

## 3. 修复方式：抽公共函数，而非改两行

改两行能止血，但两处副本会再次分裂。改为抽出 **单一偏移施加处**：

```python
def _desc_elements(desc, ox, oy) -> List[bytes]:
    if desc["kind"] == "path":
        pts = [(ox + px, oy + py) for px, py in desc.get("points_um", [])]
        return [gds_export.path(desc["layer"], desc["width_um"], pts)]
    flat = [(ox + px, oy + py)
            for ring in desc.get("rings_um", []) for px, py in ring]
    return [gds_export.boundary(desc["layer"], flat)]
```

`_device_elements` 与 `_io_grating_elements` 均改为薄委托。同时消除了第 3 处 KeyError 潜伏崩溃。

## 5. 新护栏：经反向测试证明会响

新增常驻护栏 `lda/run_io_grating_offset_smoke.py`（CI core 91 → 92，~4s），四条死标量判据：

| 判据 | 内容 |
|---|---|
| A | 齿位置去重数 == n_io × 16（端口间不得重叠） |
| B | 每个端口 12µm 邻域内齿数 ≥ 16 |
| C | 齿总数守恒 == n_io × 16（对照项，恒 PASS） |
| D | 齿 x 跨度 > 端口 x 跨度（齿必须跟随端口铺开） |

**反向测试结果**：缺陷态 **5/10 亮红**（A 16/256、B 0 个齿、D 10.20 vs 6552.01）→ 修复后 **8/8 全绿**。

## 6. 🔴 本轮最重要的工程产出：判据分辨力教训

两版判据被自己推翻，这是比缺陷本身更有价值的收获：

1. **「每齿距最近端口 ≤ 12µm」恒 PASS** —— 齿堆在原点，而原点附近必定存在一个端口，所以每个齿都"贴近某个端口"。**零判别力，已删除**，而非留作虚假护栏。
2. **只跑 WDM 小案例时 B 判据也恒 PASS** —— WDM 端口跨度仅 16.10 µm，小于判据尺度，端口邻域互相覆盖。**补 CPO 大跨度案例（6552 µm）后才获得分辨力。**

> **判据必须在目标规模上标定。小样本会掩盖缺陷。**

这条与既有的「网格/截断双向标定」铁律同源，已写入项目长期笔记。

**为什么体积和元素数完全没变**：GDS 坐标固定用 4 字节编码，**齿移位不改变字节数**。这正是该缺陷能长期潜伏、躲过所有体积/元素数断言的原因——也说明判正确性必须查几何位置，不能查计数。

## 8. 已知待办（本次刻意不修）

`boundary` 的 `rings_um` 支持多环（带孔多边形），当前**展平为单环**。GDS BOUNDARY 仅支持单环，正确做法是每环一个元素。当前全部基元数据均为单环，故展平不改变元素数。已登记在 `_desc_elements` 的 docstring 中。

不在本次修，是为了不扩大回归面。P0-1 层次化产品化时会一并处理。
