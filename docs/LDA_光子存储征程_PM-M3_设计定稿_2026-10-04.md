## 0. 一句话结论

M0/M1/M2 交付的是**标量设计**（一个单元能不能写、能装几个电平、热与保持窗口够不够）；
M3 交付的是**「客户能用」的最后一跳** —— 把单元**排成阵列、出真 GDS、过 DRC/LVS 双闸、
并且在 UI 里点得到**（此前 PM 征程**无任何 UI 入口**）。

本轮有两个产出比「数字漂亮」更重要：

1. **热学结论直接改写版图密度** —— 单元 pitch **不是随意留白**，而由 `k_iso × L_max` 决定，
   且该热约束**大于**工艺间隙而成为 **binding 约束**（material/热学 → 版图的实证闭环）。
2. **吃狗粮抓出框架级真缺陷** —— 端口锚点缓存被 `id()` 复用毒化，导致 4×8 阵列 **51 处 LVS 假红**；
   这是 PM-M3 这个「第一次同进程多次构建」的新用法才暴露的**平台级 bug**，已修并改为**丑失败优于假绿**。

## 1. 器件原语 `PCMCell` —— 五处契约单一真源

新增器件原语 `PCMCell`：**Si 条波导 + GST 相变段 + 双侧微加热器 + 4 个电极 pad**。

| 契约面 | 文件 | 内容 |
|---|---|---|
| 几何 / pad | `lda_l2/primitives.py` | `PCM_CELL_DEFAULTS`、`pcm_cell_geometry`、`pcm_cell_descs`、`pcm_cell_pads` |
| 层栈 | `lda_l2/gds_export.py` | `LIB_LAYER_PCM = 5` / `LIB_LAYER_HEATER = 6`（继光子 1–4、超导 10–14、电子 20–26 之后） |
| 端口锚点 / bbox | `lda_layout/placement.py` | `port_anchor` / `device_bbox` 的 `PCMCell` 分支 |
| 端口名 | `lda_chain/link_model.py` | `_DEFAULT_PORTS["PCMCell"] = ["in","out","h1".."h4"]` |
| 规则 / 测量器 | `lda_l2/drc.py`、`lda_l2/lvs_geom.py` | `min_pad_um=2.0` + PCMCell 判据；4 个测量器 + 器件类登记 |

**几何关键约束**：电极中心 **y = 1.10 µm** > LVS 容差 `tol = 1.0 µm`（由 `heat_gap = 0.35` 定）。
若电极中心落进容差内，布线端点归属会退化为「靠更近取胜」的脆弱判定 ⇒ 设计上主动给出**无歧义**归属
（判据 B4 + 探针 P5 守）。

- 默认单元几何：`width 0.5 / length 11.0 / gst_overhang 0.20 / heat_gap 0.35 / heat_w 0.60 / pad 4.0`（µm）。
- `pcm_cell_pads` **只返回 4 个电极 pad**（h1..h4）；光端口 `in/out` 由 `port_anchor` 的 PCMCell 分支单独给出。

## 2. 阵列层：单元 pitch 由热串扰**咬合**

`cell_pitch_um` 逐项取 `max(热串扰间隙, 工艺间隙)`，并返回 **`binding`** 显式标注**哪一侧在咬合**。

**本档（GST）实测**：

| 量 | 值 | 来源 |
|---|---|---|
| 单元长度 `l_cell_um` | **11.0146 µm** | 上游 M1 设计点（`spacing_frac = 6.5708% ≥ 6%` · `worst_ber = 4.783e-14 ≤ 1e-12`） |
| 热扩散口径 `L_max`（上界） | **0.8788 µm** | 上游 M2（扩散口径 · 与文献经验上限 ~0.15 µm 同数量级） |
| 集总 RC 口径 `L_max` | 0.2723 µm | 上游 M2（保守口径） |
| 热串扰间隙 = `k_iso × L_max` | **7.0304 µm** | `k_iso = 8.0`（**设计选择**，非物理常数） |
| 工艺间隙 | 6.0 µm | 设计规则 |
| **`binding`** | **`thermal`** | 7.0304 > 6.0 ⇒ 热串扰成为 binding 约束 |
| **单元 pitch** | **18.0450 µm** | `l_cell 11.0146 + gap 7.0304` |

> 🔴 **诚实边界**：`k_iso = 8` 是**设计者选择**（隔离余量），不是从物理律推出的常数 —— `disclosure.k_iso_is_design_choice = true`，
> 且 `min_gap_um_rc_basis = 2.1787 µm`（若改用保守的 RC 口径）**并报**，不选择性披露。
> 若热学给不出更小的 `L_max`，版图密度就上不去 —— 这正是「材料/热学结论直接改版图」的实证（见 FINDINGS[0]）。

**拓扑**：支持 **1×N**（单总线串行）与 **R×C**（多总线）两类；行间距 `BUS_PITCH_UM = 16.0 µm`
（由「光栅高度 + pad 半高」定出）；总线两端加 **20 µm 引出波导**把光栅推离 pad（见 FINDINGS[1]）。

## 4. 独立解码复核（**刻意不复用**自家解码器）

阵列以 **flat** 导出，由自写的**最小 GDSII 记录流解析器**从**最终字节**独立解出层分布：

- 记录类型：BGNLIB/BGNSTR/BOUNDARY/PATH/SREF/AREF/LAYER/WIDTH/XY/ENDEL/ENDSTR/ENDLIB；DBU = 1e-3 µm（1 nm）。
- 判据：**层 5 元素数 == 单元数 ∧ 层 6 == 6× 单元数 ∧ 单结构 ∧ 无 SREF/AREF**。
- **完整性护栏**：必须真的走到 ENDLIB —— **截断 GDS（末 4 字节）必 `raise`**（探针 P2 守）。

实测解码：

| 档 | n_structures | n_elements | 层分布 | by_kind | sref/aref |
|---|---|---|---|---|---|
| 8×1 | 1 | 109 | {1:53, 5:8, 6:48} | boundary 72 / path 37 | 0 / 0 |
| 4×8 | 1 | 436 | {1:212, 5:32, 6:192} | boundary 288 / path 148 | 0 / 0 |

> 这与「声明闭合 ⇔ 证据机器可查」同一条纪律：**认证不读生成端的结论**，只读最终字节算出来的东西。

## 6. 吃狗粮：抓出的框架级真缺陷（非本档新码）

🔴 **`placement.port_abs` 端口锚点缓存被 `id()` 复用毒化**。

- **现象**：同一进程内**多次** `build_array`（如先 8×1 再 4×8）时，上一批对象被 GC 后
  新对象**复用同一 `id()`** ⇒ 命中陈旧组件索引 ⇒ 端口偏移**静默退回器件原点** ⇒
  **4×8 阵列一次性报 51 处 LVS 假红**。
- **为何此前不暴露**：8×1 单跑全绿；**只有「同进程多次构建 + 逐规模实测」才暴露**。
- **修法**：缓存值**持有对象引用** + `is` 身份校验 + **组件数版本校验** + 容量上限 64；
  并把 `port_abs` 的「实例不在 link ⇒ 静默返回器件原点」改为 **`raise`**
  —— **拒绝静默回退，丑失败优于假绿**。

> 这是本档最有价值的「吃狗粮」产出：**平台级缺陷由新的使用方式逼出来**（而非由本档新代码引入），
> 与 v0.9.176 星型网级联重复求和、v0.9.178 布局纪律隐含前提 属同一族。
