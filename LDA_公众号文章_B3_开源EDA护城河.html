为什么我们需要一个开源的 Agent-native EDA？——LDA 的定位与护城河

作者：杜玉河 · 工业5点0产业生态联盟

当巨头们忙着把 AI 塞进闭源工具链时，我们走了一条相反的路：让 AI 直接写底层求解器，却把判决权死死交还给物理定律与实测数据。这不是取巧，而是 EDA 主权唯一的出路。

一、EDA 的困局：巨头为何做不出开放内核

传统 EDA 三巨头（Synopsys / Ansys / Cadence）的商业模式，本质是卖闭源知识产权。这决定了他们结构性地无法开放核心求解器：一旦内核开源，护城河就塌了。于是「开放内核 + 社区共建 + 主权可控」这件事，巨头做不了，只能由新玩家从零定义。

二、LDA 是什么：AI 写内核，确定性裁判验收

LDA（Lightwave Design Agent）是一套面向光子芯片（PDA）与量子芯片（QEDA）的开源设计软件。它的核心范式只有一句话：

• 生成侧：AI agent 提方案、写代码，甚至递归自举开发底层 FDTD / 严格对角化等求解器。

• 判决侧：是否 PASS 由死标量比对决定——物理定律锚（解析解 / 麦克斯韦确定性计算）+ 实证大数据锚（真实测量语料）。LLM 不进判决路径，这是不可逾越的红线。

三、护城河不在求解器代码，而在标准 + 生态 + PDK 供给

底层求解器可以重写、可以替换，真正的壁垒是：统一的中间表示（IR/DSL）、开放的 PDK / 器件本体 Registry、以及带可信基准套件的开放内核。我们刻意把「主权内核」做成可被 AI 重写、却由社区共同验收的标准层——这意味着护城河来自生态，而非某段代码。

四、主权边界：我们做什么、不做什么

• 主权优先（C 级）：L0 IR / L1 协议 / L3 求解核 / 物理定律锚，第一天就自主。

• 借今踢后（B 级）：gdsfactory / Meep / KLayout / SAX 等 MIT/BSD 工具，fork 主权副本、零硬依赖、未装优雅降级。

• 永不借（A 级）：商业 EDA、NDA-PDK。封装测试、晶圆实测回流属发动期，诚实标注不夸大。

五、现在就能跑通的设计侧主权闭环

从设计目标到已验证器件，全链路主权可控、零 GPU 也能跑：设计 → 仿真 → 版图 → 主权几何 DRC/LVS → 工艺角 → 几何寄生估算。当前账本：
