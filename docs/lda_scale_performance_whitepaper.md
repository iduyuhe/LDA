# LDA 性能纵深白皮书：从 O(n²) 到 128k+ 近线性（v0.8.45 再治 LVS 残留 O(n²)）

> **副题**：一个主权可控的开源光子+量子芯片设计软件，如何把万级器件签核从「不可迭代」做到「32k 级亚秒」；并经 **v0.8.45 再治 LVS 残留 O(n²)** 后把规模推到 **128k+ 近线性（256k 全链 14.5s）**——从「外推可行」走到「实测铁证」。
>
> 版本：v0.8.44（2026-08-28）· 配套仓库：https://github.com/iduyuhe/LDA
> 本文所有数据均为本仓库代码实测（可复现），非纸面估算。

---

## 一、缘起：万级 VLSI 的六层困难

LDA（Lightwave Design Agent）定位为**开源、主权、Agent-native** 的光子芯片（PDA）+ 量子芯片（QEDA）设计软件。当设计规模从器件级走向**万级 VLSI**（万器件、万网络）时，我们拆出了六层困难：

| 层 | 困难 | 性质 |
|---|---|---|
| ① 物理仿真 | 万器件全波仿真物理不可能，需分层数值 + 宏模型级联 | 战略级 |
| ② 布线 | A* 逐网串行，需分区并行 + 拥塞估计 | 工程量 |
| ③ 签核（LVS/DRC） | 交叉检测 / 间距检查的 O(n²) 双重循环 | 硬门槛 |
| ④ 算力 | 单线程纯 Python | 可解 |
| ⑤ 验证语义 | 万级不能逐点死标量，需锚 + 统计混合 | 工程量 |
| ⑥ 市场时机 | 万级 PIC 尚在 CPO 前夜 | 等信号 |

其中 **③ 签核层的 O(n²)** 是最硬的拦路虎——1k 器件 LVS 0.88s 看起来还好，但**每翻一倍规模耗时 ×4**：4k 要 14.4s，16k 要 230s，32k 外推约 16 分钟——**完全不可迭代**。这是所有 EDA 规模问题的经典形态。

本文记录 v0.8.39 → v0.8.44 五轮「拔钉子」，把这条 O(n²) 曲线压成近线性。

---

## 二、五轮拔钉：每颗钉子都先定位、再根治、后铁证

### 钉子 1：LVS 交叉检测 O(n²)（v0.8.39）

**根因定位**（cProfile）：LVS 签核占千器件全链 97% 时间，热点两处——
- 端口锚点归属：每个布线端点线性扫全部端口（O(n·m)）
- 交叉短路检测：每一对网络的路径做相交判断（O(n²)）

**根治方案**（纯标准库，零新依赖）：
- 锚点建**均匀网格索引**（cell=tol，查询 3×3 邻域——数学上等价于全局最近，因为返回值必须落在容差内）
- 路径 bbox 进网格——「bbox 相交 ⟺ 至少共享一格」是**精确等价**（不是近似），网格只做候选剪枝，判决语义零变化

**实测**：

| 规模 | LVS 旧 | LVS 新 | 提速 |
|---|---|---|---|
| 1k | 0.88s | **0.01s** | ~88× |
| 4k | 14.39s | **0.04s** | ~360× |
| 32k | ~960s（外推） | **0.58s** | ~1600× |

### 钉子 2：构建器 O(n·m)（v0.8.40）

**根因**：布线构建 87% 时间耗在 `port_abs`——每次调用线性扫全部组件找实例（存量低效，只是以前被 LVS 的 O(n²) 掩盖了）。

**根治**：组件查找走索引缓存（O(1) 查表 + 缓存清理兜底），公共签名与坐标语义零变化。

**实测**：32k 器件**全链**（构建+放置+布线+LVS）从外推 ~960s 降到 **0.93s**（~1000×）。

### 钉子 3：几何 DRC 间距检查 O(n²)（v0.8.41）

**根因**：`gds_drc.check_geometry` 最小间距检查是纯 O(n²) 双重循环（每对多边形做 bbox 预检 + 段距）。

**根治**：与 LVS 同法——均匀网格候选（bbox 共格 ⟺ 精确等价），候选再按 bbox 重叠过滤，保证 `spacing_checked`/`spacing_note` 与旧实现**逐位一致**。

**实测**：稀疏 8k 多边形 **0.08s**（近线性，每翻倍 2.0-2.1×）；最坏情形（4000 多边形全重叠）**0.44s**——网格把候选剪到全对的 0.75%。

### 钉子 4-6：三连纵深（v0.8.42-44）

**④ 拥塞估计**（v0.8.42）：新增 `CongestionMap` 拥塞图，A* 启发式叠加惩罚——8 条平行网绕同一障碍，**最大占用 4→2、拥挤格 222→13（-94%）**。默认关闭时逐位一致（回归保护）。

**⑤ 并行布线**（v0.8.44）：`route_batch` 批量布线——`workers=1` 串行逐位一致，`>1` 进程池并行。**收益边界是实测出来的，不是拍脑袋**：

| 场景 | 单网耗时 | workers=4 |
|---|---|---|
| 链式拓扑 | ~12µs | 无收益（框架开销 > 任务） |
| 障碍密集复杂版图 | ~400ms | **2.67× 加速** |

诚实边界：拥塞感知布线有路径标记的**顺序依赖**，并行下明确拒绝（不伪并行）。

**⑥ 规模锚 4k + 相关簇锚**（v0.8.44）：
- S11 规模锚默认 1000→4000（v0.8.44，预算 10s，实测 0.07s，余量 140×）→ **128k（v0.8.45，预算 30s，实测 5.1s，余量 ~6×）+ 256k 纵深守护（实测 14.5s）**——规模锚本身跟着能力走，且**必须真跑过才敢写**（v0.8.44 的 4k 外推到 128k 曾被误判近线性，v0.8.45 cProfile 证伪）
- S12 阵列分布锚新增**相关簇锚**：连续 ≥3 通道同向偏离中位数 = 系统级簇漂移（工艺/温度梯度）→ REJECT。实证盲区：16 通道中 3 通道 +1.0~1.2dB，旧三锚（均值/下界/离群）全过 ACCEPT，**相关簇锚是唯一捕获者**。

## 三、汇总曲线：32k 器件全链亚秒

v0.8.40 后全链（构建+放置+布线+LVS）实测：

| 规模 | 全链耗时 | 缩放斜率 |
|---|---|---|
| 1k | 0.02s | — |
| 4k | 0.07s | 4.2× |
| 8k | 0.17s | 2.3× |
| 16k | 0.38s | 2.3× |
| 32k | **0.93s** | 2.4× |

**斜率从 O(n²) 的每翻倍 4×，压到近线性 2.3-4.2×**（剩余为 dict/IO 常数项；4k 首次翻倍含构建常数项摊销）。32k 器件全链从不可迭代（16 分钟）到亚秒——这正是「万级 VLSI」技术地基的意义。

> ⚠️ **诚实边界（v0.8.45 修正）**：v0.8.44 的"近线性"只在 32k 级成立。把 S11 锚推到 64k/128k 真跑 + cProfile 后发现：**LVS 短路检测仍是 O(n²)**——v0.8.39 网格按**路径 bbox** 分桶，长链/跨行 M2 跳线 bbox 横跨整版图触发退化全对回退，128k 全链实测 12.5s 且随规模指数恶化（外推 256k 分钟级）。"32k 近线性"掩盖了残留 O(n²)。这正是**外推不能当能力宣称**的红线教训。

### 钉子 7：LVS 短路检测残留 O(n²)（v0.8.45）——按线段分桶

**根因定位**（cProfile，128k 全链）：旧网格候选对枚举 `_cross_pair_candidates` 累计时间倍率 32k→128k 达 **×11.77**（调用次数 ×13.95），远超线性（理想 ×4）；而构建/放置/布线同期 ×4.5 达标。退化回退的触发条件：`n_cells > 4*n_tot+64`（长 bbox 跨全图）。

**根治方案**（纯标准库，零新依赖，判决语义零变化）：把分桶单元从**路径 bbox** 改为**单条线段**——每条线段落进它真实覆盖的所有 cell，相交两线段必共享至少一个 cell → 候选对是真实相交对的**超集** → `_paths_cross` 精确过滤，短路集合逐字节不变。`_cross_pair_candidates` → `_collect_cross_shorts`。

**等价铁证**（红线守护）：`verify_lvs_cross_equiv.py` 用 **naive O(n²) 真值基准**（仅 `_paths_cross` 语义，不绑死任何实现）对照新线段网格，46 组随机/边界/长链/跨层断言 **FAIL=0，逐字节一致**。
> ⚠️ **勘误（v0.9.36，2026-09-04）**：事后审计发现该脚本当时内嵌了一份旧标量 cell 副本、并未直接测生产代码（护栏测副本 = 假护栏）。生产级等价护栏现由 `lda/run_lvs_cross_equiv_smoke.py` 承担（直接 import 生产 `_collect_cross_shorts`，48 组断言 + 反向测试证明会响）。本节的历史实测数字仍然有效（当时生产代码与副本恰好同版）。

**实测（v0.8.45，S11 全链 = 构建+放置+多层布线+LVS，verdict 全程 ACCEPT）**：

| 规模 | 全链耗时 | LVS 耗时 | 缩放斜率（全链） |
|---|---|---|---|
| 4k | 0.07s | 0.04s | — |
| 32k | 0.87s | 0.57s | 2.4× |
| 64k | 2.14s | 1.44s | 2.5× |
| 128k | **5.09s** | 3.54s | 2.4× |
| 256k | **14.5s** | 11.2s | 2.85× |

128k cProfile 热点榜前 12 名**已无 lvs.py 函数**（单函数 <10.7ms）——短路检测彻底退出瓶颈。规模斜率稳定在 **2.26-2.85×/翻倍**（近线性），256k 全链 14.5s 仍在 30s 预算内。**10万+ 器件签核从"外推可行"变为"实测铁证"**。

**结论修正**：32k 级规模不再是瓶颈（v0.8.44 已证）；**128k+ 经 v0.8.45 治 LVS 残留 O(n²) 后同样近线性**——规模真不再是瓶颈，瓶颈回到物理模型与市场时机（C 期三信号未解锁前，纯引擎纵深，"等信号的底气"）。

## 四、判决一致性铁证（红线不破）

所有提速都建立在「判决语义零变化」之上，铁证如下：
- LVS：3 案例（consistent/disconnect/misroute）× 4 规模 + 单层，与改造前黄金基线**逐字节 diff 零差异**；随机 400 条折线 **62138 个交叉对零漏报零误报**
- DRC：violations 3=3、checked 13=13、spacing_note 逐字符一致
- 并行布线：串行/并行结果逐位一致
- 规模锚：4k 判决与 1k 同构（ACCEPT/REJECT 确定性）

**LLM 不进判决路径**：所有 PASS/FAIL 由死标量比对决定；AI 只负责生成候选和默认参数。这条红线从第一天守到今天。

## 五、诚实边界

1. **性能对标非流片**：等效验证非本团队流片/实测；真实 PDK/晶圆实测属发动期（C 锁死）。
2. **numba 实测无效**：对细粒度几何内核（4 元素 tuple 短调用）numba njit 反而更慢（1.69s vs 0.44s）——锁定纯 Python 为最优，不引入无效依赖。
3. **并行收益有边界**：细粒度场景并行是负优化，复杂版图才有 2.67×。
4. **几何 DRC 非 foundry 全量**：主权几何规则，子集诚实标注。
5. 真实万级量产需求（CPO 万通道阵列）尚未出现——技术地基已备好，**等市场信号**（这也是我们不开足马力扩规模的原因）。
