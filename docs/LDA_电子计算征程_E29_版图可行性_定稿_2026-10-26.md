## 0. 一句话结论

E28 用闭式算出「RDL + W0.8 + 双端 ⇒ N=125、vs Mythic 2.1×」。
本段调用 E6 的真实版图能力逐条验 —— **三条路径没有一条能直接落地**。

> 这不是 E28 的物理结论有错（`C` 与 `t` 无关、`R·C` 与 `W` 无关仍是精确恒等式），
> 而是**平台当前表达不了那些方案**。这一区分是本段最重要的产出。

## 1. 发现①：「换 RDL 厚金属」在平台里不存在

E6 电子层栈只有 **7 层**（枚举自 `elayers.py`，不硬编码）：

```
DIFF(20) / POLY(21) / CONT(22) / M1(23) / VIA1(24) / M2(25) / PAD(26)
```

—— **无 M3/M4/M5/M6、无 AP/RDL、无 VIA2 及以上**。

| E28 方案 | 需新增层 | 缺口 |
|---|---|---|
| M6 级（r×5 · N=29） | M3/M4/M5/M6 + VIA2/3/4/5 | **+8 层** |
| RDL/AP（r×10 · N=42） | M3-M6/AP + VIA2-5/AP | **+10 层** |

## 2. 发现②：「加宽到 W0.80」被 DRC 否决

实测临界线宽（N=8 · 扫 0.40→0.60）：

| `row_w_um` | DRC | 违规数 | 首条违规 |
|---|---|---|---|
| 0.40 | ACCEPT | 0 | — |
| 0.45 | ACCEPT | 0 | — |
| 0.50 | ACCEPT | 0 | — |
| **0.52** | **ACCEPT** | 0 | —（**临界**） |
| 0.55 | **REJECT** | 64 = 8² | `M1 间距 0.225 < 0.230 µm（col0 / row0）` |
| 0.60 | REJECT | 144 = 12² | 同上 |

### 这是真冲突，不是误报

违规对象是 **行线（`row0`，M1 水平）与列线在 M1 上的落垫（`col0` boundary）**。
间距 0.225 < 0.230（`m1_min_space_um`）。

**三条旁证**：

1. **违规数 ≡ N²** ⇒ 每单元一处，系统性布局冲突；
2. **`pitch_y` 加大不能解决**（2.40→3.20 全 REJECT）⇒ 冲突在**同一单元内**；
3. **几何回提 `row_w` ≡ 声明值 0.4000** ⇒ DRC 不是因为参数没进几何。

⇒ **现有布局最大加宽 = 0.40 → 0.52 µm = ×1.30**，不是 E28 假设的 ×2。
⇒ 「加宽」**不是改一个参数，而是一次单元版图重设计**（要把列线的 M1 落垫挪开，或改从 M2 直接出线）。

## 3. 发现③：平台 DRC 复杂度约 O(N⁴)

| N | DRC 耗时 | 相对 N=12 | `(N/12)⁴` |
|---|---|---|---|
| 12 | 0.2 s | 1× | 1× |
| 26 | 3.8 s | 19× | 22× |
| **42** | **26.4 s** | **132×** | 150× |

⇒ N=87 估 **~8 min**、N=125 估 **~7 h**（外推，**未实测**）。

🔴 真实 DRC 工具是 O(N log N) 量级 ⇒ **这是平台能力缺口，不是物理限制**。
⇒ **可签核规模受工具限制**：E28 的 125 行方案，即使层栈与线宽都解决，**跑一次 DRC 要 7 小时**。

## 6. 我在本段踩的两个坑

### ① 探针内不得调用被 patch 的同一名字

```python
# ❌ 无限递归
with mock.patch.object(F, "current_layers", lambda: F.current_layers() + [...]):
# ✅ 先存原函数
_real_cl = F.current_layers
with mock.patch.object(F, "current_layers", lambda: _real_cl() + [...]):
```

C1 与 C5 **各踩一次**（C5 是 `_fast_scaling` 调 `F.drc_scaling()`）。
⇒ **写探针的固定动作：凡是 patch 某名字，同一作用域内的辅助函数必须先把它存下来。**

### ② 判据键名凭记忆写

`max_drc_width()` 的 `first_reject` 里是 `first`（字符串）+ `rules`（列表），
我按记忆写成 `fr["detail"]` ⇒ 当场 KeyError。

⇒ **判据要引用的字段，写之前先 dump 一次**。

## 9. 对下一段的硬指令

### 🔴 平台的三处能力缺口（按修复价值排序）

| 缺口 | 影响 | 修复代价 |
|---|---|---|
| **① 层栈只有 M1/M2** | 所有降阻路径（换层）都表达不了 | 定义 +8~+10 层 + via 关系（**纯软件，最便宜**） |
| **② DRC 复杂度 O(N⁴)** | N>42 不可实用（125 行要 7 h） | 需重写为空间索引（网格/扫描线）⇒ **O(N log N)** |
| **③ 无双侧驱动端口结构** | 双端驱动（唯一不动工艺的杠杆）无法验证 | 新增版图元素 + 左右通道 |

### 建议顺序

**先修 ①（最便宜、解锁最多）**：`elayers` 加 M3-M6/AP + VIA2-5/AP，`array_lines` 支持行线走指定层。
这一步做完，E28 的 42 行方案就**第一次可以跑 DRC**。

**再修 ②**：否则 ①修完也跑不动（42 行要 26 s，125 行要 7 h）。

**③ 可以最后**：双端驱动的版图结构较复杂，且它的收益（×4）在 ① 完成后相对次要。
