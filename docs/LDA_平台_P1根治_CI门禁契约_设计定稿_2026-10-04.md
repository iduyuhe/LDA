# LDA 平台 · P1 短板根治：CI 门禁自身契约（棘轮时序假红 + 门禁退出码失效）

> 版本：**v0.9.190**（2026-10-04 · HEAD 见提交）· 账本 **476 不变（零锚改动）** · CI core **277 → 278** · 端点 **146 不变**
> 本轮性质：**平台自身能力修复**（不改任何物理判据、不动任何锚、不新增器件能力），修复对象是「门禁/工具链」而非「被测量的物理」。

---

## 0. 执行摘要（结论先行）

本轮根治**两类会让 CI 判决失真的缺陷**，两者都属本仓最忌的「假红 / 假绿制造机」家族：

| # | 缺陷 | 危害 | 状态 |
|---|---|---|---|
| ① | **棘轮时序假红** | 每加一个 CI 成员，`--write-baseline` 全量**必产一条零信息量假红**（M0/M1/M2 连续三轮印证）⇒ 稀释真红信噪比、诱导后人去「改判据」 | ✅ 根治（含端到端证据） |
| ② | **门禁退出码失效** | `pm_m1`/`pm_m2` 门禁的 FAIL **永不被 CI 捕获**（rc 恒 0）⇒ **假绿** | ✅ 修复（含行为证据） |

并新增常驻门禁 **`run_ci_gate_contract_smoke`（14 判据 + 5 突变探针）** 把两者钉成机器纪律。

---

## 1. 缺陷 ①：棘轮时序假红

### 1.1 现象（三轮同型）
凡新增成员进 CI core 后跑 `python scripts/ci_core_batched.py --write-baseline`，终局 summary 恒为
**N PASS / 1 FAIL**，唯一 FAIL **必是** `run_timeout_budget_ratchet_smoke.py`：
`rc=1` · `elapsed_s ≈ 0.82`（**秒退**）· 失败原因指向 **B5「覆盖完备：新成员缺基线行」**。

### 1.2 根因（工具侧鸡生蛋）
```
批次 1..16（棘轮在其中某批执行 —— 读【上一版】基线 ⇒ 新成员无行 ⇒ B5 红）
        ↓
全部批次跑完
        ↓
_write_baseline() 写回基线（此时新成员才有行）
        ↓
汇总 verdict / 返回码（已把那条假红计入）
```
即：**棘轮要求「基线最新」，而基线只在最后才变最新** —— 判据与工具的执行序相互矛盾。

### 1.3 修法（最小侵入 · 不动批次结构）
`scripts/ci_core_batched.py`：

1. **抽出可重入汇总** `_summarize(results, ...) -> (out, failed)`：原先内联在 `main()` 的汇总段，
   现在必须可重入 —— 否则「后置复跑后重算」会让**报告 JSON / verdict / 返回码**三者互相打架
   （那正是本仓最忌的「同一事实两处口径」）。
2. **抽出 `_write_report(path, out)`**：报告重写复用同一出口（写盘失败不得掩盖判决）。
3. **新增 `_rerun_ratchet(a, all_scripts)`**：写回基线**之后**单独复跑棘轮（`scripts=[棘轮]`）。
4. **新增 `_overlay(results, one)`**：用后置结果**覆盖**同名条目（**不论红绿 —— 绝不掩盖真红**：
   基线已最新仍红 ⇒ 那是真问题、必须照红）。
5. `main()` 在 `--write-baseline` 分支中：写基线 → 记录 `pre_status` → 后置复跑 → `_overlay`
   → **重算** `_summarize` → **重写**报告 → 打印后置结论。
6. 报告中新增证据块 **`ratchet_post_baseline`**：`{reason, pre_status, post_status, post_rc, verdict}`，
   其中 `verdict` 由**实际红绿算出**（`时序假红已消除` / `真红（基线已最新仍红 ⇒ 不得掩盖）` / `无变化`）。

**行为不变性**：非 `--write-baseline` 模式**完全不变**（批次结构、耗时统计、`_write_baseline` 输入均不动）。

## 2. 缺陷 ②：门禁退出码失效 = 假绿（顺带实证发现）

### 2.1 现象与口径
CI 判定 smoke 成败的口径是 **`PASS if rc == 0 else FAIL`**（`run_ci_regression._run_one` L2451），
stdout 里的 `[FAIL]` 行**除 SKIP / CRASH 消歧外不参与判定**。
⇒ **`main()` 恒 `return 0` 的门禁 = 假绿**（判据在跑、FAIL 在打印、CI 永远 PASS）。

实测：`run_pm_m1_smoke.py`（**24 条判据**）/ `run_pm_m2_smoke.py`（**40 条判据**）的 `main()` 均恒 `return 0`。

### 2.2 行为证据（决定性 · 走真代码路径）
把每个 smoke 的 `check` 包一层「恒判 False」后真跑 `main()`：

| 模块 | 注入恒 FAIL 后 `[FAIL]` 行数 | **修复前 rc** | **修复后 rc** |
|---|---|---|---|
| `run_pm_m1_smoke` | 24（判据确实在跑） | **0**（假绿） | **1** ✓ |
| `run_pm_m2_smoke` | 40（判据确实在跑） | **0**（假绿） | **1** ✓ |

### 2.3 修法
对齐既有正确范式（`run_pm_m0_smoke` / `run_oi_m0_smoke`）：
```python
return 0 if (globals().get("PASS", 0) and not globals().get("FAIL", 0)) else 1
```

### 2.4 全仓扫描结论（AST · 277 成员）
初版粗判据报出 **17 个**「纯 `return 0`」候选 ⇒ 逐一核实后 **全为假阳性**：

| 形态 | 个数 | 说明 |
|---|---|---|
| `raise SystemExit(run_unittest_suite(...))` | 14 | unittest 范式，rc 正确 |
| `assert` 型（19 / 9 个 assert） | 2 | AssertionError ⇒ 非零 rc |
| 无判据 CLI 演示入口（0 check / 0 assert） | 1 | `lda_harness/run_empirical_bank.py`，恒 0 属**设计预期** |

⇒ **真缺陷仅 `pm_m1` / `pm_m2` 两处**（均为本征程新引入），其余 **275 个成员均已有失败通道**。

> 🔴 **判据收敛过程本身就是教训**：这条静态判据改了 **7 版**才收敛。三个必备特判：
> **① `sys.exit(main())` 的通道性必须继承 `main` 自身**（否则把最主流写法误判为无通道 —— 假阴性）；
> **② `assert` 也是通道**（AssertionError ⇒ 非零 rc —— 漏了会假阳性）；
> **③ 「常量」不能一票否决** —— `if FAIL: return 1` + `return 0` 全是常量但完全正确（假阳性）。

## 3. 新增常驻门禁 `run_ci_gate_contract_smoke`（14 判据 + 5 探针）

### 组 A · 棘轮时序
| 判据 | 内容 |
|---|---|
| A1 | 汇总可重入且字段齐（summary / budget_audit / verdict） |
| A2 | 后置复跑已消除时序假红（batch 内 FAIL ⇒ 终局 rc=0 / fail=0） |
| A3 🔴 | **不掩盖真红**（后置仍 FAIL ⇒ rc=1 / fail=1 / verdict ≠「已消除」）—— **反向判据** |
| A4 | 事件序 `批次 → 写基线 → 后置复跑`，且后置**只**跑棘轮 |
| A5 | 非 `--write-baseline` 模式行为不变（无写基线 / 无后置 / 报告无证据块） |
| A6 | 证据块由实际红绿算出（pre=FAIL ∧ post=PASS ∧ verdict=已消除 ∧ reason 非空） |

### 组 B · 退出码契约
| 判据 | 内容 |
|---|---|
| B1 | 无「有判据却无失败通道」的门禁 —— 🔴 **判据不含手写豁免清单**：本就无判据的文件（CLI 演示入口）自动不判红，避免清单静默进盲区 |
| B2 | 覆盖面完整（277 成员全被扫到，无静默跳过） |
| B3 | 自食其规则（本 smoke 自身在 CORE_SMOKES 内且过契约） |

### 突变探针（每条先证能变红）
| 探针 | 证明 |
|---|---|
| P1 | 禁用后置复跑（= 未修前旧行为）⇒ 假红仍在（rc=1 / fail=1）—— **证明「不加此修必红」** |
| P2 | `_overlay` 改为「不覆盖只追加」⇒ 同名 2 条 ⇒ A4/A2 必红 |
| P3 | 丢弃后置结果 ⇒ fail=1 ⇒ A2 必红 |
| P4 | 内联样例「有 check + 恒 `return 0`」⇒ 判据**必判红** |
| P5 | 内联样例「有 check + 条件返回」⇒ 判据**不**判红（证明判据**非恒真**） |

> （278 条 · 16 批 · 日志/报告落 `%TEMP%`）

**结果：⏳ 跑完回填。**

关键观察点（本轮修法的真实考验）：
1. 终局 summary `fail == 0`（**不再需要人肉复跑棘轮**）；
2. 报告出现 `ratchet_post_baseline`，其 `pre_status=FAIL` / `post_status=PASS` / `verdict="时序假红已消除"`
   —— 即**假红确实发生过、且被后置复跑自动消除**（保留了「发生过」的可审计痕迹，而不是把它藏起来）；
3. `budget_audit.n_items == 278` ∧ `low_margin` 空。

## 6. 已知边界（诚实披露）

1. **批次内那次棘轮读数仍会入基线样本**（`_write_baseline` 只剔 TIMEOUT/CRASH，不剔 FAIL）。
   影响：棘轮的 `elapsed_max_s` 可能取到那次的 ~0.82s ⇒ margin 极大、不触发欠标定 ⇒ **无害**。
   保留现状的理由：最小侵入（动 `_write_baseline` 的样本筛选规则会改变既有基线语义，风险大于收益）。
2. **组 B 是静态判据**，非行为验证。它能可靠抓「`main()` 恒常量返回且无其它通道」这一族，
   但**不覆盖**「有通道却在语义上不该失败」（那属于另一类问题，见 `run_dead_assert_guard_smoke`）。
   故组 B 的定位是**粗筛 + 显式归档**，配 P4/P5 证明其判别力。
3. **`lda_harness/run_empirical_bank.py`** 属「无判据的 CLI 演示入口」，组 B 对其自动不判红。
   若后续要把它当门禁用，应先给它加判据（届时 B1 会自动要求它同时有失败通道）。
4. 本轮**零锚改动、零物理判据改动**——所有变更都在「门禁/工具链」层。
