## 1. 瓶颈定位（profile 实测，不是估计）

v0.9.327 在 N=16（4,896 元素）上 profile：

| 函数 | `_overlap` 调用次数 | 累计耗时 |
|---|---|---|
| `run_edrc` | **11,278,080** | 3.47 s |
| `elvs_signoff` | **11,576,432** | 8.41 s |

元素数 4,896 ⇒ `n²/2 ≈ 1,200 万`，**正好对上**。

四处检查全部是全对全配对：

| 位置 | 检查 | 原复杂度 | 说明 |
|---|---|---|---|
| `run_edrc` ② | 同层最小间距 | 每层 O(k²) | 按层分组后每层内全对全 |
| `run_edrc` ③ | via enclosure | **桥 × 全部元素** | 每个桥扫整个 `boxes` |
| `elvs_signoff` ② | 同层相交 ⇒ 短路 | **全对全** | `for a: for b` |
| `elvs_signoff` ③ | 桥连通性 | **桥 × 全部元素** | 每个桥扫整个 `els` |

元素数 ∝ N² ⇒ 总复杂度 **O(N⁴)**。

## 2. 做法：索引只筛候选，判定不变

### 2.1 新增 `lda_l2/ecore/spatial.py`

**均匀网格 + 长条单列**：

```
bbox 跨度 ≤ 64 格  →  放进网格 buckets[(i,j)]
bbox 跨度 > 64 格  →  放进 oversized[]，查询时线性扫
```

- `Grid.query(bbox, expand)` → 与 `bbox` 两轴都 ≤ expand 的候选索引（**超集**）
- `Grid.near_pairs(expand)` → 所有候选对
- `brute_pairs(...)` → O(n²) 暴力超集，**只用于对拍判据**

长条（行线/列线）数量是 N，故 `oversized × all` = `N × N²` = **O(N³)**，
比 O(N⁴) 低一整个 N。

### 2.2 🔴 本段最重要的设计纪律

> **索引只负责「谁需要被检查」，不负责「是否违规」。**

判定仍然是原来的 `_overlap` / `_gap` / `_enclosure`，一个字没改。

```python
# 旧：全对全
for a in range(len(items)):
    for b in range(a + 1, len(items)):
        if _gap(items[a][0], items[b][0]) < sp: ...

# 新：只看候选对，判定同一个 _gap
for a, b in _SP.near_pairs(lb, expand=sp):
    if _gap(lb[a], lb[b]) < sp: ...
```

**为什么这条最重要**：如果让索引也参与判定，一旦新旧结果不一致，
就出现「不知道谁对」的死局 —— 那比慢得多更危险。
现在索引只会**多给候选**（超集），永远不会**少给**，所以判定结果必然一致。

### 2.3 小规模回退

索引有固定开销：n=120 时实测 **0.9×**（比暴力还慢）。
⇒ `SPATIAL_MIN_ELEMENTS = 256`，低于此走暴力。
两种路径结果相同，所以切换点**不影响正确性**，只影响速度。

## 3. 正确性证据：对拍（不是论证）

### 3.1 9 个案例，含 **5 个 REJECT**

| 案例 | 元素 | DRC 旧→新 | LVS 旧→新 |
|---|---|---|---|
| M1 基准 | 464 | ACCEPT → ACCEPT | ACCEPT → ACCEPT |
| **M1 R=0.55 间距** | 464 | REJECT → REJECT（**64/64**） | ACCEPT → ACCEPT |
| **M1 R=0.60 间距** | 1,032 | REJECT → REJECT（**144/144**） | ACCEPT → ACCEPT |
| AP+栈 | 1,232 | ACCEPT → ACCEPT | ACCEPT → ACCEPT |
| **AP W=0.40 宽度** | 1,232 | REJECT → REJECT（**72/72**） | ACCEPT → ACCEPT |
| **AP 无栈 悬空** | 464 | ACCEPT → ACCEPT | REJECT → REJECT（**64/64**） |
| **M2 行线 短路** | 592 | REJECT → REJECT（**64/64**） | REJECT → REJECT（**1/1**） |
| M6+栈 | 2,472 | ACCEPT | ACCEPT |
| M3+栈 | 1,608 | ACCEPT | ACCEPT |

🔴 **必须含 REJECT**：只对拍 ACCEPT 等于「空集 == 空集」，
证明不了违规路径也一致。这是 E31 学到的教训（当时的 C4 探针就是因为只测通过路径而假绿）。

🔴 **比集合不比列表**：旧实现是 `a<b` 字典序、新实现是格遍历顺序。
**顺序不同不代表错**。正确性标准是「违规集合相同」。

### 3.2 超集性机核

`near_pairs ⊇ brute_pairs`，在真实阵列 × 4 组几何 × expand(0 / 0.28 / 1.60) 上逐格验。

两条可证性质：
- **相交** ⇒ 两 bbox 有公共点 ⇒ 必共享至少一个格
- **间距 < expand** ⇒ 外扩 expand 后必相交 ⇒ 用外扩 bbox 查询即可

### 3.3 一个反向探针：cell 放大 1000×

把网格 cell 放大到 1000 µm（退化成一格装下全部），结果**必须不变**。
这条验的是「**正确性不依赖性能参数**」—— 网格尺寸只影响速度，不影响候选超集。

## 5. 剩余瓶颈（诚实披露）

`oversized`（行线）走线性扫 ⇒ `N 条 × 全体` = **O(N³)**，
这是 N=87 那 4.1 s 的主要来源。

| 目标 | 估耗时 | 是否需要再优化 |
|---|---|---|
| N=87（当前最大需求） | 4.1 s | ✅ 够用 |
| N=125 | ~12 s | 可接受 |
| N=200 | ~50 s | 🟡 建议用 1D 区间排序处理行线 |
| N=500 | ~20 min | 🔴 必须优化 |

**本段不做**：4.1 s 已满足「能签核」的实用门槛，继续优化属过度工程。

## 6. 我自己在本段踩的两个坑

### 坑一：C3 探针假绿（死代码造成的）

第一版 C3 用「丢掉 oversized ⇒ 违规数变少」来验。
但 `M1 R=0.55` 案例只有 **N=8**，行线跨度 2.85 µm ÷ cell 0.9 µm = **3 格**
⇒ **根本不进 oversized** ⇒ 那段代码在该规模下是**死代码** ⇒ 探针永远打不红。

修法两步：
1. C3 改用**人造长条几何**（1 条跨 100 格的条 + 10 个小块）直接验分支
2. 新增 **B8**：N=24 时 oversized **必须真的被触发**（防它变成没人跑的代码）

> 这与血案「不在任何子集里的自检 = 没人跑的自检」同型：
> **一段代码如果在所有测试里都没被走到，那它等于不存在。**

### 坑二：挪函数丢 import

`scale_table` 的实现挪到 `_scale_impl` 后，`import time as _t` 留在了原函数里
⇒ `NameError: name '_t' is not defined`。

局部 import 不是"无害的"，**挪函数要连带挪 import**。

## 8. 诚实边界

1. **空间索引不是 DRC 工具**。设计规则仍在 `ELEC_DESIGN_RULES` + `EDRC_RULES`，一个字没改。
2. **N=87 的 ACCEPT 只说明几何自洽**，不是可制造性（无 CMP/OPC/天线/密度规则）。
3. **实测只在 N ≤ 87**。更大的外推（N=125 ~12 s、N=200 ~50 s）**未实测**。
4. **旧实现保留为 `spatial=False`** —— 它不是兼容包袱，是**对拍基准**。
   没有它就无法证明新实现没漏对。
5. 输出恒 `MODEL_ESTIMATE`；**净增 0 锚**。
