## 1. 为什么要做（正当性，不是造需求）

上一批 MEM1 已把「设计期闭式核对·非流片实测」变成机器门禁，但它只守住了三件事：声明存在、禁语扫描、`N.NNN TB/s` 通式回算。本次只读核查发现**三类真实缺口**：

| 缺口 | 证据（本轮实测） | 后果 |
|---|---|---|
| ① 数字正则只认小数 | `TBPS_RE = r"([0-9]+\.[0-9]+)\s*TB/s"` 对 `4TB/s` 返回 `[]` | 写整数带宽即可绕过门禁 |
| ② 比值声明无语义 | naive 见「两倍/2倍」就判红 ⇒ **位宽是两倍**（真结论）和**带宽是两倍**（假结论）同时被误伤 | 要么误伤真话，要么放过往上吹 |
| ③ 数字各自白名单，缺跨项同源 | `4.000 TB/s + UI=125 ps` 两个数字各自"合法"，但 4.000 TB/s 隐含 7.8125 GT/s ⇒ UI 应为 **128 ps** | 假绿：文本内部自相矛盾却过门禁 |

此外还有一个必须保留的正向结论：**4096 DQ 的带宽是 HBM4 标准 2048 DQ 的 1.953125 倍，不是 2 倍**（位宽 2× × 速率 0.9765625×）。现有门禁不检查这个比值，容易被写成"带宽翻倍"。

## 2. 目标与范围

### 2.1 做什么（IN）

1. 在 `memif` 增 4 个纯 `math` 闭式：单位间隔 `ui_ps`、每通道带宽 `bw_per_ch_gbs`、全片读时间毫秒包装 `read_ms`、代际比值守恒 `ratio_chain`。
2. 在 `dclaim` 增 3 类文本检查：整数/小数通用数字正则、语境敏感的比值 claim、带宽↔UI 跨项同源回算。
3. 在 `build_mem1_material.py` 增列展示这些派生量，**所有数字来自 `memif`，不手抄**。
4. M1 门禁从 14 主判据扩到 22，探针同步 14→22，还原 2 不变（合计 30→46）。

### 2.2 不做什么（OUT）

- 不做 DRAM 器件/阵列、内存控制器、PHY、混合键合、3D 热-应力-良率模型。
- 不报吞吐/能效/容量达成，不写"复现/达到/验证"等对外宣称。
- 不碰 E38、时钟感知布局、加面积/加层（均已判死）。
- 不改主链九数、不新增锚、不新增模块、不改入口数、不改 CI core 成员（407 保持）。

## 3. 只读探针证据（写码之前跑完）

### 3.1 轮 1：正例与反例（闭式判别力）

| 项 | 结果 |
|---|---|
| `UI(7.8125 GT/s)` | **128 ps**；`UI(8.0)` = **125 ps**；`UI(3.125)` = 320 ps |
| 每通道带宽（双路） | `4.000 TB/s ÷ 64 = 62.5 GB/s` ≡ `64 DQ × 7.8125 GT/s ÷ 8 × 1000 = 62500 GB/s ÷ 1000` ✔ |
| 全片读时间 | `128 GB / 1.6 TB/s = 80 ms`；`144 GB / 4 TB/s = 36 ms` |
| 代际比值 | `4.000 / 2.048 = 1.953125` ≡ `(4096/2048)×(7.8125/8.0) = 1.953125` ✔ |
| 反例① 把带宽写成 2× | `abs(2.0 − 1.953125) > 1e-9` ⇒ 判红 ✔ |
| 反例② 通道数写 63 | `4000/63 = 63.492 GB/s ≠ 62.5` ⇒ 判红 ✔ |
| 反例③ 7.8125 GT/s 写 UI=125 ps | `abs(125 − 128) > 1e-9` ⇒ 判红 ✔ |
| 反例④ 950PR 按 4096 DQ 反解 3.125 GT/s | 出窗 ⇒ **NOT_APPLICABLE**（不是 FAIL、更不是 PASS）✔ |

**结论**：四条闭式均有判别力；三态口径在扩展下仍成立。

### 3.2 轮 2：文本门禁的洞与语境误伤

```
正则对照：
  4.000 TB/s  -> old=['4.000']  new=['4.000']
  4TB/s       -> old=[]         new=['4']        ← 旧门禁可绕过

naive「两倍」禁令：
  位宽是 HBM4 标准的两倍  -> naive=False  ← 误伤真结论
  带宽是 HBM4 标准的两倍  -> naive=False  ← 该判红却和上行同判
```

**结论**：必须换成「数字正则含整数」+「按语境判比值 claim」。修正后实测：

```
语境敏感比值：
  位宽是 HBM4 标准的两倍        -> NOT_APPLICABLE（不误伤）
  带宽是 HBM4 标准的两倍        -> FAIL（判红）
  带宽是 HBM4 标准的 1.953125 倍 -> NOT_APPLICABLE（合法值不误伤）
```

### 3.3 轮 3：跨项同源（防假绿）

```
4.000 TB/s；UI=128 ps  -> PASS（同源）
4.000 TB/s；UI=125 ps  -> FAIL（BW=4.0 ⇒ UI 候选 [64.0, 128.0]，正文 UI=125）
4.096 TB/s；UI=125 ps  -> PASS（4096×8 GT/s 是合法特例）
```

**结论**：UI 不能各自过白名单，必须由正文带宽隐含的速率反推；同时保留 4.096 合法特例（第三次证明"通式优于白名单"）。

### 3.4 探针总结

**三轮里两次推翻我自己的第一版判据**（整数绕过 / 语境误伤 / 跨项假绿），这正是立项正当性：不是"加几个数字"，而是补上当前门禁可被绕过的真实路径。

## 4. 预注册判据（G1 冻结：先定判据、后写代码）

| 编号 | 判据 | golden 来源 | 正例 / 反例 |
|---|---|---|---|
| **K1** | `ui_ps(R)=1000/R` 闭式 | UI 定义（1 bit 时长） | 7.8125→128 ps / 125 ps 判红 |
| **K2** | `BW/n_ch ≡ dq_per_ch×R/8×1000` 双路复算 | 带宽定义式 | 62.5 GB/s / 63.492 判红 |
| **K3** | `read_ms(cap,bw)=cap/bw` | 容量/带宽量纲桥 | 80 ms、36 ms / 90 ms 判红 |
| **K4** | `BW_H/BW_std ≡ (DQ_H/DQ_std)×(R_H/R_std)` | 定义式乘积 | 1.953125 / "2 倍带宽"判红 |
| **K5** | 带宽↔UI 跨项同源（不得各自白名单） | 两条独立闭式交叉 | 4.000+128 ps PASS / 4.000+125 ps FAIL |
| **K6** | 数字正则含整数形式，`4TB/s` 必须进回算 | 通式 `bw_is_derivable(4.0)` | `4TB/s` 由绕过变 PASS；`9TB/s` 判红 |
| **K7** | 比值 claim 语境敏感 | 位宽比 2 / 带宽比 1.953125 | 位宽两倍放行；带宽两倍判红；1.953125 倍放行 |
| **K8** | 三态保持：950PR 仍 `NOT_APPLICABLE` | MEM1 已冻结口径 | 3.125 GT/s 不得记 PASS |

> K1–K8 与 J1–J14 **并存、不替换**；任一 K 变红即整个 M1 门禁红。
> 新增 8 条突变探针 P15–P22，逐条把上述反例注入后必须变红；R1/R2 还原保持不变。

## 6. 对规划的自审计（做之前先挑自己的错）

| 审计问句 | 结论 |
|---|---|
| 有没有造第二套实现？ | 没有。所有派生量只从 `memif` 出，`dclaim` 只做文本判决；物料不手抄数字。 |
| 有没有真消费者？ | 有且只有一个：`scripts/build_mem1_material.py`，写盘前 `check_claim` fail-closed；M1 门禁机核该消费关系。 |
| golden 是否独立、是否凭空？ | 全部是定义式（1 bit=1/R、1 Byte=8 bit、容量/带宽），无 reference implementation；**没有使用任何未公开参数作 golden**。 |
| 判据是否可定位、可证伪？ | 每条 K 对应具名函数 + 具名探针；用 `make_check(record=...)`，不新增本地 `def check`。 |
| 会不会把边界当欠债补？ | 不会。本批只扩"公开参数自洽"诊断，46 条边界声明一条不动，17 条电子域边界不变。 |
| 会不会越成能力宣称？ | `claimable=False` / `in_blocking=False` 随每个返回值；对外物料强制白名单声明与禁语扫描；`NOT_APPLICABLE` 不记 PASS。 |
| 是否触碰已判死方向？ | 不碰 E38、时钟感知布局、加面积/加层、能效数字。 |

## 7. 否决条件（任一成立就不做）

1. 要求输出"达成 / 达到 / 性能 / 能效"结论，或把 `claimable` 改 True。
2. 要求把 `NOT_APPLICABLE` 压成 `PASS`（假绿比不做更坏）。
3. 要求以白名单硬编码替代通式回算（4.096 合法值已被误伤过）。
4. 要求把位宽 2× 写成带宽 2×，或删掉语境敏感检查。
5. 专项物料脚本消费者被废弃（无真下游 ⇒ 重演 M13/B6c 同根因）。

## 8. 诚实边界与对外口径

- 本批**只核对公开参数的内部自洽**，不验证论文结果、不验证 any 实测；议程草案参数来自媒体转述，非 IEEE 正式论文集全文。

- 无 foundry PDK、无流片实测；规则集为自建教科书尺度，**不作制造/性能宣称**。
- 对外物料只出 §5 投影表，文字仍限定「设计期闭式核对·非流片实测」；方法论与判据号不对外。
