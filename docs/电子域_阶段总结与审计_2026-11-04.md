## 0. 摘要（结论先行）

1. **这一阶段真正完成的是「入口层 + 一条能跑的干线 + 一套能判红的度量」，不是「可签核的数字链」。**
   形式层（LEF/DEF/Verilog/Liberty）字节级双射、干线 6 段守恒、对拍表结构，都已机核；
   但**没有一段产出可签核结果**（`claimable=False` 贯穿）。

2. **净增 0 锚**是这一阶段的正确结果，不是失败：解析器与干线不产物理量，硬凑锚只会伪造残差。

3. 🔴 **审计推翻了我上一版（v0.9.371）的一个结论**：我曾说「DRC 清零需要 **26.32× 行面积**」。
   它只在**旧链**（引脚塌缩到单元中心 + 无容量约束）下成立。同一份 c17 上，
   `dpnr`（B 系列 P&R 主链：真实引脚 + 通道容量律）对 **4 条跨行网**给出 **DRC = 0**。
   ⇒ **电子域的 DRC 缺口是「集成与端口建模」，不是「面积不够」。**

4. 🔴 但 `dpnr` 的 0 违规**不能**被当成「c17 已清零」：它**只布 4/11 条网**，
   7 条接端口的网**静默跳过**，且 `unrouted` 返回**空**（口径失真）。这是本轮最严重的代码问题。

5. **战略判断**：电子域的能力「零件」基本齐了（B1 单元几何 / B2 路由+容量律 / B3 干线 / B4 对拍），
   缺的是**把它们接成一条主链并让「没布通的网」大声报错**。下一步应做集成，而不是继续加锚或加模块。

### 2.2 三条战略风险（按严重度）

1. 🔴 **「零件齐、主链不通」**：`dpnr`（真实引脚 + 容量律 + DRC 0）与 `db3_trunk`（旧链、87 违规）
   并存，而对外卡片、对拍表、阶段总结全部基于**旧链**。读者会得出「电子域布不通、要 26× 面积」
   的错误结论。**这是当前最大的失真源。**
2. 🔴 **「未布 ≠ 报错」**：`dpnr` 只布 4/11 网且 `unrouted=[]`。若有人拿它的 DRC=0 去宣称
   「c17 已清零」，就是本项目最危险的形态（同族血案：把漏算 3.0103dB 当物理结论）。
3. 🟡 **「对拍没有参考」**：`dxcheck` 的 `reference` 全 `unavailable`，`evidence_level` 只到
   自检。**没有外部参考，就没有「对标」**；而环境（WSL 黑名单 / Docker / 生产机 3GB）已实测封死。

### 2.3 净增 0 锚该怎么读

- 这一阶段 8 个新模块**没有一个产出物理量**（解析器/干线/对拍/度量），所以 0 锚是**诚实结果**。
- 但要承认另一面：**电子域到现在只有 5 个锚**（B526 MNA / B527 MOSFET 平方律 / B528 寄生 RC /
  B529 互连 RC / B530 器件 PDE），占全账本 546 的 **0.9%**。这不是「锚少了」，是
  **电子域的证据密度远低于光子域**（光子域有实测语料，电子域没有 PDK/硅数据）。
- 结论：**在拿到外部参考或 PDK 之前，电子域不应以「加锚」为 KPI**，应以「主链可签核性」为 KPI。

### 2.4 全量 CI 抓到的两处红（战略含义）

| 红 | 根因 | 含义 |
|---|---|---|
| `redline_scope` B 披露 | 我在 v0.9.366 写「自主红线」未带「分层」 | 披露类判据是**活的**，改文案就会红 |

## 3. 代码审计（10 条，按严重度分级）

### P0-1 `dpnr` 端口网静默跳过，`unrouted` 返回空 ⇒ DRC 0 是「少布」换来的

**证据**（当日实跑）：

```
netlist 网数: 11
routed: ['n11','n16','n19','n3']   unrouted: []
n_in_row: 0   in_row_m3: 0   in_row_m3_tracks: 0
shapes: 74     DRC: 0
pins 里每条网都有记录：n1(1) n10(1) n2(1) n22(1) n23(1) n6(1) n7(1) n3(2) n11(3) n16(3) n19(2)
```

`dpnr` 自己的披露写「**端口网不布，如实计入未布**」，但 `unrouted` 是**空的** ——
7 条单端点网（另一端是 primary I/O）**既没布、也没被报为未布**。

**影响**：任何「dpnr → DRC 0」的对外陈述都会失真；且这与「0 同层短路」同源的乐观偏差。

**修法**（P0）：`route_block` 必须返回 `skipped_port_nets`（或把单端点网计入 `unrouted`），
并新增判据：`len(routed) + len(skipped) == 网表里端点 ≥1 的网数`。

### P0-2 三套路由器并存，口径分裂

| 路由器 | 违规（c17） | 布网 | 消费者 |
|---|---|---|---|
| `ddetail.detail_route` | **87** | 11/11 | 干线 `db3_trunk`、E36 门禁 |
| `ddetail.track_route` | **728** | 11/11 | 仅 manifest 登记 + `track_self_check` + 注释比较（**无生产消费者**） |
| `dcroute.route`（B2） | **0** | 4/4（自有 demo） | `dpnr` |
| `dpnr.route_block` | **0** | 4/11 | E45/E47–E55 门禁 |

四条路由路径、四套口径。`track_route` 实测比 `detail_route` **差 8 倍**，却仍作为
「E37 成果」挂在 manifest 与文档里。这正是本仓反复踩的「重复实现必然漂移」。

**修法**（P0）：定一条**唯一主链**（建议 `dpnr`），其余两条降级为「对照基线」并在
`capability` 描述里显式标注「非主链、仅对照」，禁止被干线/卡片引用。

### P0-3 LVS 183 是**短路**，但全仓只写「183 问题」

**证据**：`Counter({'short_via': 105, 'short': 78})`，网对如 `('n1','n3')`、`('n1','n11')`。

对外卡片、CHANGELOG、README、`s4_scope` 一律写「LVS 183 问题」，**没有一处说是短路**。
而 DRC 只报 `min_spacing`，两条口径指向同一根因（引脚塌缩 ⇒ 不同网从同一点出发）。

**影响**：读者会认为「只是间距紧」，实际是**电气连通性错误**。

**修法**（P0）：所有叙述改为「LVS 78 short + 105 short_via」，并在卡片 `drc_lvs` 段加
`lvs_by_rule`（已有 `drc_by_rule`，LVS 缺对应结构）。

### P0-4 `ddetail` 披露仍残留「0 同层短路」字样，与实测矛盾

`lda_l2/ecore/ddetail.py:37`：「0 同层短路不代表布通 —— …」。
实测同层短路 **78 处**（LVS `short`）。这句话在今天的事实下是**错的**，且无门禁核它。

**修法**（P0）：改为「实测 78 处同层 short（LVS）+ 87 处 min_spacing（DRC）」，
并把「披露与 LVS 实测一致」做成判据（关键词级）。

### P1-5 `route` 段 `nets=10` vs `routed_nets=11` 字段名歧义

`db3_trunk` 的 `"nets": r.n_nets`（只数 **≥2 端点**的网）与 `"routed_nets": len(net_pins)`（11）
并列输出。读者看到「网 10 / 布通 11」必然误判。

**修法**（P1）：改名 `nets_with_segments` / `nets_touched`，并加判据
`nets_with_segments ≤ nets_touched`（现在这个不等式在纸面上是反的）。

### P1-6 `dpnr` 与 `ddrc_lvs.run_lvs` 接口不兼容

`rt['pins']` 是 `(inst, pin, x, y)` 四元组，而 `run_lvs` 期望 `(x, y)`：
`ValueError: too many values to unpack (expected 2, got 4)`。
⇒ **B 系列主链跑不了既有 LVS**，等于「DRC 有人验、LVS 没人验」。

**修法**（P1）：加适配器 `dpnr.pins_for_lvs(rt)`，并用**同一份** `run_lvs` 验（不新写 LVS）。

### P1-7 `dsta` 未接干线，且要求拓扑序

干线 `timing_included=False`；`dsta.sta` 要求门按**拓扑序**，而 c17 文件序非拓扑 ⇒ 直接报错。
另：`dsta` 无寄生（`wire_load_ff` 未由 `dextract` 注入），即使接上也是零线延时。

**修法**（P1）：加 `dsynth` 拓扑排序（或 `dsta` 内部排序），并把 `dextract` 的分布式 RC 注入
`wire_load_ff`，才谈得上「时序段接入」。

### P1-8 电子域 69 道门禁里，**没有一道**核「网覆盖是否完整」

`s6` 核「route 覆盖每条网」——但它核的是 `detail_route`（11/11）；
`dpnr`（4/11）只被 E45/E47–E55 核其**局部结论**（容量律、列分配），无人核全网民覆盖。

**修法**（P1）：新增判据「布出的网 ∪ 明确跳过的网 == 网表网数」，对**任何**路由器生效。

### P2-9 `run_drc` 与 `fast_drc` 等价性只在 c17 验过

当日：`run_drc=87, fast_drc=87, 等价=True`。但等价性判据只在固定 c17 上；
随机/极端几何（重叠、贴边、零面积）未覆盖。

**修法**（P2）：加随机几何对拍（≥200 例，含退化形态），并要求**双向**一致。

### P2-10 两张电子域卡口径不同源

`/api/ecore_demo`（`ecore_case.py`）的数字大量是**手填常量**（我本轮手改过 span 计数 79/77/67），
靠 `B6c` 门禁与真源对拍兜底；`/api/digital_demo` 则是**每次真算**（缓存）。
两张卡并排对外，读者无法分辨哪张是「算的」哪张是「写的」。

**修法**（P2）：两张卡都加 `source: computed|declared` 字段，声明类必须给「真源 + 门禁名」。

## 4.5 三种次序是什么关系（**先读这一节，否则会把它读成三套互相冲突的顺序**）

本文有**三张清单**，它们是**同一批工作的三种视角**，不是三种做法：

| 清单 | 回答的问题 | 用途 | 读法 |
|---|---|---|---|
| **P0 / P1 / P2**（§4） | 哪些事**不能带着出门** | **发布门禁**（能不能发版） | 逐条勾；P0 未清零 ⇒ 不发布 |
| **M1 / M2 / M3**（§5） | 做到什么程度**才算这个阶段结束** | **验收口径**（判"做完了"） | 每个里程碑一组出口判据 |
| **第 0–6 步**（§6） | **先动哪个文件、按什么顺序动** | **执行顺序**（唯一按它干活） | 严格顺序，前一步不绿不开始后一步 |

**一句话总结：按「第 0–6 步」动手 → 用「M1/M2/M3」验收 → 用「P0/P1/P2」决定能不能发布。**

映射关系（三张表怎么对齐）：

| 执行步骤（§6） | 覆盖的 P 项 | 归属里程碑 | 完成标志（可机核） |
|---|---|---|---|
| 第 0 步 口径清理 | P0-3 / P0-4 / 部分 P1-5 | M1 | LVS 报 `short/short_via`；无「0 同层短路」；字段不等式成立 |
| 第 1 步 `dpnr` 端口记账 + 网覆盖判据 | **P0-1** / P1-8 | M1 | `routed ∪ skipped == 全网`，且该判据能判红 |
| 第 2 步 LVS 适配器 | P1-6 | M1 | `run_lvs` 对 dpnr 输出不抛异常且给出分类 |
| 第 3 步 主链切换（双报一版） | **P0-2** / P1-5 | M1 | 干线 `chain=dpnr`；`detail_route` 只作对照；卡片与门禁同源 |

🔴 **两处排序更正**（本文初版写错，以本节为准）：

1. **LVS 适配器必须排在主链切换之前**（初版把它排在切换之后）。理由：切换那一刻若 LVS 还接不上，
   就等于**用一个 0 DRC 但无 LVS 的主链，替换掉一个有 183 处短路记录的主链** —— 覆盖度反而下降，
   且会丢掉"短路"这条最关键的证据。**先建 LVS，再切换。**
2. **口径清理提到最前（第 0 步）**（初版排在第 4 步）。理由：第 2/3 步要重写 `route` 段的字段名
   与卡片字段，**先改口径再改结构，避免同一处改两遍**；且它最便宜（0.3 版）。

## 5. 下一步规划（三个里程碑，出口判据写死）

```
M1「主链收敛」  →  M2「可签核性」  →  M3「对标」
(2–3 版)           (3–4 版)          (环境解锁后)
```

### M1 主链收敛（先做，因为它决定后面所有数字的含义）

- 出口判据：
  1. `db3_trunk` 只走一条主链（`dpnr`），旧 `detail_route` 降级为「基线对照」且**不被对外引用**；
  2. **网覆盖完备**：`routed ∪ skipped == 全部网`，且 `skipped` 在卡片上可见；
  3. DRC/LVS 用同一套 checker，LVS 必须给出 `short/short_via` 分类；
  4. 对 c17：DRC=0 **且** LVS 干净（或如实报出 short 并说明根因）。

### M2 可签核性

- 出口判据：
  1. 时序段接入（拓扑序 + 寄生），`timing_included=True`，`hold_checked` 如实为 False；
  2. `claimable` 从常量变为**条件量**：DRC==0 ∧ LVS==0 ∧ 时序已接入 ⇒ 才可为 True；
  3. 至少一个「claimable=True」的用例，且**反向探针**（任一条件不满足 ⇒ 必须 False）。

### M3 对标（受环境阻塞）

- 出口判据：`dxcheck.reference.status == measured`，`evidence_level == EXTERNAL_CROSSCHECK`，
  且差异表给出「超界 + 归因」；在此之前**不得**出现「与 OpenROAD 一致」字样。

### 第 0 步：口径清理（0.3 版 · 最便宜，先做）

- 改动：
  - 删 `ddetail.py` 披露里的「0 同层短路」，改为「实测 78 处同层 `short` + 87 处 `min_spacing`」；
  - 卡片 `drc_lvs` 段加 `lvs_by_rule`（现在只有 `drc_by_rule`）；
  - 全仓「LVS 183 问题」→「LVS 78 `short` + 105 `short_via`」。
- 判据：`Σ lvs_by_rule == lvs_problems`；披露含 `short` 且**不含**「0 同层短路」。
- 风险：改动触及 `s4_scope` / 卡片 / 披露三处，注意 `redline_scope`（含"红线"必须含"分层"）与
  `count_consistency` 这类**文字敏感门禁**；改完先跑 `redline_scope` + `ecore_case`。

### 第 1 步：`dpnr` 端口网显式记账 + 网覆盖完备判据（0.5 版）

- 改动：
  - `dpnr.route_block` 返回 `skipped_port_nets`（单端点网入列），`unrouted` 语义不变；
  - 新增 `net_coverage(rt, nl)` → `{routed, skipped, total, complete}`；
  - 卡片 `capacity`/`routing` 段显示 `routed / skipped`。
- 判据：`len(routed) + len(skipped) == 网表网数`；**反向探针**：把一条 skipped 网塞进 `routed` ⇒ 必红。
- 风险：`unrouted` 语义变化会动到 E45/E47–E55 既有断言 ⇒ **先跑这 10 道**再改。

### 第 2 步：LVS 适配器（0.5 版 · **必须在切换前**）

- 改动：`dpnr.pins_for_lvs(rt)`（4 元组 → `(x, y)`）；复用 `ddrc_lvs.run_lvs`，**不新写 LVS**。
- 判据：对 dpnr 输出跑 `run_lvs` 不抛异常；`short` 分类与 DRC 归因一致（同根因交叉验证）。
- 风险：适配器写错会「造出干净的 LVS」⇒ 必配**故意短路**的反向探针（两网重叠 ⇒ 必须报 short）。

### 第 3 步：主链切换（1 版 · 双报一版过渡）

- 改动：
  - `db3_trunk` 改调 `dpnr`（`place_real` + `route_block` + `all_routing` + `pins_for_lvs`）；
  - `detail_route` 保留为 `baseline_compare`，**同一版内双报**（主链数字 + 旧链数字并排），
    让"口径变化"可见而不是静默替换；
  - `capability_manifest` 标「主链 / 对照」；`route` 段字段改名 `nets_with_segments` / `nets_touched`。
- 判据：干线报告含 `chain="dpnr"` 与 `baseline.chain="detail_route"`；`db3_trunk` 不 import
  `track_route`；卡片 == 门禁独立复算；`nets_with_segments ≤ nets_touched`。
- 风险：
  - **面积口径会变**：`CELL_GAP=0.46` 换 pin 可达性 ⇒ die 3.40 → **33.70 µm²（×9.91）**。
    卡片与文档必须写明「这是 pin 可达性的面积代价」，**不能说成工艺升级**；
  - 旧链数字（87 / 78+105）在双报期内仍要保留，防止"换了主链，旧证据消失"。

### 第 4 步：时序接入（1–2 版）

- 改动：`dsynth` 拓扑排序（或 `dsta` 内部排序）；`dextract` 分布式 RC → `wire_load_ff`；`dsta` 接入。
- 判据：c17 `sta` 可跑；`timing_included=True`；`hold_checked=False` **明示**；闭式回归逐位不变。
- 风险：`sta` 改动会碰 E34/E35 金标 ⇒ 先跑这两道（`lib=None` 路径必须逐位不变）。

### 第 5 步：`claimable` 条件化（0.5 版 · M2 收口）

- 改动：`claimable` 从常量改为条件量（`DRC==0 ∧ LVS==0 ∧ timing_included`）；
  三个条件各自给反向探针（缺一 ⇒ 必须 False）。
- 判据：至少一个 `claimable=True` 用例 + 三条"缺一必 False"的探针全红。
- 风险：**这是最容易被"顺手放宽"的地方** ⇒ 判据必须写成"缺一必 False"，而不是"全满足才 True"
  （后者用默认值就能糊过去）。

### 第 6 步：全量 + 发布

- 判据：全量 **400 道绿**、凭证 `green`、**`n_reused=0`**（干净全量，不用续跑兜）；
  随后 gitee → github → 三端 MATCH → 生产部署 → health → `check_ledger`。
- 风险：`run_coupler_band_smoke` 是已知 flaky（负载下 0xC0000005）⇒ 若再崩，先单独复验 2 次
  再归因，**不许改判据**。

## 7. 诚实边界（必须与结论同读）

1. **本文的「DRC=0（dpnr）」只覆盖 4/11 条网**（7 条端口网未建模），不可外推为「c17 已清零」。
2. **旧链 87 违规 / 78+105 短路**是引脚塌缩的**建模后果**，不是「路由器算法差」。
3. **26.32× 面积**只在旧链下成立；主链的代价是 `CELL_GAP` 换 pin 可达性（die 3.40 → 33.70 µm²，**×9.91**），
   两者**不是同一个量**，不得混用。
4. 电子域锚仅 **5/546（0.9%）**；没有 PDK/硅数据前，「加锚」不是有效 KPI。
5. 对拍参考仍 `unavailable`；`evidence_level` 最高只到 `SELF_CONSISTENCY_ONLY`。
6. 本文档不产生任何新的物理结论，只做事实归档与计划。
