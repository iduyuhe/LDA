# N1 电子域实证锚 · 语料可得性勘查（P1）

> **性质**：**闸门勘查，不是开工**。本文只回答一个问题——「电子域的公开实测语料，到底拿不拿得到数字表级别的？」
> 拿得到 ⇒ N1 开工有依据；拿不到 ⇒ **如实判死**，不许把曲线图读成数字。
> **基准**：HEAD `c126a9b`（v0.9.301 + 对账文档）· 勘查日期 2026-10-25。
> **纪律**：每条结论标注**本轮用什么方式核验的**（直连下载解包 / 读落地页 / 读 API 清单）。
> 只读过标题就下结论的，一律标「未核验」，不进结论。

---

## 0. 一页结论

| 问题 | 答案 |
|---|---|
| 电子域公开实测语料存在吗？ | **存在，而且不止一类**。至少 4 类数字表级语料公开可下（含 778 条实测 ADC 记录） |
| 那 N1 判死吗？ | **不判死**。v3 审计把 N1 的理由（"唯一不需要流片/NDA 的锚空间"）**成立** |
| 那为什么电子域至今 0 条？ | 不是"语料不存在"，是**没去找**（v3 审计原文即写"勘查也没做"） |
| 那可以马上开工吗？ | **还不能**。本轮抓到 **3 种「伪可得」**，以及 1 个**结构性矛盾**（见 §3） |
| N1 该怎么改 | **改指标清单**：从「MOSFET I–V 曲线」改为「带数字表的提取量」，并按「候选模型输入参数是否齐备」排序（见 §4） |

**一句话**：语料这一关**过了**；卡住 N1 的不是语料，是**候选模型的输入参数**。

## 1. 判定口径（四类 + 一类陷阱）

只分「有 / 没有」会漏掉真正危险的情形，故用五类：

| 代码 | 含义 | 能否作 golden |
|---|---|---|
| **T** 数字表 | 可下载的数值表（csv/xlsx/json），逐行可复算 | ✅ 可（还须验候选物理成立） |
| **C** 仅曲线 | 只有图（PDF/图片），数字须从图上读 | ❌ **不可**——读图 = 二次数字化，误差不可溯源 |
| **N** 需 NDA/商业授权 | 商业 PDK、代工厂实测 I–V | ❌ 当前不可（且与本仓开源定位冲突） |
| **X** 不存在 | 检索未发现任何公开落地页 | ❌ |
| **🔴 S** 伪可得（仿真） | **长得最像数据表，但内容是仿真/TCAD/BSIM 输出** | ❌❌ **红线：仿真值永不作 golden** |

**为什么单列 S**：这是本轮最危险的发现——「MOSFET + I-V + 3nm~350nm + 44 种器件 + CC-BY-4.0 + DOI」的完美数据集，
逐字读摘要才发现每一条都是 **BSIM 仿真输出**。若按 v3 审计「MOSFET I–V」直接取语料，一上手就踩红线。

## 3. 关键发现（三条）

### 3.1 「电子实证锚 = 0」的根因是「没去找」，不是「找不到」

v3 审计自己在 N1 风险栏写「先做半天语料可得性勘查」——**这半天从来没做**。
本轮半天做下来，找到 **778 条实测 ADC 记录 + 249 份 MOSIS 电测报告 + 2 个实测 MVM 数据集**，
全部公开、可引、带 DOI/CSTR。所以「电子域没有公开实测语料」这个默认假设是**错的**。

### 3.2 但「语料可得」确实 ≠ 「锚可做」——本轮抓到 3 种伪可得

| 伪可得形态 | 实例 | 若不上机核验会怎样 |
|---|---|---|
| **仿真冒充实测** | MESD（#8）：摘要里 "I-V and C-V characteristics **data**"，真正定语是 "simulated" | 直接把 BSIM 输出当 golden ⇒ 违反「仿真值永不作 golden」红线 |
| **仓库里只有论文** | Zenodo 18133051（#7）：open access + CC-BY-4.0 + 标题就是 "Statistical Analysis of MOSFET **Extracted Parameters**"，API 一列文件——**只有 1 个 PDF** | 以为拿到了"参数统计数据集"，实际只有一张表在 PDF 里 |
| **双锁** | Zenodo 15165837（#9）：仿真 + embargo 到 2027 | 写进规划却永远取不到 |

**方法论沉淀**：「数据仓库」这个标签不等于有数据；**必须列文件清单**（本轮 #7 就是靠 Zenodo API 一眼看穿的）。

### 3.3 结构性矛盾：干净实测语料都缺「喂给候选模型的参数」

这是本轮最重要的发现，也是 N1 至今 0 条的真原因：

| 语料 | 干净程度 | 缺什么（喂候选模型必需的） |
|---|---|---|
| Hacker Fab 原始 I–V（#5） | 最干净（直接测量） | **tox / Na / μ₀ 全无公开值**（自制工艺，论文未给完整 split） |
| NBSDC PMOSFET（#6） | 干净（原始测试） | 器件是 **Ge 沟道**，`ecore` 模型无 Ge 参数（μ₀/v_sat/Dit） |
| ADC survey（#1） | 干净（实测） | **输入摆幅口径未定义**（见 §3.4） |
| MOSIS 参数集（#2） | 参数齐全 | 但 VTH0/TOX/U0 是**从实测 I–V 拟合出来的导出量**，不是直接观测量 |
| MESD（#8） | **参数全齐** | ❌ 全仿真 ⇒ 不可用 |

⇒ **参数齐的必是仿真，实测的必缺参数。** 这不是运气差，是产业事实：完整工艺 split 属代工厂机密，
公开实测必然只公开「结果」不公开「配方」。

**这条矛盾已经预示过失败**：v0.9.x 那次电子实证锚尝试「候选与实测 V_th(L) 趋势符号相反、幅度几乎相等」——
正是因为没有正确的 tox/Na，模型被反推到了错误的参数区。**参数缺失不会让残差变大，只会让残差"看起来很小但符号错"**，比残差大更危险。

### 3.4 顺手做的一次可行性探针（ADC kT/C 上限）——结论是「现在不能做」

既然 #1 有 778 条实测，直接试了一下最自然的物理锚：**实测 SNDR 不可能超过 kT/C 热噪声上限**。

- 三列（`Csamp` + `VSUP1` + `SNDR_lf`）同时有值的只有 **40 / 778 条**（其余列稀疏）；
- 按「单端全摆幅正弦，幅度 = VDD/2」口径算上限：**5 / 40 条越界**；
- 查这 5 条：**4 条是过采样型（OS）**，须做 `+10·log10(OSR)` 折算（OSR = 16 / 32 / 16384）。折算后仍有 3 条在 2.6–3.7 dB 越界；
- 剩下 1 条是 Nyquist 型、OSR=1，越界 3.2 dB，只能由「差分输入 ⇒ 摆幅翻倍 ⇒ +6 dB」解释。

⇒ **幅度口径的 0–6 dB 不确定度，大于观测到的 ≤3.7 dB 偏差。** 也就是说：现在既不能说语料有问题，也不能说模型有问题——
**是口径没定**。而口径（输入摆幅定义）恰恰**不在语料里**。

**因此**：ADC 这一条**可以做「披露级一致性检查」，不能做「判决锚」**。要变成锚，必须先有独立来源定标摆幅口径，
或改用对摆幅不敏感的量（例如同一记录内 `SNDR_hf` 相对 `SNDR_lf` 的衰落，只依赖抖动与带宽，与摆幅无关——这是下一步的候选方向，**本轮未验**）。

## 4. 对 N1 的裁决建议

### 4.1 裁决：**不判死，但改清单**

v3 审计原来的五类指标 `MOSFET I–V / SS / μ_eff / ADC ENOB / MVM 精度` 是**平铺**的，
勘查后必须按「候选模型的输入参数能不能凑齐」重排，而不是按「指标重不重要」排。

| 优先级 | 指标 | 语料 | 为什么排这里 |
|---|---|---|---|
| **P-A** | MOSIS **Vth/Kp/U0 统计**（#2） | T，249 份 | 唯一「参数齐全 + 公开实测」的组合；但 golden 是拟合导出量 ⇒ 须照 E1/D-64 的先例**先验候选物理成立**，且披露「拟合 vs 闭式」的性质 |
| **P-B** | ADC **`SNDR_hf` 相对 `SNDR_lf` 的衰落**（#1，**新提，未验**） | T，778 条 | 只依赖抖动与带宽，**与摆幅口径无关** ⇒ 绕开 §3.4 的死结；须先验 jitter/带宽参数是否可从 `fs`/`fcenter` 推出 |
| **P-C** | Hacker Fab 长沟道 NMOS（#5） | T?（落地页待确认） | 5–30 µm 正好在教科书模型适用域，趋势验证最干净；**但必须先拿到 tox/Na**，否则重演趋势反号 |
| **P-D** | MVM 精度（#3 #4） | T | 语料最干净，但「候选模型 ↔ 实测指标」的映射尚未定义（LDA 侧有 `mismatch`/`mvm_datapath`，能否算 MNIST 准确率未知） |
| **P-X** | SS / μ_eff 单点（#6 #10） | 混杂/仅曲线 | Ge 沟道无参数、4H-SiC 只有图 ⇒ 暂不投入 |

### 4.2 下一步（每步都可验收，且**任何一步失败都要如实写"判死"**）

1. **P-B 前置验证**（半天）：在 778 条上算 `SNDR_lf − SNDR_hf` vs `fin_hf/fsnyq`，看是否落在抖动模型 `−20log10(2πfσ)` 的同一族上。
   落在同一族 ⇒ 该量可作锚（且绕开摆幅）；不落 ⇒ 判死，转 P-A。
2. **P-A 前置验证**（1 版）：从 MOSIS 报告取 3–5 个工艺节点的 `VTH0/TOX/U0`，用 `ecore.device_pde` 闭式 Vth 复算，
   看**绝对量级**是否在 10% 内（不是只看趋势——趋势符号相同也可能是参数反推的巧合）。
3. 只有 1 或 2 通过，才进「锚注册 + 门禁」阶段（`EM1…` 编号、`run_empirical_anchor_smoke` 新组判据、`EMPIRICAL_ANCHOR_MIN` 上调）。

### 4.3 三条不许碰的线

1. **仿真值永不作 golden**——MESD/TCAD 一律排除，哪怕参数再全。
2. **曲线图读数不作 golden**——4H-SiC 的 SS 在 Fig. 11 里，不许读。
3. **不许为了凑数先注册锚再找语料**——本轮 10 个候选里只有 5 个是真 T 类，写"8–12 条"之前得先有 8–12 个 T。

## 5. 诚实边界（本文自身）

- **#5 Hacker Fab 未定位到数据下载 URL**：文档把「100 个 .xls / 94 条有效 / 字段清单」写得很细，`github.com/hacker-fab` 下 20 个仓库我都列过，`storage` 是 CAD 不是数据。**我不能说"可以下载"**，只能说"数据存在且公开描述，落地页待确认"。
- **#2 MOSIS 我读的是落地页与报告清单，没有逐份下载 HTML 报告解析**。所以"249 份报告含参数"这个数来自仓库自述，**不是我数出来的**。
- **#4 #6 需注册**：我没有账号，未验证注册后能否真的下载 xlsx。
- **§3.4 的 40/778 与 5/40 是我自己算的**（可复现，命令见 §6），但"幅度口径"这一解释是**假设**，无独立来源确认。
- 本文**不主张** N1 一定能产出 8–12 条锚。门槛在 §4.2 的第 1、2 步，任一步不过就应判死并转投超导侧（那条路语料已在库）。
