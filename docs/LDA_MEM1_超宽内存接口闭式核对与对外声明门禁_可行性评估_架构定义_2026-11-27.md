# LDA_MEM1 · 超宽并行内存接口「闭式核对 + 对外声明门禁」· 可行性评估 / 架构定义

> **状态**：立项论证（**未实施**）· **日期**：2026-11-27 · **性质**：内部文档（方法论不进对外物料）
> **一句话**：把「对外物料只写 *设计期闭式核对·非流片实测*」从**口号**变成**机器可证伪的门禁**。
> **范围纪律**：本方案**不**以复现任何厂商方案为目标；它只回答"我们对外说的那句话，机器能不能证明它是真的"。

---

## 0. 结论（先行）

| 判定 | 内容 |
|---|---|
| **可行性** | **有条件可行**。技术上无阻塞（纯 stdlib + 闭式），但**有三个否决条件**（§10），任一成立即停 |
| **建议形态** | 缩到最小：**2 个模块 + 14 条判据 + 3 个真消费者**，不碰 PDK、不碰 DRAM、不碰 3D 热 |
| **最大价值** | 不是算 HBM，而是**把"诚实边界"从散文变成门禁**——现有 `honest_boundary_ok()` 只扫 3 个 token、且只扫内部列表，**有负向检查、无正向声明检查、无数字回算**，这是真实缺口 |
| **最大风险** | 被读成「LDA 能做 HBM」。缓解靠**命名 + 禁语 + 三态输出 + `claimable=False`** 四道锁，缺一不可 |
| **工作量** | 2 模块（约 450 行）+ 1 门禁（约 200 行）+ 3 处消费者接线 + 六处登记 + 1 次全量 |

## 1. 立项缘起：约束本身就是一个可机核的需求

杜先生给的约束是：**对外物料只写「设计期闭式核对·非流片实测」**。

这句话要成立，必须同时满足三件事，缺一即空话：

1. **有东西可核对**——"闭式核对"不能是形容词，必须有一张能被复算的表（否则"核对"二字无所指）。
2. **核对结果不能被写成结论**——核对出"4.000 TB/s 自洽"≠"我们能设计 4TB/s 内存"。两者之间必须有一道机器拦得住的门。
3. **文案不能漂移**——只要允许人自由写，三个月后必然出现"复现了/达到了/对标了"。必须机器扫。

⇒ 这不是一个"写文档"的任务，是一个**门禁工程**任务。这也决定了它的判据形态：**正例必须过、反例必须红**，而不是"看起来对"。

## 2. 事实基线（已核实，含口径澄清）

2026-11-23 IEEE 公布 ISSCC 2027 议程草案（会议 2027-02-14~18，旧金山），华为 4 篇：

| # | 方向 | 公开要点 |
|---|---|---|
| 1 | 旗舰移动 SoC | LogicFolding：混合键合 + 全芯片模块内分区 |
| 2 | AI 处理器供电 | 33A 三维堆叠集成稳压器，宣称系统降 59 W |
| 3 | 高速有线通信 | 71.3 fs 分数 N 环形 PLL，面向 212.5 Gb/s |
| 4 | 定制 HBM | **64 通道 / 4096 DQ / 5 层 W2W 混合键合 / 集成内存控制器** |

**三处口径必须钉死**（写错则后面全错）：

| 项 | 真实口径 | 常见误读 |
|---|---|---|
| 4096 bit | 4096 个 **DQ 引脚**（总位宽），64 ch × 64 DQ/ch | 读成"4096 个通道" |
| 议程草案 | 参数来自论文标题 + 媒体转述，**非 IEEE 正式论文集** | 当成实测指标 |
| 昇腾 950 | 同一 die 配两种内存：950PR=HiBL 1.0（128 GB/1.6 TB/s，公开资料称接近 LPDDR 的低成本路线）、950DT=HiZQ 2.0（144 GB/4 TB/s） | 把两者都说成"那颗 4096 DQ HBM" |

> 结论：**950PR 的 1.6 TB/s 若按 4096 DQ 反解只有 3.125 GT/s，低于 HBM4 速率窗口** ⇒ 这本身就是"它不是那颗 4096 DQ 方案"的**机器证据**，而不是"参数出错"。这条差异必须在产品里被显式输出为 `NOT_APPLICABLE`，不能被抹平成 PASS 或 FAIL（§5.3）。

## 3. 能力盘点：能做 / 不能做（逐项根因）

| 华为论文方向 | 需要的能力 | LDA 现状（已查证） | 判定 |
|---|---|---|---|
| 定制 HBM | DRAM 器件、Cu-Cu 混合键合、4096 位并行 I/O、控制器、3D 热/应力/良率 | 仅 `schip_packaging.py` 的**单根同轴 TSV + 两根平行凸点**闭式（超导低温封装层，明写"未含阵列耦合/应力/集体效应"） | ❌ |
| LogicFolding SoC | 大规模数字 SoC 分区 + 3D P&R | 数字主链证据面仅 **c17（6 门）**；`max_cells=32`；规模诚实边界锁 **L2=160 门**；E38 已判死（重排必崩） | ❌ |
| 33A 3D 供电 | 大电流 PDN、封装级供电、热-电迭代 | 有 IR drop 诊断（c17 压降 8.6 µV）+ 一维稳态热链（不含 3D 耦合、不回灌温度） | ❌ |
| 212.5 Gb/s PLL | 高频 RF、相噪、传输线 SI | MNA 仅 DC/瞬态/AC 小信号；无相噪模型；封装闭式频率无关 | ❌ |

**能做的那一层**（且已经跑通，见 §4）：**公开参数之间的守恒与量级自洽**——这是算术层面的核对，不是设计能力。

> 🔴 层级错位是根因，不是"某个模块没写"：LDA 是**教科书尺度设计期签核工具**（自建规则、非 foundry PDK、无硅、不报 TOPS/能效）；华为披露的是**工艺 + 封装 + 量产指标**。二者不在同一坐标系。

## 4. 只读测算（立项前已做，三轮迭代，含两次判据自我否决）

### 4.1 第一轮：正向 + 破坏注入

```
华为ISSCC_4096DQ   J1=True  J2=True  J4=True
HBM4标准_2048DQ    J1=True  J2=True  J4=True
950PR_HiBL         J1=True  J2=True  J4=False   ← 关键
① 4096DQ 误读成 4096 通道   J1=False ✓
② 4TB/s 用 2048bit 复算     J2=False ✓
③ 950PR 当 4096DQ 同款      J4=False ✓
④ HBM4 标准写成 4.096       J3=False ✓
```

**首个发现**：J4 对 950PR 判红，不是数据错，是**口径不适用**。⇒ 判据必须**三态**，二值化会把"该说的不同"压成"我们算错了"。

### 4.2 第二轮：文本门禁

```
BAD-1 吹牛       J5=False 命中=['复现','流片实测'] ✓
GOOD-1 合规      J5=False 命中=['流片实测']        ✗ 误伤
```

**第二个发现**：标准声明 `设计期闭式核对·非流片实测` **自身含禁用词**。⇒ 必须先**剥离白名单短语**再扫，否则门禁把唯一正确的文案判红。

### 4.3 第三轮：数字回算

```
BAD-2 数字漂移(4.096)  J6=False 抓出=['4.096']
```

**第三个发现**：`4.096` 其实是 `4096 × 8 GT/s ÷ 8` 的**合法值**，白名单式核对会误伤。⇒ 回算必须用**通式**（DQ∈{2048,4096} × R∈窗口），不能列白名单。这正是"通式必须退化为特例"的判据原则。

### 4.4 结论

三轮里**两轮把我的判据自己判红了**。这证明：① 探针不是摆设；② 这个项目的难点不在算术，在**判据边界**（三态、否定语境、通式回算）。这正是它值得立项、也值得按 LDA 的老规矩做预注册的原因。

## 5. 架构定义

### 5.1 两个模块（职责严格分离）

| 模块 | 职责 | 依赖 | 能力面 |
|---|---|---|---|
| `lda_l2/ecore/memif.py` | 闭式核对：结构守恒、带宽守恒、标准退化、反解窗口、容量-带宽、堆叠高度（量级） | 纯 `math`（**不 import 任何求解器/产品链**） | 1 条 |
| `lda_l2/ecore/dclaim.py` | 对外声明门禁：白名单声明、禁语、数字通式回算、物料文件扫描 | 纯 `re` + stdlib | 1 条 |

**刻意不加 `^ANCHORABLE =`**：避免自动进 `capability_modules()` 而触发第 8 处 `MUST_BE_REACHABLE`，也守住"净增 0 锚"。

### 5.2 判据清单（14 条 / 14 突变探针 · 预注册）

| 号 | 判据 | golden（来源） | 证伪方式（突变） | 态 |
|---|---|---|---|---|
| J1 | `DQ_total == N_ch × DQ_per_ch` | 结构恒等式 | 把 4096 改 4096 通道 | 三态 |
| J2 | `BW_TBps == DQ × R_GTps / 8000` | 位-字节量纲 | 用 2048 算 4TB/s | 二态 |
| J3 | HBM4 通式**退化**到 2.048 TB/s | 公开标准（2048/8GT/s） | 写成 4.096 | 二态 |
| J4 | 反解 `R` 落在 [3.2, 16] GT/s | HBM 代际速率包络 | 950PR 强行按 4096 反解 | **三态** |
| J5 | `t_read == cap/bw` 量级自洽 | 闭式 | 单位错（GB vs Gb） | 二态 |
| J6 | 堆叠高度 = `n·t_die + (n−1)·t_bond` | 几何恒等式（**参数为假设**） | 少算界面 | 二态 |
| J7 | 物料必含白名单声明 | 用户约束原文 | 删掉声明 | 二态 |
| J8 | 剥离白名单后无禁用词 | 禁语表 | 写入"复现/达到/签核通过" | 二态 |
| J9 | 正文数字可由通式回算 | DQ×R 通式 | 写 4.096 而表里无 8GT/s | 二态 |
| J10 | 三态完备：`NOT_APPLICABLE` 不得记成 PASS | 枚举封闭 | 把 950PR 记 PASS | 二态 |
| J11 | manifest ↔ 文件**双向**完备 | 现有 `capability_guard` ② | 加文件不登记 | 二态 |
| J12 | 消费者**fail-closed**：不合规必须 raise | 3 个物料脚本 | 传入 BAD 文本仍写盘 | 二态 |
| J13 | 产物显式 `claimable=False` / `in_blocking=False` | 红线 | 删字段 | 二态 |
| J14 | 门禁自检元判据：合规样板必须过 | 自指 | 白名单短语被判红 | 二态 |

> 三态定义：`PASS` / `FAIL` / `NOT_APPLICABLE`（口径不适用，**不等于通过**）。J4/J10 是三态，其余二态；**禁把 N/A 计入 PASS 率**。

### 5.3 数据流

```
公开参数(手填, 带出处) ──► memif.audit_public() ──► 核对表(JSON: 值/口径/态/出处)
                                                        │
对外物料草稿(text) ─────────────────────────────► dclaim.check_claim(text, table)
                                                        │
                                          不合规 → raise / 拒绝写盘
                                          合规   → 物料 + 尾部核对表
```

产物三件：`memif_report.json`（数字 + 态 + 出处）、`claim_verdict.json`（文本判决 + 命中词）、物料 HTML 尾部**自动附**核对表（数字不手抄）。

### 5.4 真消费者（六处第 3 条硬要求）

**不能是门禁**。选定 3 个既有对外物料构建脚本，在写盘前调用 `dclaim.check_claim()`：

- `scripts/build_schip_intro_html.py`
- `scripts/build_pchip_materials.py`
- `scripts/build_talk_kit.py`

⇒ 这是**产品链下游**，且天然满足 R3「新模块一出生必须有消费者」。若三者中至少一个当前已废弃（死代码），则该脚本不计入消费者，需另选 WebUI 案例卡 render。

## 6. 对外物料模板（约束的落地形态）

**唯一允许的声明句式**（逐字，不得改写）：

> 设计期闭式核对·非流片实测：按公开参数计算，⟨参数⟩ 经 ⟨式子⟩ 复算得 ⟨值⟩；核对仅验证量级自洽，不构成设计能力或性能结论。

**禁语表**（机器扫，命中即拒）：

`复现` `验证了` `已达到` `超越` `赶超` `量产` `流片实测`（白名单外）`签核通过` `对标` `等效于` `达到 HBM 水平`

**必须出现**：`设计期` ∧ `非流片`

**示例（合规）**：

> 设计期闭式核对·非流片实测：按公开参数计算，4096 DQ × 7.8125 GT/s ÷ 8 = 4.000 TB/s；核对仅验证量级自洽，不构成设计能力或性能结论。

**示例（违规，应被拒）**：

> 我们平台复现了华为 HBM，达到 4TB/s，已完成流片实测签核。

## 12. 结论

**可行，但只在"缩到核对与门禁"这个尺度上可行。**

- 能立住的部分：**闭式核对是真的**（守恒式、量纲、通式退化）、**声明门禁是真的**（正反例已实测）、**缺口是真的**（现有 `honest_boundary_ok` 只扫 3 token、无正向声明、无数字回算）。
- 立不住的部分：任何形式的"复现/设计/性能"叙事——这也是杜先生那句话本身要防的东西。
- 一句话建议：**立项，但把项目定义成"对外表述合规工程"，而不是"HBM 研究"**。前者越做越稳，后者越做越像吹牛。
