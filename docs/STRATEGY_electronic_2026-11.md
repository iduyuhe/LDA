> 版本基线：`ae369fb` / v0.9.358（E55 单元内部图形接入 DRC）· CI core 391 · 账本 546（电子域 5 锚）
> 日期：2026-11-02 · 口径：设计期签核，非流片实测；规则集为自建教科书尺度，非 foundry PDK

## 一、结论摘要（先给判断，再给依据）

**1. 我们已经把「电子后端的主干功能面」铺完了，问题是每一项都只到一阶。**
ecore 包 73 个 .py（含 `__init__`）、31,852 行，覆盖综合→布局→布线→单元库→DRC/LVS→寄生提取→时序→功耗→电源网格→多角。
商业工具的功能清单我们**不缺项**，缺的是每一项的**深度和精度**。

**2. 与商业工具最硬的鸿沟不是算法，是「不接工艺」。**
全仓 **零 Liberty 解析、零 BSIM 器件模型**。商业工具一半的价值在「吃真工艺库」，我们吃的是自己写的参数表。
这一条不补，任何「对标」都是自说自话。

**3. 这一轮（E50–E55）最大的战略价值是「把判据方向纠回来」，不是多画了几个单元。**
六轮里有四轮的真正产出是**推翻上一个结论**（E51 推翻自己、E52 推翻 E51、E53 推翻 E52、E55 修正 E54）。
走弯路不可怕，可怕的是弯路被当成成果发布 —— 这几轮都做到了「先证伪、再前进」。

**4. 要达到「能对标商业工具」，还差三个数量级的规模 + 一条工艺接入线 + 一次公开对拍。**
行数差 ≈ 3 个数量级（3.2 万 vs 千万级），规模差 ≈ 4 个数量级（64 单元 vs 百万门），
且**从未与任何商业工具跑过同一份设计**。这是当前最该补的三件事。

## 二、把「对标商业工具」拆成可测的东西

含糊的「对标」无法执行。拆成五条可机核的里程碑：

| 编号 | 里程碑 | 可机核的验收判据 | 当前状态 |
|---|---|---|---|
| **M-A** | 接真工艺 | 能读入一份公开 Liberty（免 NDA 的开源 PDK，如 SkyWater 130nm / GF180），单元时序与驱动能力按 .lib 而非自建参数计算 | ❌ 零支持 |
| **M-B** | 规模的量级 | 单次布局布线 ≥ **10 万门**、DRC 通过、耗时与内存有实测曲线（不是外推） | ❌ 64 单元 |
| **M-C** | 结果可对拍 | 与至少一个开源参考实现（OpenROAD / OpenSTA / Yosys+nextpnr）在**同一份网表 + 同一份 PDK** 上跑，结果差异逐项列出 | ❌ 从未做过 |
| **M-D** | 签核的可信度 | 时序/功耗/寄生三项与参考实现的偏差有界（如 WNS 差 ≤5%、功耗差 ≤10%），且边界写清 | ❌ 无基准 |
| **M-E** | 智能原生闭环 | Agent 能独立完成「读规格 → 综合 → 布局 → 布线 → 修 DRC → 出报告」全环，人只做审；每步有 gate 与回滚 | ⚠️ 部分（人驱动迭代） |

**「可复用、可扩展、经得起挑错」** 已有的实证（这三条不必再论证，只需守住）：

- **可复用**：规则是参数（`run_drc(cell, rules=)` / `dproc.use(node, lib=)`）、判定器单份实现、单元由拓扑+规则生成。
- **可扩展**：新增一颗单元只需要拓扑约束，标签/DRC/LVS 自动覆盖（E55 G2 判据：老单元「自动获得标签」）。
- **经得起挑错**：每步都配反向探针（改坏必红），且本轮实测三种旧口径静默情形现已必红。

## 三、现状盘点（用数字说话）

### 3.1 规模

| 项 | 数值 | 说明 |
|---|---|---|
| ecore 模块 | 73 个 .py / 31,852 行 | 含能力清单 1,083 行、布线器 1,078、单元库 1,060（`span` 口径 72 个不含 `__init__`） |
| ecore 门禁 | 62 道 / 15,308 行 | 平均每模块 0.85 道常驻门禁 |
| 全仓 py | 1,028 文件 / 326,172 行 | 含光子/量子域与 WebUI |
| 电子域 ledger 锚 | **5 道**（B526–B530） | 能力面 74 条 vs 物理律锚 5 条 ⇒ **能力宽、证据窄** |
| 已布线最大规模 | 64 单元（116 引脚级） | E49 上探到 1024 单元，但那是「DRC 计数」不是「布通」 |

**「能力宽、证据窄」不是错误，是选择的结果**：整数几何与计数类量 `resid ≡ 0`，硬做 ledger 锚会撞 `zero_resid == 0` 与「非登记锚 resid>0」两条红线，所以它们以**门禁判别式**落地而不是伪造非零残差。但要清醒：**门禁通过 ≠ 物理正确**，它只证明「按我们写的规则没错」。

### 3.2 已具备的能力面（对照商业工具的功能清单）

| 环节 | 我们有的模块 | 深度 |
|---|---|---|
| 综合 | `dsynth` `drtl` `dcell` | 布尔网络到门级，无真优化（面积/时序驱动） |
| 布局 | `dplac` `layout` `dmtrack` `dpnr.place_real` `dscale` | 行式布局，无拥塞驱动、无合法化迭代 |
| 布线 | `dpnr` `droute` `dcroute` `ddroute_grid` `ddroute_rr` `dpathfinder` `dwallrr` `dinrow` `dwidth` | 迷宫/网格/通道三种，规模到千级 |
| 单元库 | `dcells` `dhdlib` `drealcell` `dnode` `dproc` | 规则参数化，28nm/45nm 两套自建 |
| 物理验证 | `ddrc_lvs` `dcells.run_drc` `dcnet` | 逐层宽/距/包围，双射 LVS |
| 寄生/时序 | `parasitic` `dspread` `dspef` `dsta` `timing` `dsignoff` `dpvt` | 一阶 RC + Elmore，多角有定理 |
| 电源 | `dpgrid` `row_metal` `layer_stack_ext` | 真矩阵解 G·V=I |
| 功耗/能效 | `energy` `budget` `signed_off_stack` | 一阶，无真实翻转率提取 |
| 器件/模拟 | `mosfet` `mna` `device_*` `analog_mvm` `crossbar_mvm` | **MNA 通用求解器含 DC/瞬态/AC**，器件是平方律 |

**修正一处此前说法**：不是「没有 SPICE」。`mna.solve_transient` 是真的瞬态求解器。缺的是**器件紧凑模型（BSIM）与时序库（Liberty）**，不是求解器本身。这个区别很重要 —— 补的是「模型与标准格式」，不是「重写引擎」。

### 3.3 缺的（不是功能项，是深度与接缝）

1. **Liberty / LEF / DEF / Verilog 标准格式**：一个都不支持。所有输入都是 Python 对象。
   ⇒ 这决定了我们**无法与外部世界交换任何东西**，包括无法把别人的设计拿来跑。
2. **器件紧凑模型**：`mosfet` 是平方律，无短沟道效应、无温度、无工艺角（`dpvt` 只做互连线）。
3. **时钟树综合（CTS）**：无专门模块，时钟被当成普通网布。
4. **优化环（optimization loop）**：布局→布线→修→再布局 的闭环只有单轮，无迭代收敛判据。
5. **真实翻转率**：功耗里 activity 是给定值，不是仿真得来。

### 5.2 弯路的共性只有五条（这五条能直接变成纪律）

**① 归因不做对照 —— 把现象当根因。**
最典型的两次：E52 把「我们自己选的 pad 尺寸」当成「物理渐近线」；E54 把「说法不准」当「盲区」。
**硬判据**：任何「根因」结论，必须能用 `git worktree add <旧 commit>` 起一棵对照树同批复跑，
证明「换了这一处，现象就消失」。做不到就写「待定归因」，不许写成结论。

**② 口径混装 —— 把「修正错误」和「真实代价」混成一个数。**
die 面积 +52.9% 里 **+41.6% 是旧公式少算一条通道的错值修正**，只有 +8.0% 是真代价。
**硬判据**：凡报「涨了 X%」，先问一句「旧值本身对吗」。凡报「X 才能 Y」，先问「X<阈值时到底成立了没有」。

**③ 判据方向反了 —— 用结果证明意图。**
E55 的核心：同层间距用「几何连通分量相同 ⇒ 同网」判，短路一旦发生几何会「正确地并网」⇒ 短路被当同网放行。
同类：`_canon` 排序键含 `str(gate)` ⇒ 大单元 LVS 必误报；`role` 字符串判 diff_seg ⇒ 拼接后异实例同名。
**硬判据**：**「意图」与「实测」必须是两份独立数据**，一致才通过。用一份数据证明它自己，永远绿。

**④ 只在子集上验收。**
「子集全绿 ≠ 全量绿」已实证四次（helper_dup 红 5 版 → A1 漏 10 处 → BL 偶发 → 本地 `def check`）。
**硬判据**：凡「加锚/加模块/加门禁/翻版」，当轮必须跑全量 CORE。已固化为纪律，本轮 391 门实测遵守。

**⑤ 靠命名约定保正确性。**
`role` 字符串、`_canon` 排序键、`group by id(cand)`（每网候选是不同对象 ⇒ 全拿 track 0 ⇒ 86 条叠死）。
**硬判据**：能用几何/物理判据的，绝不靠字符串或对象身份。**字符串命名是注释，不是约束**。

### 5.3 这五条已经沉淀成什么

- `IRONLAWS.md` / `METHOD_NOTES.md` / `CHANGE_CHECKLIST.md` 里逐条对应；
- 每轮门禁都配「反向探针」（改坏必红），并对「探针失靶」单独设判据（改了真值要以它为靶的反向探针必须仍有效）；
- 「两份真源必然漂移」已成硬约束：`dcells.run_drc(rules=)`、`dproc.use(node,lib=)`、`_VIA_BRIDGE` 表驱动都是这条的产物。

## 六、推进计划（三阶段，按「版本 + 判据」定验收，不给空日期）

### 阶段一：接通外部世界（最高优先，先解决「致命」三项）

> 目标：**能读别人的东西、能被别人读**。没有这一步，规模与对拍都无从谈起。

| 序 | 交付 | 验收判据（机核） | 预估 |
|---|---|---|---|
| 1.1 | **Liberty 子集解析器** `dlty.py`：cell/area/pin/capacitance/timing(linear+NLDM 表) | 读入一份公开 PDK 的 .lib，逐 cell 与源文件**逐字段回读一致**；解析失败必须报错不静默 | 3–5 版 |
| 1.2 | **时序改用 .lib 驱动**：`dsta` 的 t_pd 改从 NLDM 查表插值，保留原一阶路径做对照 | 同一单元同一负载，两法偏差 ≤15% 且方向一致；N 级链仍精确 = N×t_pd（退化判据） | 2–3 版 |
| 1.3 | **LEF/DEF 子集 I/O** `dio.py`：单元 LEF（SIZE/PIN/PORT/OBS）+ DEF（COMPONENTS/NETS） | 写出去的 DEF 能被第三方工具读回（用 OpenROAD 读一次即算通过）；往返一次几何逐位一致 | 3–5 版 |
| 1.4 | **Verilog 子集读入** `dverilog.py`：结构化门级网表 | 读一份公开基准（ISCAS/EPFL）网表，门数与拓扑机核一致 | 2–3 版 |
| 1.5 | **接真 PDK 的单元几何**：用 LEF 的单元尺寸替代自建尺寸 | DRC 用真 PDK 的 min width/space 跑一遍，违例清单可见（不要求零） | 2 版 |

**阶段一出口判据**：`能读一份公开 PDK + 一份公开网表 → 布局布线 → 写出 DEF → OpenROAD 能读回`。

### 阶段二：把规模推上去（决定「能不能叫工具」）

| 序 | 交付 | 验收判据 | 预估 |
|---|---|---|---|
| 2.1 | **分块布局**（partition + 层次化），每块独立布局后拼接 | 1 万门级：DRC 0、耗时曲线线性段可见 | 4–6 版 |
| 2.2 | **布线器重构**：把「全图 O(N²) 判邻」改成**均匀网格空间索引**（`spatial` 已有雏形） | 同一输入结果逐位不变，耗时从 O(N²) 降到 O(N log N)（实测两档对拍） | 3–4 版 |
| 2.3 | **增量布线**（只重布受影响的 net） | 改一个 net，重布量 ≤ 局部窗口，结果与全量重布一致 | 3–4 版 |
| 2.4 | **10 万门实测** | DRC 0 或违例可解释；内存/耗时实测（不外推） | 3 版 |

**阶段二出口判据**：`10 万门级，DRC 0，单机可跑完，曲线有实测点`。

### 阶段三：拿证据（对拍 + 智能原生闭环）

| 序 | 交付 | 验收判据 | 预估 |
|---|---|---|---|
| 3.1 | **与 OpenROAD/OpenSTA 对拍**（同网表 + 同 PDK） | 逐项差异表：WNS/面积/线长/违例数；偏差超界必须有归因 | 4–6 版 |
| 3.2 | **CTS**：H 树 + 时钟门控，skew/insertion 报告 | skew 与插入延迟可测；时钟网 DRC 0 | 4–6 版 |
| 3.3 | **优化闭环**：布局→布线→修 DRC→再布局，带**收敛判据** | 迭代 N 轮后指标单调收敛，否则终止并报告「不收敛」 | 3–5 版 |
| 3.4 | **Agent 全环**：读规格→综合→P&R→修 DRC→出报告，人只审 | 一条命令跑完，每步有 gate、失败可回滚、报告可复现 | 5–8 版 |

**阶段三出口判据**：`能在同一份输入上给出与开源参考的逐项差异，且差异有归因`。这才是「对标」的最小可信形式。

### 不做什么（防摊大饼）

- **不做全 DRC 规则集**（数千条）。只挑「会改变布局/布线决策」的约 20 条。
- **不做完整 BSIM**。先用「平方律 + 短沟道修正 + 温度」的简化子集，误差写清。
- **不追 GUI**。WebUI 只做只读面板，版图编辑不做。
- **不做多线程求解器内部并行**（先做门禁级并行就够了，见第七节）。

| `run_empirical_anchor_smoke` | 414.2s | 实证语料逐条重算 |

**关键事实**：这 8 道里，前两道（3,018s = 25%）是「对 546 个互相独立的锚做同一件事」—— **天然可并行、天然可分片**。

### 7.2 四个方案（按风险从低到高，收益叠加）

| 方案 | 做法 | 预期 | 风险 | 风险处置 |
|---|---|---|---|---|
| **A. 分档（立刻可做，零风险）** | 新增 `--tag core-fast`：排除 ≥30s 的 50 道 | **3.29h → 16min**（341 道 979s） | 低（只是不跑重门禁） | 日常用 fast，**发布前必须 full**；把「发布前跑 full」写进 checklist |
| **B. 门禁级并行** `--jobs N` | 按「有无副作用」分两段：纯计算门禁并行、会就地写受跟踪文件的门禁串行 | 8 道理论落到 ~1,541s（最长那道），全量估 **41–50min** | **中**：并行会互相踩（`ecosystem_d98.json`、`verification_report.*` 会被多道同时写） | 副作用门禁清单先行（已知 3 个文件）＋ 每道用独立 tmpdir（`det.scrub` 已有纪律） |
| **C. 锚级并行**（改门禁内部） | 前两道按锚分片到进程池（8 核） | 3,018s → **~450s** | **中**：确定性（每锚独立、无共享状态、种子固定） | 并行前后**逐锚 PASS/FAIL 与判据数必须完全相同**，作为该门禁的新判据 |
| **D. 输入哈希缓存** | `run_soc_s4/s5` 等大求解按「输入 sha + 代码 sha」缓存中间结果 | 命中时 2,600s → **~10s** | **高**：缓存失效 ⇒ 假绿 | 双键（输入 + 代码）缺一不命中；命中时**仍跑一次轻量自检**（比较缓存值与本轮抽样重算） |

### 7.3 建议的组合与节奏

1. **本周就做 A**（零风险，立刻把日常反馈从 3h 压到 16min）。这是投入产出比最高的一步。
2. **随后做 B**（并行框架 + 副作用隔离），目标「发布前全量 ≤50min」。
3. **C 与 D 作为阶段二的配套**（等规模上探后耗时还会涨，那时再投）。

### 7.4 一条硬纪律（比优化更重要）

**「变快」不能变成「变松」。** 任何并行/缓存改动，必须同时满足：
- 每道门禁的 PASS/FAIL 与**判据数**在优化前后逐项相同（机核，不靠肉眼）；
- 缓存命中路径必须能被打断（`--no-cache` 全量重算一次做对拍）；
- 分档的 `core-fast` **永远不能**替代发布前全量（写进 checklist，并用门禁守住：`pyproject.version` 变更时若只有 fast 记录 ⇒ 报错）。

## 八、给决策的三句话

1. **现阶段最该投的不是「再加一颗单元」或「再提 3 个点的布通率」，而是 Liberty + 标准格式 I/O。** 那是从「自建世界」走到「能与外部对话」的门槛，其余所有进度都受它制约。
2. **规模（10 万门）是第二个必过项，但它的瓶颈是数据结构而不是算法。** 我们现在全图 O(N²) 判邻，这在千级能忍，万级必崩；先做空间索引与分块，比换算法有用。
3. **CI 的 3 小时里有 1 小时是「对 546 个独立锚做同一件事」。** 分档 + 并行能把它压到 20–50 分钟，而且不需要牺牲任何判据 —— 但必须先把「副作用隔离」和「并行前后逐项对拍」做成判据，否则省下来的时间会用来查假绿。
