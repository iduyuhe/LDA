## 0. 一句话结论

M0 把「**2 通道链路预算**」跑通（闭式 ≡ 级联、无源无增益 B19、抓出并修复星型网重复计数平台 bug）；

两个此前**完全空白**的维度，闭合 **G-OI3（级电光行为模型）**，并**清偿 M0 遗留的 CI 覆盖缺口**。

## 1. 里程碑定义

- **M1 = 800G**：8 通道 **LWDM**（≈4.5 nm / 800 GHz 间隔），每通道 **100G = 53.125 GBd PAM4**
  （线速率 106.25 Gb/s，FEC 后净 100 Gb/s）。
- 层次推进：M0 = **链路预算（功率）**；M1 = **带宽预算 + 色散预算 + 眼/灵敏度预算**
  （在 M0 的功率预算之上，加**频域**与**时域**）。
- 诚实边界（沿用 M0/M5 纪律）：一切仍为 **`DESIGN_BUDGET`** 级（L0/L1 解析 + 行为模型），
  **非实测、非流片、不报 fabricated 能效/TOPS**。

## 3. 红线影响评估（**其中一项待杜先生定调**）

**合法（A 档闭式，不破红线）**：EO S21 / 探测器带宽 / TIA / 光纤色散 / 眼张开度 / 代价(dB) ——
均为**闭式物理律**，红线 `docs/lda_active_device_redline_clarification_2026-09-10.md` §四 A 档明确授权同族
（「探测器带宽 `τ=RC` 闭式」）；不碰「电-光耦合增益当功能真值」（T2 锁）· 不用 A 级商业工具 · 不流片。

🔴 **边界项：BER 数字**。
`lda_l2/eic_behavioral.py` 的 `EIC_DISCLOSURE` 明写「DAC/ADC/SerDes/DSP/**BER** 全部在红线外」，
其排除对象是 **EIC 电路级（晶体管级 · 需电域真值锚）**；而 M1 若做 BER，是**光链路预算级**，**不同层**：

| | 选项 A（**推荐**） | 选项 B（保守） |
|---|---|---|
| 内容 | 光链路**预算级**闭式 BER 估计 | **只报眼张开度 + 代价(dB)** |
| golden | 闭式 Q 函数 `BER = ½·erfc(Q/√2)` | 闭式 Q 因子（**不转 BER**） |
| 分层披露 | `OI_M1_DISCLOSURE` 明写「**不含** SerDes/DSP/FEC/均衡/CDR」· `verdict` 仍 `DESIGN_BUDGET` · 与 `eic_behavioral` 显式分层 | 完全避开 BER 字样 |
| 风险 | 需杜先生裁定「链路预算级闭式 BER 是否越界」 | 无 |

> → **请杜先生定调**（本文 §8）。

## 5. Golden 闭式锚（门禁用 · 物理律）

1. 一阶低通：`|H(f_3dB)| = 1/√2`，相位 −45°。
2. RC 带宽 `1/(2πRC)`（与 `compact_model.derive_responses` 同式 → 口径一致）。
3. 高斯脉冲色散展宽 `Δτ = |D|·L·σ_λ`（**时域仿真 ⟷ 闭式**，方法学独立对拍）。
4. PAM4 眼电平：3 眼，电平间距 = 满幅/3（定义显式）。
5. `BER = ½·erfc(Q/√2)`：AWGN 无 ISI 时**理论 Q ⟷ MC 计数**一致（选项 A 用；选项 B 只到 Q）。
6. 无源无增益 B19（`|T| ≤ 1`）延续。

## 6. 突变探针（**先证能变红**）

- **P1** 抹平 EO S21（去滚降）⇒ 带宽/眼门禁必红。
- **P2** 去色散（`D = 0`）⇒ 色散代价门禁必红（C-band 变体）。
- **P3** 倍增接收噪声 ⇒ BER/眼门禁必红。
- **P4** 打乱 PAM4 电平间距 ⇒ 眼/电平门禁必红。
- **P5** 撤掉 CORE 登记 ⇒ 覆盖门禁必红（对 CI 欠账的反向测试）。

### 9.2 实测数字

链路级：`f_3dB(EO)=32.94GHz` · `worstQ=3.76` · `worstBER=5.64e-05` · 聚合 **800Gb/s** · drop IL **7.18–7.55dB** · 最坏信道隔离 **39.5dB**（级联引擎口径；规划解 L0 口径 43.09dB）。

| 设计点 | Q | BER(闭式) | 色散代价 | 所需 SNR（KP4） | 期望 / 实测 |
|---|---|---|---|---|---|
| C_2km | 3.78 | 4.61e-05 | 0.64 dB | **26.56 dB** | pass / pass ✅ |
| C_10km | 0.69 | 1.77e-01 | 12.30 dB | 不可达（>60 dB） | disp_limited / 同 ✅ |
| O_2km | 3.90 | 2.99e-05 | 0.00 dB | 26.49 dB | pass / pass ✅ |

### 9.3 与 §5 / §6 的偏差

1. 🔴 **§5 的「KP4 门限」口径实现期曾写错 100×**（写成 `2.4e-2`）。收官回扫时按**外部公开标准**核对：IEEE 802.3bs/df Clause 91 · KP4 = RS(544,514)，pre-FEC 门限 ≈ **2.4e-4**（Keysight《数据中心向 224Gbps 演进》应用笔记 / Vitex 800G 验收指南 / Heather Technologies IEEE 802.3 FEC 对照表**三源独立一致**）⇒ 已修，并加 **C13 规格锚 + 探针 P6** 机器锁死。
   - 影响：`ideal_required_snr_db` 20.92 → **26.24 dB**（与工业共识 ~26 dB 吻合）；C_2km 所需 SNR → **26.56 dB**；**设计裕量由虚高的 ~7 dB 回到真实 1.44 dB**。
   - 四处设计点 **verdict 全部不变**（C_2km/O_* 仍过门限、C_10km 仍不可达）；`run_oi_m1_smoke` 修正前后均 **0 FAIL**，即该错**不会被原判据抓到** —— 它属「外部常量口径错」，只能靠**规格锚**守。
2. **§6 探针新增 P6**（原计划 P1–P5）：正为锁 §9.3-① 这类「外部常量静默写错」。
3. 两处 M0 遗留缺陷被 M1 顺带暴露并修复（定稿未预见）：`transceiver_m0_budget` **硬编码环区数 m=170**（与 build 脱钩 ⇒ 换 m 时闭式/级联静默分歧）、**B4(FSR) 目标单位错**（1.55 当 nm 传 ⇒ 目标恒 0.0nm）。
4. 前端门禁探针⑥ **抓出门禁自身的真 bug**（`_js_ref_ok` 未命中时误返回 True ⇒ 短路径被前缀假绿），已升级为「非标识符字符收尾」边界判定 —— **护栏自身也要被护栏咬**。
