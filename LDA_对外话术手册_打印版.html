1. 通用底座（两个场景共用，必背）

1.1 30 秒电梯版

LDA 是一个开源的、主权自研的光子/量子芯片设计软件。核心求解器由 AI agent 递归自举开发，但 AI 绝不进判决路径——设计好不好，由物理定律锚和公开实测锚的死标量比对说了算，任何人都能自己跑一遍验证。 我们不做制造、不做流片，只做设计到签核这一段的设计入口。

三个记忆点：开源 · 主权 · 可证伪。

2. 客户侧话术（买设计包的人）

Q1「我买了你的设计包，能直接拿去流片吗？」

能拿到的是「设计就绪包」，不是「保证流片成功」。 我给你完整的 GDSII 版图、SPICE 网表、逐器件几何参数、DRC 自查报告和死锚比对报告——该有的都在。 但我要说清楚三件事： 第一，我们的 DRC 是自查，不是厂级签核。foundry 收到 GDS 一定用他们自己的 deck 重跑，我们的 PASS 不算数——这是规矩，不是缺陷。 第二，我们没有流片过，一次都没有。我们的验证全部来自公开可溯源实测——论文 DOI、厂商 datasheet、IEEE/ITU 标准，这叫等效验证，不是本团队流片。 第三，工艺角 SS/TT/FF 目前是假设值，不是实测分布。根因不是我们偷懒，是硅光 PDK 生态本身普遍不提供统计分布——CMOS 有，硅光没有。

所以准确的说法是：这是一份经过死锚验证、诚实标注边界的设计包，不是流片担保。

Q2「格式兼容吗？是不是得买你们的软件才能打开？」

不用买任何东西。 我们交付 GDSII + SPICE 网表 + 逐器件几何 JSON + 设计意图 IR，全是公开标准格式——GDSII 是 SEMI 标准，不是任何公司的私有格式，全球所有 foundry 都能读。 而且我们的 GDSII 编码器是自研零依赖的，不绑 gdsfactory、不绑 KLayout，核心出口主权自持，1 nm 精度带 round-trip 回读验证。

三个边界我主动说： ① GDSII 只有几何，没有器件语义——里面就是一堆多边形，不带「这是波导、端口在哪、目标波长」。电子 EDA 有 OpenAccess 保留语义，光子界至今没有统一的语义交换标准，这是全行业的空白，不是我们的缺陷。我们的补救是额外给几何 JSON 和设计意图 IR。 ② 我们给的是展开后的多边形，不是参数化 PCell。你要在厂里直接改参数做不到，得回到我们这儿重新生成。 ③ 你用 Lumerical / Ansys 导入我们的 GDS 重跑，仿真设置要全部重做（材料、波长、端口），因为 GDS 不携带这些。

Q3「没流片过，我凭什么信你的数字？」

三条，你可以自己查： 一、可溯源。 我们的 golden 全部带公开定位符——DOI、datasheet、IEEE/ITU 标准，30 条实证语料 100% A 级，你按 DOI 能查到原文。 二、可自验。 所有验证资产都开放了无鉴权端点，你 curl 一下就能拿到全部 52 道锚的分类和判决结果，不用听我说。 三、可证伪。 52 道锚里 26 道是严格独立候选——候选和 golden 方法学不同源，比对的死标量非 0，扰动必红。剩下 25 道是自证桩，残差恒 0 恒 PASS，没有验证价值，我们如实标出来。

Q4「那不是一半没验证？」

对，而且是我主动告诉你的。 商业软件不会告诉你哪个模块是自证的。 剩下的多数结构性接不了——比如 S1–S6 是纯算术恒等式，接任何候选都是同义反复，怎么接都是自证。 我们的原则就一句话：宁可红，不假绿。

Q5「AI 写的求解器，靠谱吗？出错了谁负责？」

核心求解器确实是 AI 写的，但 AI 绝不进判决路径。AI 只生成候选拓扑和默认参数；判决由物理定律锚 + 实证锚的死标量比对完成。 这是 LDA 和所有「AI 生成设计」类产品的根本区别——那些是 AI 说了算，我们是 AI 出题、物理定律判卷。

🔑 但这句话光讲是空的，要拿证据——接着往下说：

我说「AI 不进判决路径」，不是一句口号，是代码里的红线。我给您看一条真实在跑的流水线，它把这句话拆成了五步：

第一步，先用锚锁定可行域。 不是让 AI 随便想方案，是先把功率预算、频率规划、最坏情况这些锚约束算出来，画出一个物理上可行的范围。 第二步，AI 在这个范围内出题。 它只能在框里活动，出不了框。 第三步，每一案都过死锚。 提一个验一个，逐个比死标量，超容差直接淘汰。AI 生成的方案不会被无条件采纳。 第四步，确定性排序。 按余量降序排，没有随机、没有 LLM 参与。同样需求跑两遍，结果一模一样，可复现。 第五步，人拍板。 最终选哪一个，是您决定。

这条链有 6 条系统类型流水线在跑（光链路、波分复用、量子保真度、传感前端、QKD、CPO 光 I/O），配套 15 条判据已进 CI 门禁——每次改代码都自动重跑（2026-09-09 实测 15 PASS / 0 FAIL）。

给您两个刚跑出来的实测数字，比我说什么都有用： 一是域内 9 个候选，过锚只剩 3 个——AI 出了 9 个方案，物理定律刷掉 6 个。AI 出题的通过率是三分一，它通过的不是它自己说了算的。 二是给 AI 喂 4 条垃圾参数（越界 / NaN / 物理矛盾 / 类型错），4 条全被拒——这些拒它的不是人，是锚。

所以准确地说：AI 在我们的系统里只做一件事——在物理定律划定的框里，多提几个候选。判卷的是物理定律，拍板的是您。

收口一句（背下来）：

别的公司是 AI 说了算，我们是 AI 出题、物理定律判卷、人拍板。AI 连排序权都没有。

Q6「能算良率吗？」

能到设计良率这一层：环周长在 σ=±1% 光刻容差下命中 ±2% 规格窗口的概率，解析闭式 0.954413 对蒙特卡洛 0.954750，两种方法互证。 但封装良率算不了——那要工艺波动分布 + 设备能力参数，我们现在没有。这也是我们在推「设计侧虚拟制造」的原因。

Q7「出货后我们实测对不上怎么办？」

这是我们最想要的东西。我们缺的就是实测真值。 我的建议是做成数据回流条款：你把实测数据（脱敏即可，带测试条件和校准溯源）给我们，我们用来标定模型，下一版的设计精度就是你的数据喂出来的。 这对你不是成本，是让你的下一版更准。

第四层：我们要占的不是「电」，是「光电之间的接口」

电子这边有 OpenAccess 保留语义、有 IBIS-AMI 做电域模型交换；光子这边到今天没有统一的语义交换标准。 这才是「光电一体」真正缺的那块——不是谁把电也做了，是光电之间没有一个可靠的接口。 我们已经有 L0 IR 和设计意图 IR（DesignPackage JSON），走的就是这个方向。做接口，比做电更值钱，也更适合我们。

🔴 诚实边界（必须同时说）：48 条对标是对标公开规格的等效验证（公开 roadmap / 技术报告 / 实施协议 / 论文 DOI），不是本团队流片验证，也不是给这些厂商做过认证。不要说成「NVIDIA 认可我们」。

一句话收口：

光电一体不是一家做出来的，是一条链做出来的。我们不打算做整条链，我们做的是这条链上唯一既没有可证伪工具、也没有统一接口的那一格——光。

3. 特殊场景：客户要「光子计算芯片」

🔴 「光子计算芯片」是陷阱词。客户嘴里至少是三种完全不同的东西。直接答「能做」可能接下做不来的活；直接答「做不了」可能推掉真能做的单。必须先反问澄清。

3.1 第一步：一句反问定清楚（照着念）

您说的光子计算，我想确认一下是哪一类——是做 AI 推理的模拟矩阵乘（MZI mesh 那种），还是片间光互连，还是想做全光逻辑门那种通用光计算？这三种我们的能力范围差别很大。

客户说的实际是什么我们
a) 模拟矩阵乘 / ONN 推理加速MZI mesh 做矩阵-向量乘（最主流，Lightmatter、Lightelligence 在做）✅ 能做光前端
b) 光互连 / 光 I/O其实是 CPO，叫错名了✅ 能做（走 CPO 口径）
c) 全光通用计算光逻辑门、光晶体管❌ 诚实劝退——全球都没有产品

问出这一句，你就已经不是外行了。 外行直接接单，内行先问清楚。

3.2 第二步：如果是 a（最可能），这样答

能做，但我要先说清楚我们做哪一段。 我们把光子计算拆成四层——无源光前端、有源器件、电域、非线性激活。我们只做第一层：MZI mesh 的分光、波导交叉、传输损耗、级联插损预算、相移器效率，一直到版图 GDS、DRC/LVS 签核。 有源器件（激光、调制、探测）我们按黑箱 + 公开文献锚处理，不做物理级建模。电域（ADC/DAC、驱动、存储、时序）和非线性激活，我们明确不做——那不是我们的领地。 所以准确的说法是：我们交付的是光子计算的「光前端」，不是一台光子计算机。

#层我们做不做说明
①无源光前端（分光 / 交叉 / 传输 / 级联预算 / 相移效率）✅ 主权可做一直到 GDS + DRC/LVS 签核
②有源器件（激光 / 调制 / 探测）⚠️ 黑箱 + 文献锚不物理级建模（负面清单）
③电域（ADC/DAC、驱动、存储、时序）❌ 不做无电域锚，硬做必假绿
④非线性激活 / 全光逻辑❌ 不做全球无产品

3.3 第三步：🔴 客户最想要的那个数，我们不能给

客户接下来大概率会问：「那能做到多少 TOPS？能效多少 pJ/op？」

这个数我们不给，也不该给。 因为 TOPS 和能效主要由电域决定——ADC/DAC、数据搬运、存储。光的部分只占一小部分。我们没有电域锚，硬比一个数出来必然是假绿。 我们能给的是光前端的插损预算：每一级 MZI 多少损耗、N 层 mesh 级联后还剩多少光、探测器端信噪比够不够。这个数给你，你把电域参数代进去自己算总账。

🔴 这条和「不判决 pJ/bit」是同一条铁律：电域主导，比了必假绿。说出来是加分项——对方会觉得你懂系统，不是只会吹光。

3.4 第四步：抛出杀手锏（这一个问题定住场面）

顺便问一个可能比算力更要命的问题：您知道在这条工艺线下，您的 mesh 实际能到几 bit 有效精度吗？

为什么这是杀手锏： MZI mesh 对相位误差极端敏感——工艺波动 σ 一大，矩阵权重就偏，有效精度直接崩。这是光子计算落地的真实瓶颈，比算力更致命。

而我们恰好能算：S13 设计良率锚（工艺波动 → 命中规格窗口概率）+ B29 热光相移效率锚 + 工艺角分析，给的是可证伪的死标量，不是吹的。

别人答不了这个问题，我们能。这才是你该把话题引向的地方。

3.5 第五步：判断这单接不接

客户类型判断
高校 / 研究所✅ 值得接，而且是宝贝——他们的实测数据可以回流标定，正是我们最缺的真值。甚至可以谈「我们做设计，你们回流数据」
要做产品的公司⚠️ 接，但要提醒：光前端不是瓶颈。可以直说「您这笔钱如果全花在光前端上，可能买不到您想要的性能提升」

3.6 🔴 反面提醒：别为了接单说「能做」

如果客户期待的是「交给我们一台光子计算机」，你接了必翻车——翻车的时候，前面那些「开源、主权、可证伪」的信誉一起赔进去。

我们最值钱的资产是「说出来的每个数都能被验证」。为了一单砸掉它，不划算。

4. Foundry 侧话术（PDK / 合作）

🔴 开场定调（最重要）：Foundry 的人每天被打招呼，第一反应是「又来要东西的」。 所以开场不要提你要 PDK，先讲你能给他什么。

Q1「你们想让我们提供什么？」

先说我们不想要的： 我们不问你要工艺配方（recipe），不问你要 TCAD 参数，不问你要任何不外给的东西。那是你的核心资产，我们清楚边界。

我们想要的是你已经公开或半公开的两类东西： ① PDK 本身——层栈定义、DRC/LVS deck、器件紧凑模型、工艺角。这些你本来就给所有客户，给我们一份不会增加你的风险和成本。 ② （如果能给）工艺波动的统计分布——CD 偏差 σ、膜厚均匀性、侧壁角范围。这是可选的，给不了我们也能干活。

Q2「我们的 PDK 是保密的，凭什么给你们？」

完全理解，而且这正是我们的价值所在—— 我们有 PDK 之后做的第一件事，是帮你在设计端把不合格的设计挡住。

你现在面对的问题是：客户把设计丢过来，DRC 一跑一堆违规，来回打回三趟。设计方不知道你的规则，你也替不了他们设计。 我们在中间加一层：用你的 deck 做设计侧预检，交到你手上的设计已经过了你的规则。 这直接减少你的打回次数和沟通成本。

而且我们开源。你看到的就是全部，没有隐藏逻辑，没有把你的数据送去训练任何模型。

Q3「你们是竞争对手吗？我们会不会培养出一个抢我们生意的？」

不会，因为我们明确不做三件事： 不做工艺仿真 TCAD、不做封装、不做流片。这三块是你们的领地。 我们做的是设计入口——把更多、更合格的客户送到你这里。 我们的商业模式是设计授权和定制设计，客户越多、流片越多，我们越好。我们和你是同一侧的。

Q4「你们的 DRC 跟我们的 deck 什么关系？」

我们的规则是自查用的，不等同、也不试图替代你们的 deck。 我们对外一直是这么说的：「我们的 DRC 结果不算数，厂里会用他们自己的 deck 重跑。」 有了你们的 deck 之后，我们要做的是适配层——把你们的规则接进来，让设计侧预检用你们的规则，而不是我们的。这才是真签核。

Q5「你刚才提到工艺波动分布，那个我们不外给」

理解。那我换个问法：你们有没有公开的表征数据？ 比如 shuttle 的公开实测报告、公开 PDK 文档里的层厚公差、论文里引用过的你们的数据。 我们要的不是配方，是统计分布——一个 σ 值，用来把我们的工艺角从「假设」变成「数据驱动」。 给不了也完全没问题，我们继续用公开文献的量级，只是精度上不去。这一点我们对外也是如实说的。

Q6「这对我们有什么好处？说直接的」

三条，都可以量化： 一、客户质量提升。 设计侧预检过滤后的设计，打回率下降，你的工程时间省下来。 二、MPW 拼版利用率。 我们能帮客户把设计做得更紧凑、更合规，同样面积多放设计。 三、你多一个获客渠道。 我们的创新超市 75 个货架是面向真实买家的，他们在那儿选设计，流片要找你。我们可以把你的工艺作为推荐选项挂上去。

前两条是我们的活，第三条是白给你的曝光。
