## 一句话

E34 把数字这条腿从 0 建到「能综合一颗真控制壳、并机器证明它对」—— 但那仍是**无物理面积、无真实线延时**的「逻辑前端」。
本段在 **「不借 OpenROAD」** 的前提下，自己造一个**最小但诚实的 P&R**，把 E33 的阵列 GDS 与 E34 的数字壳 + 本段布局布线，**打包成一个真的 CIM 加速器 IP 硬宏**。
核心诚实闭环：**把 E34「走线电容=0 的理想 Fmax 1535 MHz」变成「带线载的真实 Fmax 1024 MHz」**。

---

## ① 终点裁决：CIM 加速器 IP（不是能流片的 SoC）

用户裁定终点为 **CIM 加速器 IP**（硬宏），而非完整 SoC。两者签核标准差一个数量级：

| 维度 | CIM 加速器 IP（本段终点） | 完整 SoC（未做） |
|---|---|---|
| 内容 | CIM 阵列 + 数字控制壳 + 外框 + 引脚 | 上 + IO ring/PLL/数模混合/子系统 |
| 签核 | 阵列 DRC/LVS + 数字等价性 + IP 级 GDS | 全芯片 DRC/LVS + 时序签核 + 电源网络 |
| 对外 | 作为 IP 被集成 | 独立芯片 |

⇒ 本段交付物就是那个「IP 实体」，有**外框、顶层引脚、单一 GDS**。

## ② 四层自研 P&R（4 模块 · 能力 43 → 47）

| 层 | 模块 | 关键金标 |
|---|---|---|
| 0 | `dplac`（标准单元布局） | **面积守恒**：Σ(摆放单元面积) ≡ Σ(n_tr·area_per_tr)（差 < 1e-6） |
| 1 | `droute`（全局布线） | **2 端网线长 ≥ 两端曼哈顿距离**（精确下界）；总线长 ≤ 1.5×HPWL |
| 2 | `dextract`（线载 + 线感知 STA） | **Fmax(线载) < Fmax(理想)；线载×K 单调降；线载=0 逐位=理想** |
| 3 | `dmacro`（IP 硬宏 + GDS 合并） | **合并 GDS 元素 emit ≡ 回读 parse（零丢失）** |

复用：E34 的 `dsta.sta`（新增 `wire_load_ff` 参数，零线时行为不变 ⇒ E34 三路径金标不受影响）、
E33 的阵列 GDS（`crossbar_array` + `gds_export` 编码器/解析器）。

## ③ 数字壳 P&R 后的真实数字（全部现算）

| 指标 | 值 | 口径 |
|---|---|---|
| 数字区 die | 18.0 × 18.7 µm · 6 行 | 行式布局（H_ROW=2.4µm · 宽=面积/行高 ⇒ 面积守恒） |
| 总线长（MST） | 16,565 µm（1,359 网） | 🔴 MODEL_ESTIMATE（布局是模型） |
| 总走线电容 C | 3,313 fF（0.2 fF/µm 假设） | 🔴 假设 c_per_um |
| **Fmax（理想，线容=0）** | **1,535 MHz** | E34 同值（边界确认） |
| **Fmax（带线载）** | **1,024 MHz** | 🔴 线感知 STA（比值 0.667） |
| IP 硬宏 | **270 × 232 µm · 62,581 µm²** | 阵列(~207µm) + 数字(18µm) + 间距 + IO ring(12µm) |
| 顶层引脚 | **108**（真实对外端口，已剔除 @d 次态网） | — |
| IP GDS | **4,459,976 字节 · 69,746 元素零丢失** | flat（非 AREF，可机核零丢失） |

⚠️ **架构差异显式声明**（与 E34 同）：控制壳是**单 ADC 时分复用**，E17 假设 ADC 并行 ⇒ 两者每样本耗时**不可相除**。

## ④ 🔴 本段踩的/防的四个坑（突变成探针 C1–C4）

| # | 缺陷 | 表现 | 谁守 |
|---|---|---|---|
| **C1** | **面积不守恒**（宽砍半 ⇒ 面积少一半） | 布局的诚实缺口会被「Σ摆放 ≡ Σ n_tr·area」抓红 | `plac_self_check` 对照组 |
| **C2** | **2 端网线长 < 两端距离**（物理不可能） | 布线编数会被「线长 ≥ 曼哈顿距离」抓红 | `route_self_check` 对照组 |
| **C3** | **线载×100 却 Fmax 不降**（伪造「线让电路更快」） | 线感知 STA 逻辑反；单调性判据抓红（fw0=1024 → fw100=22） | `extract_self_check` 单调性 |
| **C4** | **漏掉数字单元包围盒却谎报 emit**（E31 via stack 假绿同型） | GDS 元素 emit≠parse 必须打红 | `macro_self_check` 对照组 |

🔴 **C2 是「金标方向」的教训**：初版写成「总线长 ≥ HPWL（半周长线长总和）」—— 方向**反了**
（HPWL 是 RSMT 的**上界**，多端网 MST 可低于其 HPWL）。⇒ 通则：**先想清不等式方向，再写金标。**
最终改用「**2 端网线长 ≥ 两端曼哈顿距离**」（精确下界，取等即直连）作为可机核判据。

## ⑤ 诚实边界（下一步的全部前提）

- **数字单元只画了「包围盒矩形」，不是真实单元内部几何**（poly/diff/via 没画）⇒ 这是**布局占位** GDS
- **无 detail route 全解** ⇒ 全局 MST 是估计；无绕障/拥塞/via 代价
- **无 IO 环电气连接几何** ⇒ 阵列与数字块只是「摆在一起」，未做电源/信号整合
- **线载只算 C_wire，没算 R_wire·C_wire 的分布式延时** ⇒ 长网被低估 ⇒ **Fmax(线载) 偏乐观**
- **无 P&R 签核 DRC/LVS 对 IP 整体** ⇒ IP 的**可制造性未验证**
- 🔴 `soc_flow` 的边界声明已换代（E34「无 P&R」→ E35「自建**简化** P&R · CIM 加速器 IP 硬宏」），E33 门禁 B12 同步跟改
