# 层次化 GDS 导出 POC · 实测报告

> 日期：2026-09-04 · 版本基准 v0.9.31 · 承接 `lda_million_scale_assessment_2026-09-04.md` 的 P0 建议
> 脚本：`assess_1m_hierarchy_poc.py`（可复现：`python -u assess_1m_hierarchy_poc.py {small|full}`）
> 目的：回答「把 flat 版图改成 cell + AREF 层次化，能降多少？降了以后还等价吗？」

---

## 0. 结论

**层次化方案成立，且效果远超预设目标。CPO 250k 的 GDS 从 97.45 MB / 897,600 元素
压到 36 KB / 331 元素，降幅 99.96%，展开后与 flat 数值等价（≤1 DBU）。**

预设目标是「元素 < 50,000、体积 < 10 MB」，实际达成 331 / 36 KB——**比目标好两个数量级**。

**同时 POC 意外暴露一个真实产品缺陷：IO 光栅齿没有应用端口位置偏移**（第 4 节）。

---

## 1. 实测数据（CPO 250,240 器件 · 2,720 通道）

| 指标 | flat | 层次化 | 降幅 |
|---|---|---|---|
| GDS 元素数 | 897,600 | **331** | **99.96 %** |
| GDS 字节 | 97.45 MB | **36 KB** | **99.96 %** |
| 编码耗时 | 6.332 s | **0.001 s** | **99.98 %** |

- 自动检测结果：重复周期 **p = 92 器件**（= 单通道器件数），阵列 **4 列 × 680 行**，步进 (3289.883, 28.989) µm
- 层次化结构：**1 个 `CHANNEL` cell（330 元素）+ 1 条 `AREF` 记录** = 331
- 周期检测耗时 0.334 s；等价性验证 7.90 s

**规模无关性**：cell 元素数与通道数无关。降幅 ≈ 1 − 1/n_inst
- 4 通道（小规模验证）：1,320 → 331，**降 74.9 %**
- 2,720 通道：897,600 → 331，**降 99.96 %**
- 外推 1M 器件（≈10,880 通道）：flat ≈ 359 万元素 → 层次化仍是 331

⇒ **层次化把 GDS 体积从 O(N) 变成 O(1)。**

---

## 2. 方法（均为算法自动完成，未硬编码 92）

1. **周期自动检测**：把每个器件映射为签名 `(kind, 参数元组)`，用 KMP 前缀函数求 token
   序列最小周期，再全量验证 `sigs[i] == sigs[i % p]`。实测自动得出 p = 92。
2. **阵列结构识别**：计算每个实例相对首个实例的位移，找换行点确定 `nx`，
   再**严格校验全部 2,720 个实例位置**满足 `pos(k) = base + (a·dx, b·dy)`，
   任一不符即放弃 AREF 回退 SREF。实测识别为 4 × 680。
3. **cell 提取**：
   - 器件：第 0 个周期内的全部器件几何，坐标减去通道原点
   - 布线：**严格归属**——net 两端器件必须都属同一通道（用 `net.connects` 判断，
     不靠坐标猜测）。POC 早期版本用「y 坐标是否同行」判断，导致同行其他通道的
     布线被错误并入 cell，展开后多出 104 个元素 —— 已修正
   - IO：端口所属器件必须属同一通道
4. **AREF 编码**：`gds_export` 原无 AREF，POC 新增（`0x0B` + `COLROW` + 三原点 XY，
   `STRANS=0` 无变换）。
5. **等价性验证**：层次化按实例位置展开 → DBU 量化（1 nm）→ 与 flat 做多重集合比对。

### 等价性判据（两级，显式不掩盖）

GDS 的最小网格单位是 1 DBU（= 1 nm）。层次化引入「减原点 + 加实例位置」的浮点往返，
在 `.5 DBU` 边界会产生 1 DBU 的舍入差异。故：

| 级别 | 判据 | 本次结果 |
|---|---|---|
| 严格等价 | 多重集合完全相同（0 偏差） | ✗（8,846 个元素有差异） |
| **数值等价** | 差异元素可一一配对且距离 ≤ 1 DBU | ✅ **通过**（最大偏差 1 nm） |
| FAIL | 存在无法配对或 > 1 DBU 的差异 | — |

**8,846 个差异元素占总数 0.99 %，偏差恒为 1 nm = 1 DBU**，是版图精度定义下的最小单位，
远小于工艺 CD 控制精度，在 GDS 语义上无意义。但**必须显式报告，不得悄悄放过**。

## 4. 🔴 意外发现：产品缺陷 —— IO 光栅齿未应用端口位置偏移

> **✅ 状态更新（2026-09-04 · v0.9.32）：本缺陷已修复并加常驻护栏。**
> 修复方式不是「一行改动两处」，而是抽出 `_desc_elements(desc, ox, oy)` 作为**单一偏移施加处**
> （根治「两处各抄一遍、错得一样」）。新增常驻护栏 `lda/run_io_grating_offset_smoke.py`
> （CI core 91→92），经反向测试证明会响（缺陷态 5/10 亮红 → 修复后 8/8 全绿）。
> 详见 `CHANGELOG.md` v0.9.32 段。以下保留取证过程备查。

### 4.1 缺陷位置

`lda/lda_l2/chip_layout_export.py:108-122` `_io_grating_elements`：

```python
for (inst, port) in io_ports_of(link):
    ox, oy = port_abs(inst, port, placement, link)
    for d in primitive_descs("grating_coupler", {...}):
        pts = [(ox + px, oy + py) for px, py in d.get("points_um", [])]
        if d["kind"] == "path":
            elements.append(gds_export.path(d["layer"], d["width_um"], pts))
        else:
            flat = [pp for ring in d.get("rings_um", []) for pp in ring]   # ← 未加 (ox, oy)
            elements.append(gds_export.boundary(d["layer"], flat))
```

`path` 分支正确偏移，**`boundary` 分支漏加 `(ox, oy)`**。
同类问题亦见于 `_device_elements`（`chip_layout_export.py:103-104`）的 boundary 分支。

### 4.2 证据（实测，非推理）

`primitive_descs("grating_coupler", n_tooth=16)` 返回 **1 个 path + 16 个 boundary（齿）**。
即光栅齿走的是 boundary 分支 → 全部未偏移。

小规模（4 通道）实测 boundary 元素的首点 y 分布：

| | y 分布（DBU） |
|---|---|
| **修复前**（产品现状） | `(-250, 256)` —— 256 个齿**全部**堆在同一处 |
| **修复后** | `(-12250, 64), (-250, 64), (16739, 64), (28739, 64)` —— 正确分散到 4 个通道的 4 类 IO 端口 |

而 4 类 IO 端口的实际 y 确为 `0.0 / -12.0 / 16.9886 / 28.9886`（实测），修复后的分布与之逐一对应。

### 4.3 影响

- CPO 250k：**174,080 个光栅齿（2720 通道 × 64）全部堆在原点附近**，占全部元素的 **19.4 %**
- 后果：IO 光栅区版图完全错误——所有齿重叠在 (0,0)，真正的 IO 端口处没有任何齿结构
- 性质：**版图正确性缺陷**（非性能问题）。若据此流片，IO 耦合器全部失效
- 未影响：器件主体几何（Waveguide / Ring / GC 主体均为 path 分支，偏移正确）

### 4.4 修复方案

一行改动（两处同样模式）：

```python
flat = [(ox + px, oy + py)
        for ring in d.get("rings_um", []) for px, py in ring]
```

⚠️ 修复会改变 GDS 输出，需按项目纪律走完整回归（48 锚三分类 23/0/25 + 91 条 CI smoke），
并补一条**反向测试**证明护栏会响（例如断言 boundary 元素的 bbox 随 IO 端口位置变化）。

   **POC 的降幅结论（99.96%）现已完全适用**，不再依赖「修正后几何」这一前提。
2. ~~**本 POC 未集成进产品代码**，是独立验证脚本。~~
   **✅ 已于 v0.9.33 消解**：层次化已产品化（`lda_l2/hierarchy.py`），
   `export_chip_gds(with_hierarchy=True)` 默认开启，CPO 250k 实测降幅 99.96%。
3. **未做层次化 DRC / LVS**——只验证 GDS 导出环节的降幅与等价性。层次化 LVS 的
   降速效果（评估中预估 3.45 s → < 1 s）尚未实测。
   ⚠️ 注意：v0.9.33 的层次化**只压缩 GDS 编码**，DRC/LVS 仍走 flat 几何，
   判决结果与层次化前完全一致（已由护栏判据 G 钉死）。**降速收益尚未兑现。**
4. **周期检测依赖「器件按重复模式顺序生成」**。若设计是任意网表、器件顺序打乱，
   需先做拓扑排序或改用几何哈希聚类——本 POC 未覆盖这类输入。
5. **代价**：2,720 个实例的等价性验证耗时 7.90 s（展开 + 量化 + 集合比对）。
   产品化时应改为**抽样验证**（验证首、末及若干随机实例），不必全量展开。
