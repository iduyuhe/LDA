1. 客户尽调的五个发现（把追问转成 BP 资产）

1.1 客户替我们划定了首个可接订单的范围

客户说「电域也就是 ADC/DAC，不是最复杂的部分」——这不是刁难，是在划范围。

⇒ 于是有 A 档：光电接口层，150–300 万（2–3 人 / 12–18 月）。这是订单，不是融资。客户一旦签，我们就有自造血。

1.2 成本真相：钱不在光，也不在电，在接缝

硅光模块成本项占比
封装 · 测试 · 组装79.9%
硅光芯片（Tx + Rx die）11.4%
电芯片（Driver / TIA / LDD 等）8.6%

数据来源：Yole Développement（IEEE 802.3cz 公开材料，Ogura 2021）；天风证券 2024 同口径「芯片约 10%、封装约 80%」。

推论（对客户、对投资人都成立）：光电集成不是更便宜，是更贵——因为单模光纤 MFD ≈ 10 µm、硅波导亚微米，对准容差 < 0.5 µm，主动对准是串行逐器件的，无法像晶圆制造那样并行扩产。产业实证：ficonTEC 高端全自动耦合设备年产能仅 30–40 台，交期 5–7 个月。

⇒ 这恰恰证明我们占的那一格是对的。

1.3 判决锚决定 AI 能进哪一段（Ricursive 反证）

业界确实有人在挑战「链」——AlphaChip 创造者创立的 Ricursive Intelligence，累计融资约 $985M，明确说「不是 EDA 公司、不用标准 EDA 工具链」，目标 workload → GDSII 端到端。

但它打的是电子链，不是光电链。 分野在于：

AI 能进入一个环节的前提，是那个环节有可精确计算的判决信号（reward）。

  • 电子链：PPA / 时序 / 线长 / 拥塞 / DRC 全是可精确计算的死标量 ⇒ AI 全链渗透。
  • 光子链：器件有 Maxwell 锚、链路有功率预算；但工艺角是假设值、封装测试无锚、无统一语义交换标准 ⇒ RL 到这里没有 reward。

⇒ AI 设计芯片走通了，不是因为 AI 变强，是因为电子链的判决锚成熟。瓶颈是判决锚，不是算力。

这也正是我们把钱投在真值而不是电域的根本原因：补判决锚，是光子链上唯一别人做不了、且卡住所有人的那一格。

1.4 暴露的真短板：网表只是骨架（必须主动披露）

核实代码确认：我们交付的 SPICE 网表目前只有 `X1 in out WAVEGUIDE` 这类结构行，端口语义为占位，没有 VπL、带宽、结电容、响应度等器件参数。

⇒ 这是缺口，不是资产。 已在话术手册与本文档主动披露。客户追问参数时主动说出来，反而是加分项。

1.5 客户替我们做了定位

客户问「只有光没有电，怎么适应市场」——这个问题本身说明：市场认为光电之间的接口是缺的。 电子有 OpenAccess、有 IBIS-AMI；光子界到今天没有统一的语义交换标准。我们要占的不是「电」，是光电之间的接口。做接口比做电更值钱。

2. 战略定位修订

LDA = 光电接缝上的可证伪设计入口。

我们不打算做整条链，我们做的是这条链上唯一既没有可证伪工具、也没有统一接口的那一格。

2.1 三不做及其产业根因

不做根因
不做电域求解器（SerDes / DSP / 眼图 / BER）没有电域锚 ⇒ 做出来的数必然是假绿；且客户已有 Cadence，做了也不会换
不做 foundry TCAD / 工艺仿真foundry 核心资产，不外给；护城河在设计→验证数据层

「不做」不是能力不足，是结构性选择 —— 每一条都有根因，这是内行的答法。

2.2 交付链全景：我们从「需求」就开始管

客户第一个问题永远是「我要什么架构」。这一段答不好，后面所有环节都建立在错误的需求上。LDA 不是从仿真开始的，是从需求编译开始的：

``` 功能需求 → ① 锚约束剪枝 → ② 域内生成候选 → ③ 逐案过死锚 → ④ 确定性排序 → ⑤ 人终审 （先锚定可行域） （AI 在此出题） （物理定律判卷） （无随机无 LLM） ```

这条链已在生产代码里落地（`lda_harness/proposal_compiler.py`，687 行，15 判据 smoke 在 CI），已支持 6 条系统类型流水线：`link` / `wdm_demux` / `quantum_fidelity` / `sensor_frontend` / `qkd_link` / `cpo_optical_io`。

这是「AI 出题、物理定律判卷」最完整的落地样板——AI 只在可行域内生成候选，每一个候选都必须过死锚，排序完全确定性，最终选择权在人。LLM 不进判决路径这条红线，在这里是代码级的，不是口号。

一家设计公司跑一个项目要经 8 个阶段。逐段核对后，我们覆盖的是「技术链」，不是「项目链」：

🔴 最隐蔽也最要命的缺陷：我们没有「基线」

设计公司靠基线活着：需求基线 → 设计基线 → 出带基线，改需求即改基线，须签字并重估工期与费用。

「可证伪」的前提是「证伪的对象是固定的」。 需求不冻结、验收标准不签字，客户可以一直改指标——那时 52 道锚也没用，因为判的对象在变。

这不是流程洁癖，是「可证伪」能否落地的前提。

责任边界声明（可直接作为客户洽谈附件）

LDA 定位为「可证伪的设计与验证能力提供方」，在项目全生命周期中只承担第 3–5 段（设计实现 → 版图签核 → 出带包）。 第 1 段（需求冻结）我们提供模板与流程并要求签字；第 2 段由需求架构工作台覆盖；第 0/6/7/8 段由客户或伙伴承担，我们不承接，也不对其结果负责。 封测验证（第 6 段）当前为空白，我们明确不自建产线，采用委托 + 伙伴模式——这也是「0 真值」的根因，由 T2 部分补上。

补完整项目链的成本远超 1000 万，且不是我们的护城河。 生命周期评估从另一个方向撞出了与 §1.5 相同的结论，说明该生态位选择是经得起交叉验证的。

3. 市场与切口重算

原 BP 用 EDA 软件市场规模做 TAM。本版增加一层成本结构倒推，因为它直接指向我们的定价能力：

若硅光模块 79.9% 的成本在封装测试与耦合对准，而设计决策（耦合容差、间距、端口布局）能显著影响这部分成本 ⇒ 设计侧工具的价值锚定在八成的成本池上，而不是一成多的芯片成本池上。

3.4 生态开放：定位为获客引擎，不是研发外包

开源是我们的形态，但「开放任务给生态并行做」的第一目标应是获客与真值，不是省研发人力——因为 `users=1`、真实访客≈0，开放 ≠ 有人接。而在 EDA 圈，来提 PR 的工程师往往就是潜在使用者，一个 PR 比一条冷线索值钱。

一个反直觉判断：没钱的时候开放「重活」是白 open——荣誉只能吸引学生与爱好者。现阶段应优先开放高荣誉感、低工作量任务（破壁者徽章、对抗题、语料）；要让第 2/3 层真正跑起来，需从融资中单列一小笔 bounty 现金池。

🔴 最大风险：假绿（自证桩的批量生产）

外部贡献者「自己写代码 + 自己写 smoke 证明自己对」= 典型的自证桩，正是 52 道锚里 25 个的老病，而外部贡献会成批生产这种东西。

规避机制只有一条：判据先于代码，且判据由 maintainer 写。 贡献者写实现，我们写判据——与「AI 出题、物理定律判卷」完全同构：生态出题（写代码），锚判卷。

硬要求：没有验收判据的任务不许发布；判据必须含反向测试（扰动必须响，同判据 D 思路）。

做什么① 多目标权衡：出 Pareto 前沿而非单一排序 ② 需求入口：自然语言 / 规格表 → 结构化需求 → 提案 ③ 扩锚覆盖至 S8（S7 已接入） ④ 预留「可封装性」维度（T3 产出后接入） ⑤ 红蓝队分离：启用 LLM 生成器（蓝队）+ 新增红队自动出题攻击
🔴 红蓝队纪律「审核」有两种，只能把第二种给 LLM：❌ 判 PASS/FAIL → LLM 由此进入判决路径，破最核心红线；✅ 找可能错的地方（出题 / 攻击） → 属生成侧，可以给。⇒ 架构为 蓝队生成 / 红队出题攻击 / 锚裁判（死标量）/ 人终审 四层，红队不判对错，只扩大被检验的覆盖面。代码已给出答案：`llm_proposer.py:66`「只出参数，不判对错（判决在锚管线）」；`run_proposal_compiler_smoke.py` 有源码级断言「红线：LLMProposer 零 PASS/FAIL 判决逻辑」
🔴 假独立陷阱红蓝若同源模型则共享偏见 ⇒「第二意见其实是同一个脑子」——这是判据 D 的组织版。⇒ 须不同模型 / 不同提示 / 不同数据源，且红队有效性须由锚标定、不可自评
红队也要被证伪命中率 = 被锚确认的真实缺陷数 ÷ 出题数（死标量）。否则红队自身退化成新的自证桩
终止条件须显式设定：轮次上限 / 命中率阈值 / 时间预算，三者至少其一，防无限抬杠不收敛
交付物需求→架构工作台（WebUI）+ 结构化需求 schema + 多目标权衡报告（含逐案锚证据）
可证伪验收① 同一需求下改变成本权重，Pareto 前沿必须位移（防常数假绿，同判据 D 思路）② 任一候选必须带逐案锚证据，无证据者不得进入 ranked 列表 ③ 域外候选（违反功率预算）必须被剪枝，不得进入排序
🔴 不做不让 LLM 决定架构；不让 AI 跳过判卷直接给结论
为什么便宜核心引擎已存在且有 CI 守护，本期是升级不是新建——这也是它能放在最前面做的原因
