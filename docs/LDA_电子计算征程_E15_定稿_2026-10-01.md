# LDA 电子计算征程 · E15 端到端误差预算链（设计定稿）

> 日期：2026-10-01 · 阶段：**E15（D-178 定稿 → D-179 实现 → D-180 验证）**
> 上游：E7 寄生（D-157）· E8 失配（D-158）· E9 规模（D-159）· E13 输运（D-170…D-172）· E14 外围（D-174…D-176）

---

## §0 一句话

E1–E14 每一段都给了**单点误差**，但**从未合成过**；且口径互不相同（相对 % / σ / LSB）、
性质未分类（系统性 / 随机 / 有界）。本段把这些接成**一条链**，产出两件东西：

1. **「这颗阵列实际有几个有效位」** —— 一个数；
2. **「给定精度目标，最大能做多大」** —— 一条曲线（精度 vs N），并泛化 E9 的规模上界。

## §1 缺口取证（为什么必须做这一段）

### 1.1 四类误差各自存在，但**无人合成**

| 误差源 | 已有能力 | 接口（实测验过） | 口径 |
|---|---|---|---|
| 互连 IR drop | E7 `ir_drop_report` | ✅ | **相对 %**（`max_rel_err` 最坏列 / `rel_err_per_col` 逐列） |
| 互连 sneak | E7 `sneak_report` | ✅ | 比例倍数 |
| 器件失配 | E8 `mc_output_error` | ✅ | **随机 σ**（`sigma_rel` / `mean_rel` / `p95_rel`） |
| 行驱动负载 | E14 `row_system_error` | ✅ | **相对**（按行增益离散） |
| 权重/输入 DAC | E14 `dac_static_report` | ✅ | **LSB**（`max_abs_err_lsb` · `inl_lsb_max` · `dnl_*`） |
| 输出 ADC | E14 `sar_error_report` | ✅ | **LSB**（`max_err_lsb` · `all_within_1lsb`） |
| 理想量化 | E3 `quantize_uniform` | ✅ | **LSB** |

⇒ **客户问「你这颗阵列有几个有效位」，此前无人能答** —— 不是没人算，是**没有统一口径把四类合起来**。

### 1.2 缺口的三层性质

1. **口径层**：一半是相对 %、一半是 σ、一半是 LSB。**三者不可直接相加**。
2. **类型层**：系统性确定项（IR drop / 行负载 / 有限增益）**不该用 RSS**；
   随机项（失配 σ）**不该用代数相加**；有界项（量化 / INL）**不该当随机项**。
   ⇒ **简单相加是错的，全用 RSS 也是错的** —— 这正是本段的技术核心。
3. **框架层**：E9 `max_scale_for_budget(budget_rel_err, ...)` **已是「给定预算反解 N」的框架**，
   但它只吃一个数（实际是 **IR-drop-only** 预算）⇒ **接口天然可泛化**，本段把它扩成**全链预算**。

### 1.3 提前发现的**口径陷阱**（本段必守）

E9 `max_scale_for_budget` 内部用的是 `row_line_profile(...)["avg_rel_err"]`（**全列平均**＝ MVM 平均输出误差），
而 E7 `ir_drop_report` 的主字段是 `max_rel_err`（**最坏列**）。

🔴 二者**不是同一个量**（E9 通则 1 已登记：口径不同 ≠ 模型错）。
⇒ **本段的 IR drop 项一律取 `avg_rel_err`**（与"输出精度"与 E9 同口径），
并在报告里**同时披露** `max_rel_pct`（最坏列）作诚实补充。**不许混用。**

## §2 架构选型

新增单一模块 **`lda/lda_l2/ecore/budget.py`**（ecore 第 19 个模块 · 能力清单 18 条）。
**不新增任何求解器** —— 全部数据来自既有模块的公开接口（**只读消费，不复制公式**）。

### 2.1 口径桥（口径层）

| 函数 | 定义 | 依据 |
|---|---|---|
| `lsb_to_rel_pct(bits)` | `100 / 2**bits` | 1 LSB 相对**满量程**的百分比（k bit ⇒ 满量程 = 2^k LSB） |
| `rel_pct_to_lsb(pct, bits)` | `pct * 2**bits / 100` | 上式的逆 |
| `output_effective_bits(rel_pct)` | `log2(100 / rel_pct)` | 「输出有效精度位数」（🔴 **非 IEEE ENOB**，见 §6） |

🔴 **自洽锚**：`output_effective_bits(lsb_to_rel_pct(k)) == k`（∀k）——
这是本段最干净的 golden：**自己与自己的定义必须闭合**，可独立手算。

### 2.2 误差项数据结构

```python
ErrorTerm = {"name", "category", "rel_pct", "source", "note"}
# category ∈ {"systematic", "random", "bounded"}
```

### 2.3 三分类合成律（类型层 · **本段核心**）

| 类别 | 成员 | worst 贡献 | typical 贡献 | 依据 |
|---|---|---|---|---|
| **systematic** | IR drop · 行驱动负载 · 有限增益 | **Σ**（代数） | **Σ** | 确定项，不会互相抵消也不会被平均 |
| **random** | 器件失配 σ | **3σ_tot** | **σ_tot** | `σ_tot = √(Σσ_i²)`（独立随机变量 RSS） |
| **bounded** | 量化 · DAC INL/DNL · ADC ≤1 LSB | **Σ|b|** | **Σ|b|/√3** | 均匀分布 `U(−a,a)` 的标准差 = `a/√3` |

合成：
```
worst_pct   = Σ_sys      + 3·σ_tot            + Σ_bnd
typical_pct = Σ_sys      +   σ_tot            + Σ_bnd/√3
bits_eff    = output_effective_bits(worst_pct)   # 报告口径 = 最坏值（保守）
```

🔴 **两条设计取舍（显式声明）**：
1. **systematic 的 typical 也取代数相加**（不给它"打折"）—— 系统性项是确定的，
   "典型值更小"没有物理依据，**宁保守**。
2. **报告口径用 worst**（不给客户乐观数）；typical 只作参考并标注。

### 2.4 全链规模上界（框架层 · 泛化 E9）

```python
max_scale_full_chain(budget_pct, ...) -> int   # 二分：全链 worst_pct(N) <= budget_pct
```
- 与 E9 `max_scale_for_budget` **同框架**（二分 + O(N) 求解），只是判据从单一 IR drop 换成**全链合成**。
- 🔴 **一致性判据（G7）**：把除 IR drop 外的所有项关掉（`terms` 只留 IR drop），
  `max_scale_full_chain` **必须 ≡** `max_scale_for_budget`（同预算、同 `r_seg`/`g`）——
  这是「**不是另起一套模型**」的机器证明。

### 2.5 主导项分析

`dominant_term(terms, mode)` → 按 worst 贡献排序取最大者。
**这就是给设计者的行动指令**：主导项是谁，就该优化谁。

## §3 golden 设计（可独立手算 / 闭式）

| # | golden | 形式 | 为什么是 golden |
|---|---|---|---|
| 1 | **口径桥自洽** | `output_effective_bits(lsb_to_rel_pct(k)) == k` | 定义闭合，纯代数，**无需任何模块** |
| 2 | **退化闭式** | 只留一类误差 ⇒ 合成退化为该类闭式（3 种情形） | 合成律在边界上的**唯一正确值** |
| 3 | **下界性** | `worst ≥ max(单项 worst 贡献)` | 合成本质是叠加，单调性推论 |
| 4 | **有序性** | `worst ≥ typical` | 3σ ≥ σ，且 Σb ≥ Σb/√3 |
| 5 | **规模单调** | N ↑ ⇒ IR drop ↑ ⇒ `worst` 非降、`bits_eff` 非增 | 与 E7/E9 已实测的超线性一致 |
| 6 | **E9 等价** | 仅 IR drop ⇒ 与 `max_scale_for_budget` 逐值相等 | 泛化必须"退化为特例" |

| # | 判据 | 期望 |
|---|---|---|
| **G1** | 口径桥自洽：∀k∈[4,12]，`output_effective_bits(lsb_to_rel_pct(k)) == k` | rel ≤ 1e-12 |

## §6 诚实边界（本段最重要一节）

1. 🔴 **不叫 ENOB**。`output_effective_bits` 是**本项目自定义的"输出有效精度位数"**，
   口径 = `log2(100 / 最坏相对误差[%])`。**IEEE ENOB** 是 ADC 标准量（含噪声 + 谐波 + 直流非线性，
   由 FFT 谱定义）—— **本段不是那个量，不得张冠李戴**。
2. **只覆盖静态**：给定权重与输入的静态精度。**不含时序 / 动态 / 建立时间 / 采样率**。
3. **合成律是工程近似**：worst 用「Σsys + 3σ + Σbnd」是**保守工程口径**，不是严格概率保证
   （要严格需给出分布假设与卷积）；typical 的 `Σb/√3` 假设均匀分布。
4. **误差项来源均为公开典型量级占位**（非 PDK）；不含 LDD/halo/应变/量子修正；
   器件侧仍是 **DD 框架、常数迁移率**。
5. **不含**：时钟抖动 · 热梯度空间分布（E8 有列温梯，未纳入合成）· 老化 / 漂移 · 电源噪声。
6. **不报** TOPS / TOPS-W / fJ/op。
7. **保护性约束**：**不改** E7/E8/E9/E14 任何既有模块的默认值与公式（G8 守住）——
   本段是**只读消费 + 合成**，不重算、不替换。
