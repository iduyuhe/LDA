## 零、结论先行

这一阶段（3 个版本）做了 **四件**事，其中**只有两件是"新功能"**（QKD 信息论锚、D 赛道 CPO），
另外**两件是在补地基**（CI 门禁缺口清零、超市分类下沉）。

真正值得记住的不是加了多少东西，而是两个反转：

1. **最危险的缺陷不住在红灯里，住在绿灯下**。全量回归 97 条全绿时，研发生产链路的四赛道 17 个任务
   **从未进过 CI**（文档/注释/记忆三处都写着"进 CI 防回归"）。`run_system_types_smoke` 更是在 core 集里
   **从 M2 起就红着**。全绿是一种感觉，不是一种证据。
2. **用户要"筛选器"，答案是"先补标签"**。量化后发现现有字段根本筛不动
   （`system_type` 的 `link` 独占 53/75 = 70.7%）。若直接加控件，会交付一个筛不出东西的筛选器。

**下一阶段的排序建议（详见 §5）**：技术侧**只做收口，不开新战线**；把主要产能转到**商业侧零获客破局**。
理由：技术侧已越过"可被外部验货"的门槛，边际收益下降；而 `users=1 / orders=0` 是当前唯一硬约束——
**再强的验证体系，没人用就等于零**。

## 一、本阶段交付的四件事

### 1.1 QKD 安全密钥率信息论锚（方法学扩展）

| 项 | 内容 |
|---|---|
| 问题 | QKD 此前借**光子插损**判据判安全链路 —— 物理量错位：安全性的度量是**密钥率**，不是损耗 |
| 落地 | `lda/lda_design/qkd_engines.py`：decoy-state BB84 渐近下界（Lo–Ma–Chen 2005 公开公式）<br>`R = q·[Q₁·(1−H₂(e₁)) − Q_μ·f·H₂(E_μ)]` |
| 意义 | **LDA 第一类信息论类死标量锚**（此前只有光子损耗类 / 量子保真度类） |
| 护栏 | **Q-D67**：① 密钥率 ≤ 单光子贡献上界 ② 等效探测效率 η ≤ 1（漏算误纠错惩罚 / 错用 Q_μ 替 Q₁ 必突破） |
| 配套 | `SYSTEM_TYPES` 新增 `qkd_link`；`IM-QKD-FULL-LINK` 由 `link` 升级；golden 43→45 |

**诚实边界**：零新物理、判决纯死标量、LLM 不进判决路径 —— 但这是**公开公式 + 公开 datasheet 量级标定**，
不是本团队实测 QKD 系统。

### 1.2 D 赛道 `cpo_optical_io`（硅光 I/O 共封装）

| 项 | 内容 |
|---|---|
| 问题 | 既有 8 条 CPO 货架**没有一条判带宽密度**，而 CPO 的真实竞争维度正是**海岸线带宽密度** |
| 三锚 | `S-CPO-IL`（每通道插损）/ `S-CPO-DENSITY`（lane_rate ÷ pitch，纯几何）/ `S-CPO-BUDGET`（链路余量） |
| 核心 | **P-CPO 间距几何下界护栏** —— 与 D-67 **对称夹逼**：`le` 方向由 D-67 能量守恒下界防漏算损耗；<br>`ge` 方向由 P-CPO 防把间距写小虚报密度。**下界按耦合方式分档**（fau 125 µm = G.652 包层直径；<br>grating_array 10.3 µm = G.652 模场直径 @1550） |
| 证据 | `GC-CPO-OIO-16CH` 复现 **1574.8 Gbps/mm = 物理上界 1600 的 98.4%** ⇒ 护栏贴身，判据有效 |

🔴 **主动放弃一个判据：不判决能效 pJ/bit**。该量由电域 SerDes/DSP 主导，LDA 无电域锚，
拿光域激光功率比会低约 4 个数量级 ⇒ **恒过 = 必假绿**。只作规格标注，不进判决。
**这是本阶段最值得保留的一次自我否决。**

### 1.3 CI 门禁缺口清零（六处潜伏断裂）

| # | 断裂 | 性质 |

## 三、方法论沉淀（比功能更值钱的部分）

### 3.1 同步五处铁律（本阶段从"同步三处"升级而来）

改动任何一个条目库，**必须同时同步**：

1. 条目库本体（货架 / 锚 / 引擎）
2. CI 断言计数
3. **派生表**（定价 / 白名单 / 覆盖矩阵 / 方向映射）
4. **回归集登记**（core 或豁免表，二选一）
5. **对外账本计数**（README / CHANGELOG / 设计文档散文里的数字）

🔴 新增教训：**凡散文中描述代码实体的数字，都是会腐化的派生数据** —— 要么由代码生成，要么由 CI 校验。
本阶段已加判据 ⑪（扫描文档中的"N 应用域"与代码比对）。

### 3.2 护栏的三条验收纪律（本阶段被自己的错误反复验证）

1. **新护栏必须反向测试会响**（本阶段三次因反向测试不到位而重写判据）；
2. **判据要落在行为上，不落在标签上** —— 标签≠行为（v0.9.15 老教训，本轮再次印证）；
3. **护栏要先查清会命中什么再落断言** —— 只锁"N 应用域"不锁"N 赛道"，
   因为后者在历史文案里另有"4 赛道"表述，一刀切等于 5 会**误报**，而误报的护栏最终会被人关掉。

### 3.3 我自己在本阶段犯的错（记下来，不粉饰）

| # | 错误 | 处置 |
|---|---|---|
| 1 | 称 17 条货架"用户在目录里看不到" —— 实测 `DIR_SHELVES` 是**定制下单方向映射**而非浏览网格 | **读代码核实用途后再下结论**，别只看 grep 命中就推断语义 |
| 2 | 前端行为测试 2 条断言写错（关键词命中数 / 清空赛道后的域集行为） | 用真实数据核实后**改断言，不改判据** |
| 3 | 文档通篇写"20 应用域"，代码实为 24 | 改数字 + **加判据 ⑪ 防复发** |
| 4 | 误报 core 集有"ghost 条目不存在" | 复核后 5 个文件均存在（我的 disk 集合只扫了根目录） |
