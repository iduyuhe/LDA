## 一、诊断：老化干线是通的，新能力全在孤岛上

### 1.1 三组数字（这是「基础到底牢不牢」的客观答案）

| 指标 | 实测 | 读法 |
|---|---|---|
| 平均入度 / 中位入度 | **3.32 / 2** | 老一代模块**确实有分层**，不是散沙 |
| 入度 ≥3 的模块 | **29 / 72（40%）** | 主干脊梁存在：`dctrl`(16) `layout`(15) `dsynth`(15) `dcell`(12) `dplac`(11) `parasitic`(11) `energy`(11) `mosfet`(11) |
| 零入度模块 | **21 / 72（29%）**，占 **24% 代码量**（7,541 行） | 这 21 个只被自己的门禁调用 = **能演示，不能用** |

### 1.2 关键发现：21 个孤岛里有 12 个是我们最近 11 轮的成果

```
dcnet  ddroute_grid  dhdlib  dinrow  dmacro  dpathfinder
dpgrid  dproc  dpvt  dscale  dwallrr  dwidth
```

（E45 之后的节点参数化、HD 库、DFF、单元内 DRC、电源网格、多角 PVT、规模上探、宽度扫描、行内布线、破墙、路径搜索、IP 集成）

**这句话必须直说**：最近十一轮我们做的每一件事，都通过了门禁、都发过版本、都有实测数字，
**但没有一件进了主链**。它们被验证了，却没人调用它们。

这不是「质量差」，是**机制问题**：每轮的模式是「新模块 + 新门禁 + 发版」，
门禁成了唯一的消费者。E55 修的那个「单元内部图形」问题，本质也是这个机制的症状 ——
模块之间缺检查面，因为模块之间**没有真实的调用关系**。

### 1.3 第二条：数字后端没有端到端干线

`soc_flow`（882 行，唯一像流水线的模块）服务的是**模拟/存算阵列链**
（器件 → 规模 → 层栈 → 布局 → DRC → LVS → GDS → 报告）。

数字后端（`dcells` → `dpnr` → `ddetail` → `ddrc_lvs` → `dsignoff`）**没有任何一条串起来的链**。
所以「综合→布局→布线→签核」这句话目前是**四个并列模块**，不是一条流程。

### 1.4 第三条：数据模型重复定义

全包 **29 个 class、分布在 13 个模块**里各自定义数据类型（`drtl` 一家 12 个）。
没有一份「网表 / 单元 / 引脚 / 版图 / 寄生」的公共模型 ⇒ 每接一次就要写一次转换，
这正是孤岛难接的根因。

### 1.5 一条自我修正（口径纪律）

本诊断的**第一版算错了**：脚本只认相对导入，漏掉 `from lda_l2.ecore import x` 这类绝对导入，
把零入度虚高到 **62 个 / 86%**。修正解析后是 **21 个 / 29%**。
—— 记在这里，因为「根因结论必须能复现」本身就是纪律（见 §5）。

## 二、什么叫「基础」：四个可机核的定义

不谈感觉，只谈能被门禁判定的东西。

| 代号 | 基础项 | 定义（可机核） | 现状 |
|---|---|---|---|
| **B1** | **统一数据模型** | 一份 `lda_l2/model.py`：`Net` / `Pin` / `CellView` / `Instance` / `LibArc` / `Layout` 六类；**全包只此一份**，其余模块通过适配器进出 | 无（29 个 class 分散） |
| **B2** | **标准格式层** | Liberty / LEF / DEF / Verilog 子集解析与写出；**解析器只依赖标准库**（不引第三方解析框架） | 零支持 |
| **B3** | **端到端干线** | 一条真实调用链：`Verilog → 综合 → 布局 → 布线 → DRC/LVS → 时序 → DEF`，**每段都用上一段的输出**（不是各自重算） | 无（四个并列模块） |
| **B4** | **对拍框架** | 同一输入跑「我们 vs 开源参考」，逐项差异表；差异超界必须有归因字段 | 无 |

**为什么是这四项、不是别的**：
- B1 决定「加新能力要不要重新写转换」⇒ 决定**复利**
- B2 决定「能不能跟外部对话」⇒ 决定**可验证性**
- B3 决定「四个模块到底是不是一条流程」⇒ 决定**它是不是工具**
- B4 决定「凭什么是你说得对」⇒ 决定**科学性**

其余（CTS、器件模型、优化环）都是 B1–B3 之上的一层皮，**基础不牢时加它们只会新增四个孤岛**。

## 三、复利怎么度量（三个指标，可做成门禁）

「复利」不能当口号，要能算。

| 指标 | 定义 | 现值 | 目标 | 对应基础 |
|---|---|---|---|---|
| **R1 零入度占比** | 零入度模块 / 全部模块 | **29%** | **≤12%** | B1 + B3 |
| **R2 入度中位数** | 全包模块入度中位 | **2** | **≥3** | B1 |
| **R3 新模块首版有下游** | 新模块发布当轮是否已有**非门禁**消费者 | **0%**（近 11 轮全无） | **100%** | B3 |

**R3 是最狠也最有用的一条**：它直接禁掉「再造一个孤岛」。
实现方式：新模块的提交必须同时给出「谁调用它」的结构性证据（AST 可见的 import + 真实调用），
否则门禁报红。判据写法与既有 `reachability_registry` 同族，不新造机制。

## 四、自主可控：三分表（用 / 借 / 自研）

用户要求「充分用成熟方法，但自主可控」。把它落成三档，每档有明确判据：

| 档 | 含义 | 具体内容 | 判据 |
|---|---|---|---|
| **① 可直接依赖** | MIT/BSD/Apache 许可、可替换、不进判决路径 | `numpy`（BSD）、Python 标准库；将来可加 `lark`（MIT，做语法） | 许可证白名单机核；且**移除后仍能跑**（降级路径存在） |
| **② 借规范与思想，不借代码** | 用公开标准与公开算法的**描述**自行实现 | Liberty/LEF/DEF 语法规范 · NLDM 查表插值 · Elmore 延迟 · AWE/PRIMA 降阶思想 · Lee/Mikami-Tabuchi 迷宫路由 · 模拟退火/解析布局 · 矩匹配 | 代码仓库内**零第三方实现体**；只在注释与文档里引出处 |
| **③ 必须自研（不可替代）** | 判决路径与证据体系 | golden/candidate 对拍 · 判据与反向探针 · 账本三分类 · DRC/LVS **判定器** · 豁免与边界声明 | 一旦引入外部实现，判决独立性即失效 ⇒ **永久自研** |

**关键判断（这条最容易走偏）**：**格式解析可以借规范，判定器不能借实现。**
Liberty 是公开文本格式，照着规范写解析器不损失任何自主性；
但如果拿 OpenSTA 当 golden 判我们自己算得对不对，那「独立」就没了 —— 只能当**对拍参考**（B4），
且必须在报告里写清「差异来自何处」，不能写成「我们通过了商业工具的检验」。

## 五、调度：四步，每步一个「出口判据」

依赖关系是 **B1 → (B2 ∥ B3 前半) → B3 → B4**。注意 B1 先行不是官僚流程，而是
**用第一个任务把后面三个的接口定下来**（避免 B2 解析出的 Liberty 又要为 B3 改一次格式）。

| 步 | 内容 | 出口判据（一句话，可机核） | 依赖 | 预估 |
|---|---|---|---|---|
| **S1** | **B1 数据模型 + 适配器**（不动既有模块，只加 `to_model`/`from_model`） | `adapt(INV_X1)` 与 `adapt(INV_X1_HD)` 输出**同构**模型；往返 `from_model(to_model(x))` **逐位一致**；三者（模型/dcells/dhdlib）双射 | — | 4–6 版 |
| **S2** | **B2 Liberty 子集**（cell/area/pin/cap/timing 表），输出直进 B1 模型 | 读一份公开 PDK 的 .lib，**逐 cell 逐字段回读一致**；未知语法**报错不静默**；`master` 单元数与源文件相等 | S1 | 3–5 版 |
| **S3** | **B2 LEF/DEF + Verilog 子集**；同时开始 **B3 干线**（先把「综合→布局→布线→DRC」用现状模块串起来） | LEF/DEF 往返逐位一致 + OpenROAD 能读回；干线跑通一份 ISCAS/EPFL 网表，**每段断言「吃的是上一段的输出」** | S1（S2 可并行） | 6–9 版 |
| **S4** | **B4 对拍框架** + 首个对拍对象（面积/线长/WNS 与 OpenROAD/OpenSTA） | 逐项差异表产出，每项有「超界/未超界 + 归因」字段；差异表可复现（同输入同结果） | S3 | 4–6 版 |

**为什么 S3 在 S2 中间就开始**：干线是骨架，越早立越能暴露「哪些模块其实接不上」。
S2 只做 Liberty 一个格式，S3 同时干 LEF/DEF 与串链，两者并行不冲突（都吃 B1 模型）。

**并行度**：单线程推进时按 S1 → S2 → S3 → S4；
若要多线并行，可拆成「S1 完成后：A 线做 B2 格式、B 线做 B3 干线」两条，互不改同一文件。

## 六、第一刀（具体到文件与判据）

**S1 的第一步不是写代码，是定「六类对象的最小字段集」**，因为字段定了才不会返工。

```
lda/lda_l2/model.py
  Pin(name, direction, layer, rect_nm, cap_ff)          # 引脚：几何 + 电学
  LibArc(from_pin, to_pin, sense, cell_rise/fall, ...)   # 时序弧：NLDM 表 or 一阶闭式
  CellView(name, w_nm, h_nm, pins, arcs, rail_y, obs)    # 单元视图：LEF 与 dcells 的共同抽象
  Instance(cell, x_nm, y_nm, orient)                     # 实例
  Net(name, pins=[(inst, pin)], ...)                     # 线网
  Layout(die_w_nm, die_h_nm, instances, nets, shapes)    # 版图：DEF 与 dpnr 的共同抽象
```

**判据（S1 出口）**：
1. `model.adapt(dcells.CELLS["INV_X1"])` 与 `model.adapt(dhdlib.build_inv_hd())` 都能得到 `CellView`；
2. 两者的 `pins` 名字集合、`rail_y`、`w/h` 逐位可对（不同规则集下数值不同，但**结构同构**）；
3. `from_model(to_model(x))` 与原对象**逐位一致**（往返双射，不许有「顺手归一化」）；
4. **既有模块零改动**：`git diff` 里 `dcells.py`/`dhdlib.py` 不在改动清单内。

第 4 条是这次的关键纪律：**用适配器，不动实现**。改实现的代价是 62 道 ecore 门禁全要重跑重核，
而且极可能改坏 E40–E55 的既有数字。

## 七、防止「再造一个孤岛」的三条纪律

1. **新模块首版必须给出下游消费者**（R3）：没有就并入既有模块，不许新建文件。
2. **每轮收尾加一次依赖图体检**：把 §1.1 的三组数字（平均/中位/零入度）当发布指标之一，
   零入度只在**顶层**（如 `soc_flow`）和**纯库 API** 上允许。
3. **格式层不引第三方解析框架**（若确需，须满足「移除后可降级运行」并登记在①档）。

## 八、与三阶段战略的关系（不冲突，是前置）

- 战略文档的阶段一 = 「接通外部世界」= **本文 S1+S2+S3**
- 战略文档的阶段二 = 「上规模」= 依赖 B1（数据结构重构）与 B3（真干线才能算吞吐）
- 战略文档的阶段三 = 「拿证据」= 本文 **S4**

所以这份规划不新增路线，它只是把阶段一**拆到能开工的粒度**，并补了战略文档缺的那一条：
**先让新能力接回主链，再谈新能力。**
