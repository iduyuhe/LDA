# LDA 零成交根因取证方案

> 版本：v0.9.1 · 2026-08-30 · 钉子序列：审计收尾后第一商业动作
> 作者：AI（杜先生定调执行）

## 0. 为什么做这件事

生产实测硬数据：**真实用户 1 / 真实订单 0 / 58 货架零成交**。这是商业侧当前的**第一事实缺口**——它锁死了后续所有动作的优先级：

- P1-1b 定制需求产品化（不知道客户要什么）
- P1-2 定制报价自动化（没有成交样本可定价）
- D3 货架扩张（零成交下扩张=在真空里扩张）

**在归因清楚之前，任何商业侧动作都是盲打。** 本方案目标是用现有被动证据，先回答"58 货架为什么零成交"，把方向性信号捞出来。

## 1. 核心问题（要回答什么）

| # | 问题 | 对应证据 |
|---|---|---|
| Q1 | 站点有没有流量？量级多少？ | nginx 日志总请求 / 独立访客 |
| Q2 | 流量从哪来？ | nginx referer / UA |
| Q3 | 流量看了什么？ | nginx 路径（/insights.html、/api/shelf、/api/purchase/*） |
| Q4 | 有没有人走到"对公购买申请"？ | purchase_requests.json + nginx /api/purchase/request 调用 |
| Q5 | 那 1 个真实用户是谁、干了什么？ | store.json 用户/订单轨迹 |

## 2. 待证伪的假设

| 假设 | 含义 | 若成立，下一步 |
|---|---|---|
| **H1 没流量** | 站点几乎无人访问 | 渠道 / SEO / 公众号引流优先（D3 前先曝光） |
| **H2 有流量无转化** | 来了但不看购买 / 不提交申请 | 落地页价值主张 / 购买入口问题 |
| **H3 有意向流程断** | 提交申请但没转账 / 没审批 | 支付 / 信任 / 人工瓶颈（R16） |
| **H4 产品市场错配** | 来的人不是目标客户 | 定位 / 定价 / 货架方向问题 |

## 3. 取证数据源（被动证据，无需改代码）

| 层 | 源 | 生产位置（115.191.20.92） | 提供 |
|---|---|---|---|
| 流量层 | nginx access 日志 | `/var/log/nginx/access.log`（或站点 server 块自定义路径） | 访客 IP、时间、路径、referer、UA |
| 转化层-用户/订单 | WebUI 数据文件 | `/opt/lda/dist/store.json`（`STORE_PATH`，`store.py:38`） | users / orders / config |
| 转化层-购买申请 | 对公申请文件 | `/opt/lda/dist/purchase_requests.json`（`PURCHASE_PATH`，`app.py:96`） | 申请列表及状态 |

> **关键约束**：WebUI 全代码**无任何前端埋点、无应用层访问日志**（已 grep 确认 analytics/track/visit 零命中）。因此"用户看了哪个货架、在哪个环节流失"只能靠 nginx 路径做**粗粒度推断**，无法做细粒度漏斗。

## 4. 取证步骤（连生产只读拉取）

1. `paramiko` 内联密码连 `root@115.191.20.92`（密码即用即弃，不落盘）
2. 拉 nginx 日志 → 统计：**总请求数、独立访客（去重 IP）、Top10 路径、referer 来源分布、/api/purchase/request 调用次数**
3. 读 `store.json` → 用户总数、**真实 vs 测试邮箱分布**、订单数、config 定价生效情况
4. 读 `purchase_requests.json` → 申请条数及状态（pending / approved）
5. 还原那 1 个真实用户：注册时间、邮箱域、是否产生订单 / 申请

## 5. 解读决策树（怎么判断主因）

```
nginx 总请求 < 100（或独立访客 < 10）
   └─> H1 没流量：优先渠道/曝光，暂缓产品化
nginx 有量 但 /insights.html、/api/shelf 极少
   └─> H1 / H4：落地页未被触达 或 人群错配
/api/purchase/request >= 1 但 orders = 0
   └─> H3 流程断：提交未转账 / 未审批（人工瓶颈 R16）
/api/purchase/request = 0 但 insights 有量
   └─> H2 价值主张 / 购买入口不明显
综合判定 → 输出主因 + 置信度
```

## 7. 诚实边界

- WebUI 当前无埋点；若 nginx 日志轮转丢失或未记录 referer，则**流量来源证据缺失**，须在结论标注置信度
- 样本极小（真实用户仅 1），任何结论都是**方向性信号**而非统计显著，须谨慎表述，不得夸大为"结论"
