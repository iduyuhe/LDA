## 1. 这张矩阵要治什么病

**病**：账本有 **538 道锚**、CORE 有 **333 个门禁**，但「**哪个锚被哪个门禁判决**」此前无人能答。

后果有三：
1. **新增锚可能"登记了但没人判"** —— 账本加了锚，门禁没跟上，靠全量 CI 的通用阶段兜底，一旦通用阶段退化就静默失守；
2. **改一个门禁时不知道会牵动哪些锚** —— 只能全量回归，成本高且看不出影响面；
3. **盲区不可见** —— 说「538 锚全绿」是真的（统一判决），但「其中多少有**专属**判据」没人知道。

**治法**：把「判据 × 锚」关系**机器化落表**，并把「专属覆盖数」变成**只升不降的棘轮**。

## 3. 矩阵结构（`lda/reports/anchor_gate_coverage.json` · 受跟踪 · 85,720 B）

**双向索引**：

```jsonc
{
  "anchors": {
    "B519": {"l1": true, "l2_gates": ["run_j5_qnet_smoke.py",
                                      "run_statistical_anchor_smoke.py"],
             "l2_count": 2, "l3": true},
    "B1":   {"l1": true, "l2_gates": [], "l2_count": 0, "l3": false}
  },
  "gates": {"run_j5_qnet_smoke.py": ["B519","B520","B521","B522", ...]},
  "blind_anchors": ["B1","B10","B103", ...],          // 415 条
  "ratchet": {"l2_min": 123, "l3_min": 65,
              "policy": "只升不降：新增锚必须补专属判据或显式登记为 L1-only"},
  "excluded_gates": {"run_k4_coverage_smoke.py": "判决覆盖矩阵本身；_band() 的号段标签不是锚判据"},
```

## 4. 🔴 建表过程中抓到的两个真问题

### 4.1 自我污染 → **排除面双向锁死**

新门禁 `run_k4_coverage_smoke.py` 自身有一个 `_band()`，里面写着 `"B100–B199"`、`"B1–B99"` 等**号段标签字符串**。锚号正则 `\bB(\d{3})\b` 会把 `B100` / `B199` 当成「该门禁覆盖了 B100 与 B199」⇒ **假覆盖**。

**处置不是「悄悄排除」**（那样会开出作弊口子），而是**双向锁死**：

| 侧 | 登记 |
|---|---|
| 生成器 | `EXCLUDE_GATES = {"run_k4_coverage_smoke.py": "判决覆盖矩阵本身..."}` |
| 门禁 | `_EXCLUDED = {"run_k4_coverage_smoke.py"}`（**独立写死，不 import 生成器**） |
| **G1 判据** | 两侧集合**相等** ∧ 长度 **== 1**（只许排除自身） |
| **G2 判据** | `core_smokes == gates_scanned + excluded`（计数自洽） |

⇒ 想偷偷多排除一个门禁，G1 当场红。

### 4.2 台账有条目、门禁无判据 → **补建 E8**

K0 台账从建立起就有 `G-K-6` 条目，但 K0 门禁的 E 组只覆盖 **G-K-2 / 3 / 4 / 5 / 7 / 8** —— **独缺 G-K-6**。

这本身就是「**覆盖盲区**」的活样本：**台账登记了缺口，但没有判据看守该缺口的关闭**。

**K4 补建 E8**：

```
E8 G-K-6 已结算：矩阵存在 ∧ 三层覆盖自洽 ∧ ratchet ≥ 硬编码下限 ∧ 锚键集 ≡ 账本
```

台账 `G-K-6` → **`settled`**（新增 `matrix_table` / `matrix_summary` / `matrix_ratchet` / `matrix_gate` / `matrix_generator`）；`items_settled` 4 → **5**；K0 判据 **28 → 29**。

> **通则（第 4 例）**：**关闭一个缺口，必须回头检查「谁在看守这个缺口的关闭」**。前 3 例是「旧判据被打反」，本第 4 例更隐蔽 —— **判据根本不存在**。

## 6. 怎么用这张矩阵

### 6.1 我要改某个门禁，会影响哪些锚？

```bash
python -c "import json;d=json.load(open('lda/reports/anchor_gate_coverage.json',encoding='utf-8'));print(d['gates'].get('run_j5_qnet_smoke.py'))"
```

### 6.2 这个锚有几个门禁在看？

```bash
python -c "import json;d=json.load(open('lda/reports/anchor_gate_coverage.json',encoding='utf-8'));a=d['anchors']['B522'];print(a['l2_count'],a['l2_gates'])"
```

### 6.3 补盲排期（SOP）

1. 从 `blind_anchors` 按号段取一批（建议先做 **E 实证 10** 与 **S 系统层 13** —— 数量小、语义强）；
2. 为该批锚补 bespoke 判据（**不是重复 harness 判决**，而是加「跨源对拍 / 残差形态 / 反向探针」这类**独立角度**）；
3. `python scripts/k4_coverage.py --write` 重生成；
4. **上调 `ratchet.l2_min` / `l3_min`**（生成器常量 `L2_MIN` / `L3_MIN` + 门禁 `_HARD_L2_MIN` / `_HARD_L3_MIN` 两处同步 —— **棘轮只升不降**）。

> 🔴 **不许**把 `ratchet` 下调来让门禁过红。

### 6.4 什么时候必须重生成

```bash
# ① 新增/删除锚（账本变化） ② 新增/删除 CORE 门禁 ③ 门禁里增删锚号引用
python scripts/k4_coverage.py --write
python lda/run_k4_coverage_smoke.py    # 25 判据必须全绿
python scripts/k0_audit.py --write     # K0 快照含 ci_core ⇒ bump/加门禁后必重生成
```

**忘记重生成会怎样**：A4（锚键集）、B1（逐字节）、G2（计数自洽）**当场红**。

## 7. 诚实边界

1. **L2 是「源码显式提及」的下限** —— 动态拼接锚号（`f"B{n}"`）、纯 harness 判决、**注释里的提及均不计入**。
2. **盲区 415 不是缺陷申报**，而是**补盲排期的输入**；本档只建立可见性与棘轮，**不虚增判据**（章程 K4「候选锚 0」）。
3. 号段分班按 **B 号数字段**（B1–B99 / B100–B199 / …）+ `E` + `S`，不是按蓝图档位（J1–J5）；档位维度归 K3 表与各档门禁。
4. 既有 `lda/run_anchor_coverage_matrix.py`（T-9 · 2026-09-06）是**器件宿主维度**（33 类 × 52 锚，人工维护 `ANCHOR_HOSTS`）且**未入 CORE** —— 与本矩阵**维度不同、不互相替代**；本档未改动它。
