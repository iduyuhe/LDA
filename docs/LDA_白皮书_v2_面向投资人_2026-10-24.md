## 0. 一页摘要

**LDA 是什么**：一个开源的、Agent-native 的光子/量子芯片**设计期签核平台**。
它不画版图、不做电磁仿真替代品，它做的是——**为设计链上每一个关键数字，提供一条可被外人当场证伪的验证路径**。

**已建成什么**：

| 项 | 实测 | 含义 |
|---|---|---|
| 签核锚（anchor） | **541** 道 | 每道锚 = 一个关键设计量 + 闭式物理律 golden + 方法学独立的 candidate + 容差 |
| 严格独立判决 | **519**（95.93%） | 候选由**另一套方法**算出，而非取用 golden |
| 其中带残差证据 | **505** | 两条路径给出不同但接近的值 —— 残差本身就是证据 |
| 常驻 CI 门禁 | **350** 道 | 每道锚至少被统一判决覆盖；改错会当场变红 |
| 专属判据覆盖（L2） | **523 / 541** | 有**为该锚单独写的**判据，不是只有统一判决 |
| 多重覆盖（L3，≥2 道门禁） | **70** | 单点失效不会静默通过 |
| 公开 API 端点 | **158** | 严格 JSON（其中 60 个需登录），可程序化调用 |
| 全量复算耗时 | **约 5 分钟** | 外人可以自己跑一遍，不需要信我们 |

**一句话**：这不是"我们能算 541 个物理量"，而是"**这 541 个量里，有 505 个的两条独立路径给出了不同但一致的数值，其余 14 个我们如实标注为弱证据**"。

**差异在哪**：业界通行的"签核"是**结论**（PASS/FAIL 由闭源工具给出），LDA 交付的是**过程**——
golden 是物理律闭式，candidate 必须来自另一套数值方法，判决由死标量比对完成，**大模型不参与判决**。
任何人可以重跑、可以对拍、可以指着一个锚说"你这条不对" —— 而我们要么修，要么公开反驳，不能沉默。

**现在什么阶段**：设计侧闭环完成（含量子六层能力链、光子域 153 个能力模块）。
**尚缺**：流片实测回流、真实 foundry deck 数据（NDA）、线路级浮点仿真、封装几何。

## 1. 问题：光/量芯片设计里的"可信度赤字"

光电子与量子芯片的设计工具链，长期存在三个结构性失真。它们不是"精度不够"，而是**声明与证据之间没有机器可查的链**。

**失真一：性能宣称 ≠ 可复算。**
一个链路预算表里的插入损耗、一个量子器件的协同度，通常是某个仿真器的输出。
工具换了、版本升了、参数默认值变了，数字就变了 —— 而**没有任何机制记录"这个数当初凭什么"**。

**失真二："通过" ≠ "验证"。**
最典型的失效模式是**假独立**：所谓"独立验证"的候选实现，实际只是把 golden 的公式抄了第二遍。
此时 `|candidate − golden| ≡ 0` 恒定成立，判据永远绿 —— 它测的不是物理，是两次调用的一致性。
这个坑在本项目里真实发生过，并留下了可复算的血案（见 §3.2）。

**失真三：闭源签核不可审计。**
设计方拿到的是 PASS/FAIL，拿不到"为什么"。在需要向投资方、客户、代工厂解释"这个设计能不能做"的场合，
**一个不可审计的 PASS 和一个不可审计的 FAIL 价值相同** —— 都无法被第三方复核。

三者叠加的结果：**芯片设计里最贵的东西不是算力，是"这个数字可以被人相信"**。

## 2. 解法：把"可证伪"做进架构，而不是写进文档

LDA 的四条设计选择，每一条都是为了**让错误的声明无法存活**，而不是为了让数字好看。

### 2.1 golden 必须是物理律闭式，不能是另一个仿真器

如果 golden 本身是某个数值解，那"两条路径一致"只说明两个仿真器都收敛到了同一个离散误差里。
所以 LDA 规定：**golden = 可解析写出的物理律**（闭式解 / 解析极限 / 精确组合量）。
候选侧才允许是数值方法（FDTD、FEM、RK4、Monte Carlo、级数求和……）。

### 2.2 candidate 必须方法学独立，且这件事要有机器证据

"独立"不是一句形容词。平台对每道锚计算**独立性证据**，并分成可核查的档位（§3.2）。
不满足时，`run_harness` 直接**断言失败、报告生成不出来** —— 不是警告，是拒绝出报告。

### 2.3 判决路径里没有大模型

平台大量使用 AI 做工程流水线（代码生成、门禁编写、审计），但**判决一律是死标量的比对**：
`|candidate − golden| ≤ tol`。大模型可以写判据，**不能判结果**。
这条边界是产品的核心资产之一：它让"AI 提效"不会污染"验证可信"。

### 2.4 声明与验证必须分开，且各自有机器面

一个模块"能做某件事"（声明），和"这件事被验证过"（验证），是两件不同的事。
平台为此把覆盖分成互相独立的两档（§3.3），并**禁止把纪律级覆盖并入数值级覆盖** ——
因为混在一起会让独立率虚高，那是虚报而非改进。

## 3. 证据

以下全部为现场现算，命令见 §9。

### 3.1 账本：541 道锚，95.93% 严格独立

| 分类 | 条数 | 定义 |
|---|---|---|
| `strict_independent` | **519** | 候选由方法学独立的另一路径算出，且通过容差 |
| `degraded_ordinal` | **3** | 只能给出**量级/序关系**参考，不构成定量验证 |
| `self_consistent_stub` | **19** | 自证桩：只有 golden，没有独立候选（**如实登记，不算验证**） |
| 合计 | **541** | 独立率 = 519 / 541 = **95.93%** |

**为什么要把 3 和 19 单独列出来**：因为把它们算进"验证通过"是最容易做的事，也是最没有价值的事。
一个把 19 道自证桩混进"100% 通过"的账本，在尽调时一文不值。

### 3.2 独立性证据分档：505 有残差，14 靠扰动响应

519 道严格独立里，证据强度并不相同：

| 证据档 | 条数 | 它证明了什么 |
|---|---|---|
| `RESIDUAL_NONZERO` | **505** | 两条独立路径给出了**不同但落在容差内**的值 —— 残差本身就是"候选真在独立计算"的证据 |
| `PERTURBATION_RESPONSE` | **14** | 残差落在机器精度内（`|Δ| < 1e-12`），改用"候选对参数扰动有物理响应"来证明它真在算 |

**必须说清的两件事**：

1. **14 条是弱证据**。它只排除"候选跟着 golden 走"这一种最坏情形，**不证明方法学独立**。
   这句话同时写进了代码常量、对外账本的 `honest_note` 和本文档 —— 三处一致才算说清。
2. **一条真实血案**（`B10`，量子比特门时间）：候选是真的 4×4 Liouvillian 超算子 RK4 积分，
   但生产工作点上 `|L|·t ≈ 2.5e-4`，导致残差恒为 **1.11e-16**、且**与积分步数无关**（物理上不可标定）。
   旧版判据会把它误判成"假独立"，现行判据改用扰动响应才正确定性。

**一个反直觉的发现（值得单独说）**：外部读者若拿平台导出的报告 JSON 反算残差，会得到系统性错误结论。
原因是报告里的浮点只保留 **9 位有效数字**；对量级大的量（如 `B100 = 3.65647835e+16 Hz`，容差 `1e7`），
9 位有效数字的最后一位本身就有 `1e7`，于是 golden 与 candidate **在报告里必然显示相同**，
而真实残差是 `1e5~1e7`。**本项目自己在这上面错过两次**（先算出"87 条逐位相同"，实际只有 14 条）。
所以平台现在把**结论**（证据档）由生成端写进报告，不再让读者自己反算 —— 这也是本文敢写"505/14"的原因。

### 3.3 覆盖分档：541 有统一判决，523 有专属判据，70 有多重覆盖

| 档 | 条数 | 含义 |
|---|---|---|
| L1 统一判决 | **541 / 541** | 每道锚都进了 CI 的主判决 |
| L2 专属判据 | **523 / 541** | 有**为它单独写**的判据（不是靠统一判决兜底） |
| L3 多重覆盖（≥2 道门禁） | **70** | 单道门禁写错也不会静默放过 |
| 盲区（仅 L1） | **18** | 没有专属数值判据 |

**盲区不粉饰，但也不再被误读**：这 18 道锚**全部**有纪律级覆盖
（它们的元数据被全局纪律门禁按类断言，例如"自证桩必须登记不可锚理由"），
`blind_without_any_coverage = 0`。
所以准确的说法是"**这 18 道没有数值级专属判据**"，
而**不是**"这 18 道无人看守"。这两件事在旧版对外材料里被混成了一件事。

### 3.4 量子赛道：51 道锚，43 残差 / 8 扰动响应

| 项 | 实测 |
|---|---|
| 量子赛道锚（B473–B525） | **51** |
| 全部严格独立（`strict_independent`） | **51 / 51 = 100%** |
| 全部判决通过 | **51 / 51** |
| 证据：残差 / 扰动响应 | **43 / 8** |

注意 8/51 = **15.7%** 落在弱证据档 —— 这比光子域（6/444 = **1.4%**）高一个量级。
原因不是量子侧做得差，而是**量子器件的很多关键量在物理上不可标定**（见 §3.2 的 `B10`）。
这个差异本身是诚实的一部分：**不同物理域的证据质量天然不同，把两域混成一个平均分是耍流氓**。

### 3.5 光子域：153 个能力模块，12 个模块有成对实现

| 项 | 实测 |
|---|---|
| 能力模块（`lda_l2` 100 + `lda_agent` 53） | **153** |
| 其中"同模块内既有闭式、又有独立数值实现" | **12 个模块 / 23 对** |
| 这 12 个模块的专属门禁 | **12 / 12** 存在、**真调用**该模块、**且真在 CI 里跑** |

**为什么"成对实现"值得单独统计**：同模块内同时写出闭式与独立数值两条路径，等于作者已经把
golden 与 candidate 两半都写好了 —— 那是**天然的锚候选**。平台对此立了契约（三层判据：
门禁存在 → 真调用该模块 → 真在 CI 里跑），防止"写了一对实现但没人验"。

**同时如实说明一处结构事实**：光子域的 541 道锚中，**531 道**的 golden 实现集中在
`lda_harness`（70 个模块），能力模块**不直接产出锚**。这不是缺陷，是组织形态：
量子域的模块本身就是被判定对象，光子域的模块是设计期模型。两者纪律落点不同，不能互相套用。

## 4. 一个反直觉的结果：可锚性的射程是有限的

这是本项目最值得对外讲的一件事，因为它不是"我们做到了什么"，而是"**我们用数据证明了某条路走不通**"。

平台在连续多个版本里统计"每个版本新增多少锚"：

| 阶段 | 版本区间 | 版本数 | 净增锚 | **边际产出（锚/版）** |
|---|---|---|---|---|
| 量子传感器件（QS） | v0.9.216 → 227 | 12 | 24 | **2.00** |
| 量子六层（J1–J5） | v0.9.230 → 242 | 13 | 24 | **1.85** |
| 蓝图 v2（异质集成 / 码族 / 编译） | v0.9.259 → 267 | 6 | 3 | **0.50** |
| 之后（能力层 / 可观测性） | v0.9.270 → 281 | 12 | **0** | **0.00** |

四段**单调下降**，最后一段是**精确的零**。并且已逐版核对：**这 12 个版本的账本恒为 541 / 519**，
一格没动；同期交付的全部投入在"验证质量与可观测性"上。

**为什么边际会归零**（这是技术结论，不是营销话术）：

> **物理律闭式锚的射程到物理层为止。** 越往编译、算法、调度、系统集成层走，
> 可锚量趋近 0 —— 因为上层量往往不满足"两条独立数值路径都能给出可比较标量"这个前提。

平台把"不可锚"的判死归纳成三种形态，并逐条机器化留证：

| 形态 | 判据 | 实例（均已登记，可现算） |
|---|---|---|
| ① 两条路径**代数恒等** | 残差恒为 0，不构成判别力 | 表面阻抗的三种写法（定义式 / ρ/δ / Re(ρk)），12 组参数下最大相对差 **2.13e-16** —— 本质是同一个恒等式 |
| ①' 两路径都对但**差被淹没** | 路径差 ≪ 参数不确定度 | 动能电感：两流体 ≡ BCS，工作点差 **3.88e-08**，被 λ_L(0)±50% 的材料分散淹没 **1.29e7 倍** |
| ② 另一条路径**物理失效** | 差得很大，但错的那条不成立 | 20 mK 下两流体模型与 BCS 差 **1.563e+38 倍**（两流体 ∝ (T/Tc)⁴，BCS ∝ exp(−Δ/kT) ≈ 1.08e-46） |
| ③ **精确组合量** | 正确实现给出精确整数，残差恒 0，与自证桩不可区分 | 量子码族资源数 n/k 为整数、对距离分段常值 |

**形态 ② 是最危险的**：差得越大越容易被误当成"可锚证据"，而实际上另一条路径物理上根本不成立。

**对投资人意味着什么**：一个团队知道自己能力的**边界在哪、以及为什么在那**，
比多三个锚更能说明它不会在下一轮把钱烧在不可能的地方。
这也直接决定了我们的路线选择：**不再追锚，把资源投在"让已有 541 道锚被人相信"上**。

## 5. 产品形态与可交付性

**技术形态**

| 项 | 实测 / 事实 |
|---|---|
| 许可 | **MIT**（含全部判据源码，无 open-core 保留） |
| 部署 | 自托管单机；生产实例为 systemd 服务，Python 3.12，无外部数据库依赖（`db: not_configured` 亦可运行） |
| 接口 | **158** 个 HTTP 端点（严格 JSON，60 个需登录）；**27** 个可视化段 |
| 复算 | 全量 541 道锚约 **5 分钟**（单机）；覆盖矩阵与台账可逐字节复现 |
| 外部数据接入 | 支持从 foundry deck 注入真实工艺限值（`LDA_QUANTUM_DECK` / `LDA_FOUNDRY_DECK`），**只记 sha256、不记时间戳**，保证可复现 |
| 供应链 | 数值核自研，不依赖商用 EDA 授权；核心判决链无 GPL 依赖 |

**三种可交付方式**（尚未定价、不构成承诺）

1. **自助**：MIT 仓库自建，用自己的参数跑自己的设计。
2. **托管签核**：客户提供 deck 与设计参数，我们出具签核报告（含每道锚的 golden / candidate / 残差 / 门禁）。
3. **集成**：把 158 个端点接进客户既有流程（PDK 校验、设计规则回归、供应商对比）。

## 7. 不做什么（红线，写死）

- **不宣称流片**：本文全部为设计期签核，**不含任何硅/超导工艺实测数据**。
- **不宣称量子优势**：不做任何"量子优于经典"的性能主张。
- **不报能效/算力类指标**：不做 TOPS、fJ-op、能效比、良率承诺。
- **"规模"指版图容量**：文中涉及比特数/通道数的表述均指**设计可承载规模**，不是已制造器件数。
- **不替代代工厂签核**：本文不构成 DRC/LVS 的替代，也不构成流片放行依据。
- **不把弱证据当强证据**：`PERTURBATION_RESPONSE` 永远单独列出，不与残差证据合并统计。

## 8. 诚实边界（必读）

1. **设计期签核，非流片实测**：541 道锚验的是"两条独立路径一致"，**不是**"这个设计在硅上表现如此"。
2. **参数是设计示例量级**：取典型设计值，**非某一具体 PDK 的认证值**。
3. **505/508 那批"有残差证据"只说明两条路径给出了不同但接近的值，不说明两条路径都对。**
   若外部把它读成"505 已验证"，那是误读。
4. **14 条扰动响应证据是弱证据**：只排除"候选跟着 golden 走"这一种最坏情形。
5. **18 道盲区没有数值级专属判据**（有纪律级覆盖）。`blind_without_any_coverage = 0` 不改变这一事实。
6. **不为好看的数字删代码**：本版把此前不在扫描面内的 156 个公开函数纳入防腐烂检查，
   一次性暴露 2 条零引用。数字上升（95→97）是扫描面扩容，不是退化。
