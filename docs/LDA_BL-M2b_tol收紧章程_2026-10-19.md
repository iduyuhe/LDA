## 0. 一句话

BL 的缺陷面还剩两类：**注入 0 仍放行的 5 条** 与 **偏松（`|g|/tol<10`）22 条**（前者是后者的子集）。
本档用**可行性窗口法**逐条判定「能不能只靠收紧 `tol` 治好」：**14 条能，8 条不能** —— 不能的必须登记，不许硬压。

## 1. 判定方法（窗口法，不靠感觉）

对每条锚，`tol` 必须同时满足两条硬约束：

```
① 判据不许太松：   |g| / tol ≥ 10        ⇒  tol ≤ |g| / 10
② 候选必须真有余量：resid ≤ tol / 2       ⇒  tol ≥ 2 · resid
```

⇒ **可行窗口 `[2·resid, |g|/10]`**。窗口为空 ⟺ 候选精度撑不住更严的 `tol` ⇒ **不可靠收 tol 治**。
（本档实操把上界收紧到 `|g|/12`，给「golden 小幅变化」留 20% 缓冲，避免贴线翻红。）

## 4. 🔴 `B31` 单独立项（本档不修，只登记）

现算：`golden = 0.804938866203 rad`、`candidate = 1.57946845154 rad`，**相差 0.7745 rad ≈ 44.4°**，
而 `tol = 1.5` 把这条差异**掩盖成 PASS**（残留仅占 tol 的 52%）。

两种可能，必须查证后才能动：
1. **候选算的是 `π/2 + 相位`**（`1.5795 ≈ π/2 = 1.5708`，差 0.0087）⇒ 语义错位；
2. **golden 与候选的参考面/符号约定不同**（相位族常见）。

⇒ 建议**单立 M2b-1「B31 语义裁决」**：用第三条独立路径（Drude 相移的解析导数 / Kramers-Kronig 互检）
判定谁是错的，再决定「改候选」还是「改 golden 语义」。**本档只把它保留在登记面**，不压 tol、不改数。

## 6. 风险与护栏

| 风险 | 处置 |
|---|---|
| `tol` 收到 `1e-16` 量级（`B74/B87/B88`）后**跨平台可能假红** | 这三条的 `resid` 本身是 `1e-17~1e-16`（位级一致）⇒ 100× 余量；**生产 py3.9 必须现算复现**（对拍门槛见 §7-3） |
| 贴线项（`B16/B32/E8` 的 `\|g\|/tol=12`、`E8` 的 `resid/tol=0.39`） | 上界已用 `\|g\|/12`（留 20% 缓冲）；`E8` 列入**观察项**，若漂移则登记为「不可收紧」而非放宽 |
| 收紧后旧回归数据变红（判据变严） | 全量 CI 照妖镜；任一红**只许修候选，不许把 tol 改回去** |
| 有人把 tol 放宽回去 | 新增 **`tol` 棘轮判据**：14 条 `tol` 只许 ≤ 本档定值 |

## 7. 验收点

1. **14 条** `resid ≤ tol/2` ∧ `|g|/tol ≥ 10` ∧ 注入 0 被拒（逐条机器判据，不靠人眼）。
2. **8 条**如实登记在「不可收紧」面，且**不得**出现在「偏松」清册里（否则等于既没修又没登记）。
3. **`B31` 保持原样**且必须在登记面（防有人「顺手调 tol 让它更好看」）。
4. `run_bl_anchor_guard_smoke` 新增 **tol 棘轮判据**（14 条定值只许更严）；`_RATCHET` 收紧到 `loose 8 / inject0 1`。
