# 光子计算 SoC 征程 · 架构定义 v1（S1 产物）

> 本文档是光子计算 SoC（PIC）征程的 **S1（架构定义 + 能力缺口台账细化）** 交付物。
> 上游：S0 可行性评估（`docs/LDA_光子计算SOC征程_可行性评估_2026-10-09.md`）。
> 下游：S2（补齐 G2/G3/G5）→ S3（端到端设计+行为验证）→ S4（规模爬升）→ S5（主权 GDS 出口+DRC/LVS）。
> 性质：**纯设计文档**，不改动引擎内核；所有接口契约均基于平台**现有真实模块**写实，缺口项明确标注。

**子系统清单（首期必须同片集成）**：
1. **光子计算核**（N×N MZI 网格，物理综合 + DRC/LVS 签核）
2. **电子外设**（per-MZI 驱动 DAC + TIA + 标定 FSM，行为/功能级）
3. **光 IO**（GratingCoupler 阵列 + 封装光源接口）
4. **封装光源接口**（G5 外置激光合规出口）
5. **标定环**（CalibrationStateMachine + 可辨识性验证 + 读回反估 Vπ）

## 3. 各子系统接口契约（基于真实模块）

### 3.1 光子计算核（已有能力，Clements 物理综合）
- **职责**：把目标酉矩阵 U（来自训练/权重）物理综合成"真算该酉"的 MZI 网格版图。
- **现有平台接口**：`lda-mzi-mesh-physical-synthesis` skill —— Clements 矩形分解 → 物理综合（伴随 MZI + 反转序 + 输出相移 D）→ 主权 DRC/LVS 签核；已证 **512×512 版级保真度 1.0、DRC/LVS 全绿、驱动清单落盘**。
- **输入**：`U_target (N×N 酉矩阵)`。
- **输出**：网格 netlist + GDS + DRC/LVS 报告 + per-MZI 驱动相位表。
- **首期缺口**：无（核本身已证）；规模爬升见 G6。

### 3.2 光电协同（已有能力，`photonic_electronic_cosim.py`）
- **职责**：把电子侧 DAC 码字 → 驱动电压 → 相移器相位 → 光网格传输 → PD → TIA，串成端到端推理链，并含读回闭环标定。
- **现有接口**：
  - `eo_phase_map(target_phi, dac_bits)`：相位 → DAC 码字映射
  - `eo_unitary_transfer(U, dac_bits)`：酉矩阵 → 光传输
  - `eo_layer_forward(W, x, activation, beta)`：单层前向（MVM + 非线性）
  - `eo_golden_classify / end_to_end_eo_inference(net, labels, ...)`：端到端推理（golden 精度比对）
  - `eo_calibration_loop(dac_bits, v_dd, ...)`：**读回闭环标定，反估真实 Vπ**
  - `eo_budget(n_mzi, dac_bits)`：行为级预算
  - `verify_photonic_compute_m3(seed)`：M3 验证入口（已挂 CI）
- **输入**：权重组 `W`、输入 `x`、DAC 位深。
- **输出**：光推理结果 + 与数字 golden 的精度差 + 标定后 Vπ。
- **首期缺口**：无（M3 已证）；需与 §3.1 物理综合产物对接（S3 集成）。

### 3.3 电子外设（行为级已有，功能级缺口 = G2）
- **职责**：per-MZI 驱动（DAC→相移器）、PD 后 TIA 跨阻放大、标定 FSM 控制。
- **现有接口（`eic_behavioral.py`，行为级）**：
  - `driver_step_closed_form / driver_step_rk4(t_s, tau_s, v_dd, ...)`：一阶 RC 驱动阶跃
  - `vpi_from_vpi_l / mzi_phase_from_voltage(v, vpi_l, ...)`：VπL→Vπ、电压→相位
  - `phase_resolution_rad(dac_bits, ...)`：DAC 量化最小步进
  - `tia_transimpedance_ohm / tia_bandwidth_hz`：单极点 TIA 频响
  - `eic_budget(n_mzi, tau_s, v_dd, dac_bits, ...)`：行为级预算
- **红线外（明确不在平台内）**：DAC/ADC/SerDes/DSP/BER 晶体管级模型（`eic_behavioral.py` 负面清单）。
- **首期缺口 G2（部分补齐）**：把"行为级"推进到"功能级"——理想 DAC 量化器、理想 ADC 流水线、标定 FSM 状态机（`CalibrationStateMachine` 驱动）。晶体管级仍红线外。

### 3.4 标定环（已有协议，`calibration_protocol.py`）
- **职责**：网格可辨识性验证 + 标定状态机 + 双重门护栏（无锚不得宣称 calibrated）。
- **现有接口**：
  - `mesh_params / mesh_jacobian / power_jacobian / complex_jacobian`：网格参数与雅可比
  - `power_rank_law(N) / complex_rank_law(N) / power_blind_dims(N)`：秩定律（标定可解性）
  - `identifiability_report(N, mode, ...)` / `rank_report`：可辨识性报告
  - `wdm_rank_sweep(N, lam_sets, ...)`：WDM 多波长秩扫描
  - `forward_consistency(N, unitary)`：前向一致性
  - `CalibrationStateMachine`：标定状态机（双重门：锚 + calibrated 声明）
  - 护栏：`guard_calibration_requires_anchor` / `guard_no_foundry_process_truth` / `guard_anchor_kind_eligible`（`ANCHOR_KINDS = pdk_process_corner, measured_calibration_data`）
- **首期缺口 G5（部分）**：冷态标定 + 可辨识性验证已可；**热串扰矩阵 + 工艺角敏感性**模型缺失（"未知⇒不授权闭合"），留 S3 补 `thermal_crosstalk_model` + `corner_sweep`。

### 3.5 光 IO（已有，`GratingCoupler` + `cpo_optical_io_metrics`）
- **职责**：光纤 ↔ 芯片光耦合 + 封装光源注入。
- **现有接口**：`lda_ir/photon.py::GratingCoupler(...)`（kind=GratingCoupler）；`cpo_engines.py::cpo_optical_io_metrics(geom)`（CPO 光 IO 指标）。
- **首期缺口**：无（光栅耦合器可用）；edge coupler 备选待补（非阻塞）。

### 3.6 封装光源接口（已有合规出口，G5 网关）
- **职责**：接入外部激光源，作为 SoC 光输入。
- **现有接口**：`four_layer_redline_gate.py::check_external_laser_bypassable()`（G5：外置激光可绕，不破红线）。
- **首期缺口 G1（延后）**：单片集成激光（DFB/DBR/异质）不在首期；封装级外部光源经 G5 合规接入。

## 4. SoC 集成数据流（端到端）

```
权重 U ──(Clements 物理综合)──► MZI 网格版图 + per-MZI 相位表
                                      │
输入 x ──► [电子外设] DAC码字 ──► 驱动RC ──► 相移器(电压→相位, mzi_phase_from_voltage)
                                      │
[封装光源] 激光 ──(G5)──► 光注入 ──► MZI 网格(光矩阵乘 y=Ux) ──► PD阵列
                                      │                         │
                                      │                         ▼
                                      │                    TIA跨阻放大 ──► 输出 y
                                      │                         │
                                      └──── 读回环 ──► eo_calibration_loop 反估 Vπ
                                                │
                                          [标定环] CalibrationStateMachine
                                          (可辨识性验证 + 双重门护栏)
```

- **集成正确性证据**：S3 阶段用 `end_to_end_eo_inference` 跑端到端推理，比对数字 golden，精度落差 = 0 即架构正确（L6 已证 0 落差参考设计）。
- **标定正确性证据**：`eo_calibration_loop` 反估 Vπ 后，网格实际传输与 `eo_unitary_transfer(U)` 误差 < 容差。

## 5. 首期 N 取值与规模爬升路径

| 阶段 | N | 说明 |
|---|---|---|

## 8. 诚实边界与红线纪律

1. **能效维度禁止宣称**：无电域锚、无 foundry 数据 ⇒ 不报 TOPS / pJ·op / fJ·bit / 能效。对标只用集成度/规模/架构正确性。
2. **标定红线**：任何 `claim=="calibrated"` 必须绑定合格物理锚（`pdk_process_corner` 或 `measured_calibration_data`）；无锚 ⇒ `CalibrationAnchorError`，不得宣称 calibrated（`guard_calibration_requires_anchor`）。
3. **封装光源合规**：首期光源走 G5 外置激光可绕，不破红线；单片激光（G1）不在首期。
4. **集成债不可隐藏**：模块级全绿 ≠ 集成无债；C1–C9 全 PASS 才算首期成功（IRONLAWS 反复强调）。
5. **判据必须真算**：所有性能/精度数字须由平台真实模块现算，禁止手写期望值冒充。
