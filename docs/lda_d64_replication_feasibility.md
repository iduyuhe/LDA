# D-64 后续：E3–E7「复制 E2 模式」可行性评估

> 日期：2026-09-01 · 版本线：v0.9.9 · 依据：本机实测数值实验（非推测）
> 背景：杜先生拍板「先打通 E2 样板再复制」。E2 样板已打通，本文件回答「能否照复制到其余六道」。

## 结论先行

**不能直接复制。七道实证锚里，能按 E2 模式接通独立求解器的路径远比想象中窄。**

|---|---|---|---|---|---|

| E5 | MMI 过量损耗 0.05 dB | ✅ 可算 | 2D FDTD + EIM | 🟡 中 | 几何已知（2.8×27 µm）；tol 0.1 dB 对 FDTD 数值误差偏紧；单次时长需评估 |

## 一、E6 的定位问题（最硬的一条）

**传播损耗是第一性原理算不出来的量。** 理想（无损、光滑侧壁）模式求解器给出的传播损耗恒为 **0 dB/cm**。真实的 0.087 dB/cm 来自：

- 材料吸收（理论上可算，但需材料的复折射率/吸收系数，且是工艺相关的唯象参数）；
- **侧壁粗糙度散射**（占主导）——需要 σ（粗糙度均方根）与 L_c（相关长度）两个**唯象参数**。

这两个参数**只能从测量中拟合出来**。于是任何「算得 0.087」的路径都是：拿同一批实测 → 拟合 σ/L_c → 回去「预测」0.087 → 循环自证。**这比现在的占位空判决更糟**——空判决至少诚实标注了「无验证价值」，而拟合回算会伪装成验证。

**建议：把 E6 从「实证验证锚」改判为「工艺规范事实 / 设计预算输入」**（spec compliance：设计须满足 ≤0.087 dB/cm 的损耗预算），不再宣称它参与验证判决。这是本次评估里**性价比最高、也最诚实**的一项改动——不花算力，只纠正一个分类错误。

## 二、矢量 FDTD 本征模求解器：实测不可用（推翻预期）

仓库已有真 3D 全 Yee 矢量本征模求解器 `lda_solver/fdtd3d_waveguide_vec.py`。它此前**只与标量 FDFD ORACLE 自校过，从未对实测验证过**——所以它是 E1/E3 的天然候选。实测结果：

```
SiN 1000×300（E2 器件，实测 n_g=1.892）
λ=1.53 → n_eff=1.55659
λ=1.55 → n_eff=1.62975   ← 非单调（应随 λ 增大而减小）
λ=1.57 → n_eff=1.36839   ← 非单调
⇒ n_g = 8.7552（荒谬值）

对照：标量 FDFD 同条件 n_g = 1.8818（|实测−标量| = 0.010）
```

- **单次 305 秒**（压缩网格后；原网格 > 7 分钟）——做不了 CI 常驻断言，也做不了 n_g 的三点差分（×3）。
- **n_eff(λ) 非单调** → 相位法（双监视点 DFT 相位差）精度不足，n_g 的差分被噪声主导。可改进方向：加长传播距离 dz、改用全矢量 FDFD 本征值法（scipy 已是硬依赖，`eigsh` 可用）而非 FDTD 相位法。

## 三、网格收敛缺口（D-65 / R16）：卡住 E1/E2/E3 的共同根因

同一器件**只改计算窗口**，结果就在跳：

```
SiN 1000×300            SOI 500×220           SiN 800×800（对照）
clad  n_eff    n_g      n_eff    n_g          n_eff    n_g
1.5   1.5637   1.8777   2.5384   3.7924       1.7642   2.0829
2.0   1.5699   1.8818   2.7385   3.8192       1.7884   2.0843
2.5   1.6197   1.9621   2.7843   3.8000       1.7884   2.0843
3.0   1.6129   1.9587   2.5852   3.7761       1.7642   2.0829
4.0   1.5699   1.8817   2.7385   3.8192       1.7884   2.0843
散射  ±0.028   ±0.042   ±0.123   ±0.022       ±0.012   ±0.0008
```

**根因是网格过粗，不是物理、也不是求解器逻辑**：0.3 µm 芯厚在 dl=λ/24=64.6 nm 下只有约 **4.6 格**，阶梯边界随窗口尺寸改变对齐位置 → 离散化误差跳变。对照组（厚 SiN 800×800，约 12 格分辨）**完全收敛**（n_g 散射 0.0015）——反证是分辨率问题。

排查中两次推翻自己的假设，如实记录：
1. ❌「σ 硬编码 2.3 致取错模态」——`oracle_mode.py` 的 shift-invert 目标确实写死为 n=2.3，与注释「σ 由 EIM 估计给出」不符，且对低对比度 SiN 而言 σ 落在整个导模谱**之外**。改成按 EIM 估计取值后**结果逐位不变**（4 个构型全同）→ σ 不是主因。（该 latent bug 仍修，代码与注释对齐。）
2. ❌「矢量 FDTD 能闭合标量近似的缺口」——见上节，实测不可用。

**根治方向：亚网格 ε 平均（sub-cell averaging）+ 更细网格**，并把「窗口散射」作为求解器的**收敛性自检指标**固化进 smoke。

## 四、建议的执行顺序

1. **E6 改判定位**（最省、最诚实，纯分类纠正，零算力）。
2. **R16 根治（亚网格 ε 平均）**——这是**一次性解锁 E1/E2/E3 三道题**的最高杠杆工程项，且完全自主（C 级不借外部依赖，scipy 已是硬依赖）。建议优先于单点复制。
3. **E5（MMI）接 2D FDTD**——几何已知，是 R16 之外最可能成功的一道；先做小尺寸试探，量大单次时长再决定是否入 CI。
4. **E3**——等 R16 修好 + eps 构造器支持层堆（薄 BOX + Si 衬底）后再做。
5. **E4 / E7（crossing）**——高动态范围 3D FDTD，暂缓；等 R2 外部 ORACLE 或算力到位。
6. **E1**——golden 源仍是 B 级（无定位符），即便候选达标也升不了 A；需另寻可溯源的 SOI 500×220 实测 n_eff/n_g。

## 五、给外部读者的一句话

> 当前 7 道实证锚中，**仅 E2 具备独立的候选求解路径**，且即便 E2 也只能判「量级一致」不宣称「精度验证」。其余 6 道为占位自证（candidate≡golden，|diff|≡0），其 PASS 不构成验证。这些事实已写进 `README` 诚实边界段、`/api/verification_ledger` 的 `judgment_paths` 字段，并由 CI 断言守护。
