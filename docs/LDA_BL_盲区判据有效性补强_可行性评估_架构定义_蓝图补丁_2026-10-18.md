## 0. 先纠正前提：B 的价值**不是**把覆盖率刷高

K4 的 L2 定义是「**CORE 门禁源码（去注释后）显式出现该锚号**」。这是**文本代理**，K4 自己也标注了「是**下限**，动态拼接锚号不计入」。

⇒ **在门禁里写一行锚号，就能让 L2 +1，而判据强度一点没变。** 这是纯粹的指标游戏，与项目红线（不虚报）冲突。

**B 的真命题**：盲区锚已经有 golden + 独立候选 + L1 判决，缺的是**判据的判别力**——
即「**这条锚的判据能不能区分对与错**」。现算证据（见 §1）显示：至少 **25 条判据形同虚设**、**1 条残差恒 0**、**4 条有相消嫌疑**。

⇒ 本征程的主产出是**判据有效性**，覆盖率上升只是**副产品**。若两者冲突，以有效性为准。

### 0.1 一个极端实例（说明"覆盖率"毫无意义）

**B81**「方势垒透射 T」：`golden = 4.656e-05`，`tol = 0.01`（绝对口径）。

⇒ **tol 是 golden 的 215 倍** ⇒ **候选取 0 也能 PASS**（`|0 − 4.656e-5| = 4.66e-5 < 0.01`）。
这条锚在账本里是 `strict_independent`，L1 判 PASS，**但它的判据根本没有判别力**。
刷 L2 覆盖率不会改变这一点。

### 1.5 🔴 关键方法学发现：**`verification_report.json` 不可用于残差审计**

| 口径 | 零残差条数 |
|---|---|
| 读报告（6 位小数） | **86** |
| **现算**（oracle 与 candidate 直跑） | **19**（= 18 条不可接 + `B82`） |

⇒ **67 条是报告舍入造成的假零**（如 `B87` 报告 0.000000，现算 `8.890e-17`）。
🔴 **通则：残差审计必须现算，读报告必误判。**（报告 6 位精度本就低于若干 tol=1e-9 的锚。）

### 1.6 `B82` 定性（唯一真零残差的可锚锚）

- 锚：「方势垒反射 R（异参数 v2）」，`candidate = 1 − 切片转移矩阵数值透射`
- 因子：`R ≈ 0.99995`（深隧穿，`T ≈ 4.66e-5`）⇒ **`R = 1 − T` 灾难性相消**：`1 − T` 把 `T` 的差异压到 `1e-16` 以下
- **note 里写着「R≈0.99995，|d|~0」—— 等于默认接受了一个数值上不可区分的锚**
- 🔴 **候选是独立的，坏的是观测量**：`R` 在深隧穿区是病态观测量。正解是**改观测到 `T`（或 `−ln R`）**，让离散误差浮出。

## 3. 征程路径（BL-M0 → M4）

> 🔴 **总纪律**：**本征程不新增锚**（账本 538 不变）。产出是**判据变强**，不是数字变大。
> 🔴 **若某条修不动，如实登记豁免并写明原因**，不硬改。

### 🥇 **BL-M0 · 逐锚有效性护栏 + 体检台账**（A 金级 · 平台）

- **生成器** `scripts/bl_audit.py`：逐锚现算 `resid / resid/tol / |golden|/tol / tol_mode / 相消标志`，产出受跟踪台账 `lda/reports/bl_anchor_audit.json`（**必须现算，不读 report**）。
- **常驻门禁** `run_bl_anchor_guard_smoke.py`，判据分节：
  - **A 台账三件套**：子进程重跑 ≡ 磁盘（逐字节）· 幂等 · LF only
  - **B 逐锚四断言**：`resid > 0`（或以**豁免登记**放行）· `resid/tol < 1` · `|golden|/tol ≥ 10`（或豁免）· `candidate != golden`
  - **C 豁免面锁死**：`BL_EXEMPT` **逐条带书面原因**，且**集合只许缩小**（棘轮：条数不得增加）；反向探针——从豁免表删一条 ⇒ 若该锚本应红则必红
  - **D 相消探针**：`|golden| ∈ (0.9,1.1) ∧ resid/tol < 1e-9` ⇒ 必红（除非显式登记"已复核为真精确量"）
  - **E 红线**：生成器零时钟/随机 · 本门禁 ∈ CORE
- 🔴 **性能**：397 条现算 **187 s** ⇒ 预算 **900 s**（4.8× 余量）；且须登记 `_SLOW_CORE` 排除（`run_ci_industrial_smoke` 递归跑 core 时跳过）。

### 🥈 **BL-M1 · 相消修复（`B82` + 3 条嫌疑复核）**（A 金级 · 单锚）

- `B82`：**把观测量从 `R` 改为 `T`**（或 `−ln R`，等价且良态）⇒ 残差从 `0.0` 变为可测。
  - 🔴 **这会改变该锚的 golden 语义 ⇒ 须用户拍板**（B7 结清先例：订正 golden 语义需授权）。
  - 改后须重算 tol（按实测偏差 2.2–2.5× 余量重定）并写进 note。
- `B68/B73/B83`：先判「真精确量」还是「相消」—— 若候选与 golden 是**同一闭式的两种写法** ⇒ 按判据 D 判**假独立**，须换候选或降级（🔴 会动账本）。

### 🥉 **BL-M2 · 25 条偏松批修**（A 金级 · 分 3 批）

- **批 1（7 条"放行 0"级 · 实跑确认）**：`B81 B391 B74 B87 B11 B88` + **`B31`** —— 注入候选 `0` 会被判 PASS，优先。
  - 手法：① **收紧 tol** 到 `|golden|/10` 量级（若实测余量允许）② 或**换观测量**（如 T → `ln T`，与 `B82` 同型）③ 或登记为「口径受限」豁免（**最下策**，须写清为何不能修）。
  - 🔴 收紧 tol 前必须**实测该锚候选的余量**：若 `resid` 已占新 tol 的 >50%，说明候选精度不够 ⇒ 不能硬收，改换观测。
- **批 2（7 条偏松但能拒 0）**：`B65 B372 B60 B106 E9 B59 B31`（`B31` 已在批 1 处理）
- **批 3（12 条 3–10）**：`B6 B5 B107 B32 B16 B80 B108 E8 B7 B383 B47`（`B7` 已有 93% 披露 ⇒ 只复核不动）

### **BL-M3 · 10 条余量不足复核**（B 平台级）

- 逐条现算余量轨迹，判断「候选精度不足」还是「tol 偏紧/偏松」；`B7` 已有披露 ⇒ 只复核。
- 产出「余量不足锚披露表」，写进 note（**披露而不一定改**）。

### **BL-M4 · L2 口径升级（覆盖率真实化）**（B 平台级）

- 机制：门禁**运行时登记**它实际检查过的锚号 → 受跟踪 `gate_anchor_manifest.json`。
- K4 的 L2 改为 `文本提及 ∪ manifest`，并**双向锁死**（manifest 与运行时断言集必须相等；删一条 ⇒ 红）。
- 目标：L2 从 **123 → 逼近 397+123**（上限 520，18 条不可接永不覆盖）。
- 🔴 **前提是先有 BL-M0**：没有逐锚真判据，manifest 只是另一种文字游戏。

## 7. 诚实边界

1. **本文不触发任何实现** —— 零锚、零门禁、零端点、零产品代码改动（账本仍 538 / CI core 仍 335 / 端点仍 156）。
2. **187 s 体检只覆盖 397 条 strict 盲区锚**；另有 123 条已被 L2 覆盖的锚**未做同等体检** ⇒ 它们可能也有偏松/相消问题，只是不在本征程首轮范围。
3. `B81` 类"候选取 0 能过"的判断已从**结构性推理升级为实跑注入探针**（25 条全测，7 条放行、`g±5tol` 25/25 被拒）—— 见 §1.3。
4. 25 条偏松是否可修，取决于**收紧后余量是否够** —— 现在**未逐条实测**，可能有一部分根本修不动（只能豁免）。
5. 18 条不可接锚**永不补判据**，L2 上限 **520** 而非 538。
6. 🔴 **本档自曝一次方法学错误**：初版把 `compare_fn` 的返回值当布尔用（`bool(err)`），
   导致误报"`g±5·tol` 也放行"。**实际 `compare_fn` 返回的是误差值**，判 PASS 必须 `err ≤ tol`。
   ⇒ 通则：**凡用 `compare_fn`，先确认它返回误差还是布尔**（本仓为**误差值**），否则反向探针全是假结论。
